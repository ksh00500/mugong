# 무인 외형 10종 · 2026-10-03

## 확정 규칙

사용자 요청: 삼재검법을 10성으로 복원하고, 모집 카드의 후보 번호를 없애며, 외형 10종을 무작위로 제시한다. 외형은 능력치·무공·특성·모집권 가격에 영향을 주지 않는 디자인 요소다.

- `src/domain/appearances.ts`: 백의 검객, 청록 유랑객, 은발 협객, 홍의 무인, 묵안 검객, 황의 수행자, 연화 무인, 노년 협객, 서역 유랑객, 도화 협객. 성별·연령·머리·피부·옷 색·장신구로 구분한다. 신발은 천/평평한 무림 복식이고 무기는 몸에 그리지 않는다.
- `recruitAppearances()`는 10개를 섞고 앞의 3개를 뽑아 한 번의 모집에서는 중복 외형이 없다. 다른 모집에서는 다시 등장할 수 있다. 성장 배율과 타고난 특성은 별도로 계산한다.
- `appearance`는 후보 → 무인 → 저장에 유지되는 선택적 0–9 식별자다. 기존 `portrait` 0–2를 새 번호로 해석하지 않는다. 이전 저장의 모습과 성급은 그대로 유지한다.
- 번호 텍스트 없이 초상화·특성·배율·선택 상태로 고른다. 버튼의 접근 가능한 이름에는 디자인 이름과 특성이 들어가고 Enter/Space로 선택한다.

## 에셋과 실행 연결

원본: `docs/source/hero-roster-v1/`. 배포 파일: `public/art/hero-roster-v1/`. 초상화 10개, 로비 전신 10개, 방향 시트 2개(8열×5명), 행동 시트 2개(6열×5명). `manifest.json`, `export-report.json`, `lobby-export-report.json`은 원본과 절단 영역을 기록한다.

`src/platform/character-art.ts`에서 모집·로비·HUD·명부·전투 파일을 선택한다. 전투 진입에서는 선택한 무인이 속한 5명 묶음의 시트 두 장만 추가로 로딩한다(`src/platform/game-loader.ts`).

`src/game/CombatScene.ts`는 같은 행 식별자를 유지한다. 실제 그림을 검토하여 앞/옆/뒤 시점을 배정했으며 대칭 방향은 좌우 반전을 사용한다. 보행은 외형별 8방향 원화에 연속 리그를 적용한다. 앞 대각 보행의 두 행동 원화를 번갈아 사용하던 규칙은 방향 반전 문제 때문에 폐기했다. 자세한 방향표와 검증은 `docs/hero-walk-directions-v1.md`를 따른다. 8방향×모든 상태를 각각 새로 그린 것은 아니다. 피격·사망 원화는 각 무인의 행동 시트에 있다. 자세 전환은 몸체 면적 기준으로 정규화하고 발 기준점을 유지한다. 무기는 `HeldWeapon`이 실제 연결 장비를 별도로 렌더링하며 몸과 동일한 전환 리그를 따른다.

재생성 시 초상화를 정체성 기준으로 참조해야 한다. 머리·얼굴·옷·장신구를 상태별로 임의 변경하지 않는다. 투명 배경, 균등 셀, 발끝/긴 머리 여백을 확보한다. 포장 스크립트는 원본을 보존하며 배경 매트·중복 인물·빈 셀을 검사한다. 근거 없는 자동 재도색/캐릭터 교체는 금지한다.

## 삼재 10성 복원

`src/domain/content.ts`의 원래 10개 단계에 맞춘다. 승급 비용은 현재 성급(5→6 비용 5, 9→10 비용 9). 7성 공격 간격 감소, 8성 삼재 완성과 궁극 개방, 9성 조준 방향 검기, 10성 적을 향하는 이기어검 및 공격 이동 제약 해제. 5성에 9/10성 효과를 압축하던 성장 v2 예외를 전투·설명·선택·저장 검사에서 제거했다. 다른 무공의 5성 상한은 유지한다.

## 검증과 한계

- 단위 검사: 삼재 5/8성에는 검기가 없고 9성 조준/10성 적 방향 발사, 이전 고성급 수련 선택 보존, 외형 3종 중복 없음과 10종 도달, 구형 초상화 호환.
- 브라우저: 10명×8방향×6상태 480개 몸체 스케일·식별자·메시 좌표·피격/사망 무기 숨김. 모집 1440×900/1366×768/1093×614에서 키보드 선택·후보 유지·전투 진입.
- 실제 시각 검토: 초상화/전신/행동/방향 시트와 모집/전투 화면. 자동 검사는 모든 자세의 손 위치나 표현의 미학을 인증하지 않는다. 방향 반전과 리그를 사용하는 부분은 후속 미세 조정이 가능하다.
- 캡처와 런타임 결과는 `docs/verification/hero-roster-v1/`, `docs/verification/recruitment-v1/`에 있다. 이 변경은 로컬 구현이며 Daytona에는 별도 배포가 필요하다.
