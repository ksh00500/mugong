# 소스 GitHub / 개인 서버 에셋 분리 — 2026-10-18

사용자가 GitHub LFS 예산 초과 이후 소스는 GitHub, 에셋은 개인 서버 별도 보관을 선택했다. 이전 전체 업로드는 LFS 서버의 budget 초과 응답으로 실패했으며 원격 브랜치가 생성되지 않았다. 인증 만료나 이번 계정의 이미지 생성 한도 문제로 해석하지 않는다.

## 변경

- 실패한 LFS 스냅샷 `a60ee477150cc91b7272e2592a502d42ba52af7b`는 로컬 `codex/self-hosting-setup`에 보존했다. 원격 main에서 직접 이어지는 `codex/source-assets-split`을 마련해 실패한 LFS 커밋을 새 원격 이력에 포함하지 않는다.
- 원본 파일을 삭제하지 않고 Git 추적에서 미디어2,414경로를 제외했다. Git LFS 필터를 제거했고 소스·제작 프롬프트·메타데이터·라이선스·SVG·검증 요약은 유지한다.
- 전체 에셋의 경로·바이트 수·SHA256을 `asset-manifest.json`으로 관리한다. 실행용863개, 제작/참고1,551개를 독립 압축본으로 묶었다. 실제 크기·SHA는 `docs/asset-bundles/*.json`에 기록했다.
- 에셋이 없거나 변조되면 빌드 전 검사에서 실패한다. 기본 CI는 에셋 목록·타입·소스 단위 검사·JS/CSS 컴파일이다. 실제 미디어를 사용하는 Docker/브라우저 검사는 별도이며 기본 소스 CI 성공으로 합산하지 않는다.
- README·CONTRIBUTING·서버 설치·업데이트·롤백 문서를 이 구조에 맞췄다. 개인 서버 다운로드 주소와 비밀정보는 Git에 넣지 않는다.

## 이번 검증

실제 미디어가 없는 별도 폴더에 Git 인덱스의 소스만 꺼내 `npm ci`·타입·목록 검사·소스 단위62파일1,295검사(26.06초)·Vite186모듈 JS/CSS 컴파일(11.77초)을 통과했다. 미디어가 없으므로 Vite는 폰트/일부 CSS 이미지의 런타임 경로 경고를 출력하며 이것을 완성 배포 빌드로 사용하지 않는다.

같은 별도 폴더에서 에셋이 없을 때863개 누락으로 검사가 실패함을 확인했다. 실행용 압축본을 복원한 뒤 실제 파일 SHA/바이트 검사가 통과했다. 복원 폴더의 폰트1개를 한 바이트 변조하면 SHA256 오류로 실패했고 즉시 원래 바이트로 복구했다. 제작용 압축본도 다른 폴더에 풀어1,551개 모두 원본 SHA/바이트가 일치함을 확인했다.

소스 저장소 감사에서 LFS·미디어 오추적·자격 정보 패턴 발견0개를 확인했다. 패턴 검사는 완전한 비밀 탐지 보장이 아니다. 원본 미디어·실제 사용자 저장은 변경하지 않았다.

초기 검증용 Windows Git archive 해제는 한글 문서 경로 처리에서 실패해 Git checkout-index로 검증 폴더만 다시 구성했다. 첫 소스 테스트는 샌드박스 임시 파일 rename 권한 문제로 실행되지 않았고 일반 실행 환경의 같은 검사에서 통과했다. 제작용 복원 검사의 첫 명령은 잘못된 작업 경로로 모듈을 못 찾았고 올바른 복원 폴더에서 재실행해 통과했다. 이 실패들을 게임 로직/에셋 무결성 실패나 성공 검사로 합산하지 않는다.

공개 개인 서버 업로드·SSH·도메인/TLS 연결은 아직 실행하지 않았다. 압축본은 `.asset-bundles/`에 보존하며 다음 서버 이전 단계에서 전달한다. 기존10지역 원화·17보스75행동 적용 범위 및 미완료 미술은 그대로다.
