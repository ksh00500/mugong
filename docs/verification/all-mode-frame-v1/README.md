# 모드 전체 프레임 검증 — 2026-10-24

검사 흐름은 실제 원화를 쓰는 Phaser 장면 → 모드별 확정 상태/표시 분리 → 실제 HTTP·WebSocket 입력/화면 → 저장/재접속/정산이다. [수정 범위](../../all-mode-frame-v1.md).

## 측정의 의미

원래 온라인 강호의60Hz 그림 중 위치가 바뀐 비율은 약16%, 비무·레이드는 약32%였다.144Hz에서는 약6.5%/13.1%였다. 갱신 CPU P95는 각 장면에서 약0.2~1ms로 낮았지만 받은 좌표를 반복해서 그렸다. 이는 프레임 중복 문제를 확인한 것이며 사용자의 실물GPU에서10~20FPS를 재현한 뜻은 아니다.

최종 대조는 같은 원화/렌더러/서버 확정 상태와 로컬 이동 예측을 쓰고 새 네트워크 표시 사본만 통과시키는 baseline을 사용한다. 과거 전체 체크아웃은 아니다. 초기 수정 전4개 장면 기록도 `.local-preview/all-frame-before`에 보존하며 그때 비무/레이드 계측의 connected=false를 최종 FPS 대조와 혼동하지 않는다.

60/120/144/240Hz 제어 일정에서 워밍업 후 이동 표시가 이어지는지·단일 프레임 이동량·서버 상태 불변을 확인한다. 실제 브라우저 약3초 표본에는 OS/소프트웨어GPU 변동이 있어 큰 FPS 향상이나 서비스 수준으로 판정하지 않는다. 별도 소프트웨어WebGL 강제 시험은 실제 하드웨어 GPU 성능 시험이 아니다.

## 검증 범위

- 단위:10/20Hz 상태와60/120/144/240Hz 표시, 지터 보정·입력 예측·문맥 손실 중 중립 입력·원점/죽음/회피/층/라운드/정지 경계·단절 상한·투사체 수명/발사 시점/그림 동일성·월드 경계·실제18종 원화 프레임 조회. 기존 전투/저장/서버 회귀도 실행한다.
- 실제 장면: 로컬/온라인 강호·비무·4인 표준 레이드와 비무/레이드 WebGL 경로. 그림 해상도·맥동/무기/HP를 유지하며 alpha/MSAA=false, 문맥 손실 콜백·입력 마스킹을 검사한다. 제어된 신호이며 실제 소켓 시험과 구분한다.
- 실제 소켓: 신규 온라인 모집/육성·이동/새로고침/저장, 두 계정 친선 실제 HP·항복, 순위전 취소/재접속·Elo 중복 정산 없음, 자연 완주 개인 무인/정상 보스HP1600의3해상도 레이드 이동/돌진/피해/HUD를 확인한다. 실제 사용자 계정/IndexedDB/SQLite에 시험 상태를 주입하지 않는다.
- 실제 소스 장면을 계측해 온라인 무인, 비무 상대, 레이드 보스의 신호 수신 위치 변화와 화면 위치 변화를 따로 센다. 게임 전역 디버그API는 추가하지 않고 시험 브라우저에서만 메서드를 감싼다.

최종 횟수/수치는 summary.json, 장면별 결과는 baseline/final JSON, 적용 대조는 local-build.json에 기록한다. 실제 HTTP/WS 계측 원시 프레임과 캡처는 `.local-preview/all-online-source/frames`, `all-online-final`, `all-frame-final`에 보존한다.

## 도중 실패와 구분

초기 고주사율 검사에서 패킷 도착 때2px 안팎의 점프가 남아 작은 보정 이력을 추가했다. 첫 이동까지 과도하게 끌던 보정은 이미 이동 중인 이력에만 적용하도록 고쳤다. 한 투사체 제거 fixture는 실제 JSON 수신과 다르게 같은 원본을 직접 수정해 새 사본으로 고쳤다. 관측 보조의 중복 import와 Phaser가 캐시한 update를 뒤늦게 감싼 오류는 시험 코드에서 바로잡았고 대기 중인 해당 실행은 중단했다.

초기 실제 접속 시험에서 재접속 중 활성 전환 버튼이 입력 마스킹보다 먼저 나타나던 경합을 수정했다. 레이드 준비 클릭 미확정/대기는 별도 확인으로 기록하고 서버 준비 확인·전송 진단과 문구 공간 유지를 추가했다. 소스 시험 중 파일 편집으로 발생한 HMR 새로고침도 성공으로 합산하지 않는다. 초기 단위/브라우저 실패와 최종 통과를 합산하지 않는다.

온라인 강호 관측에서 발견한 매 프레임 화살 경고는 폭탄 아틀라스의 불필요한 조회였으며 제거하고 전용 원화 조회/경고 검사를 추가했다. 실제 렌더 오류와 별개인 시험 경계 실패를 구분한다.

최종 단위 검사는107파일1633개 통과했다. 타입·에셋(1069파일, 누락/LFS 포인터0)·클라이언트 빌드도 통과했다. 동일 조건 대조3개와 수정 후 실제 장면6개가 통과했고, 별도 컴파일 출력의 실제 HTTP/WS6개도 모두 통과했다. 제어 일정의 이동 표시 변화 비율은 수정 후60/120/144/240Hz에서 모두100%였으며 실제 GPU FPS 향상률을 뜻하지 않는다.

최종 단위 검사 첫 시도는 sandbox 임시 캐시 rename의 EPERM으로107개 파일이 로드되지 않았다. 해당 결과를 통과로 합산하지 않았고 권한 오류가 없는 재실행의1633개 결과만 위에 기록했다.

최종1093×614 비무/레이드 전투 HUD와 별도 소프트웨어WebGL4인 레이드 캡처를 직접 확인했다. 캡처 확인과 자동 조작/시계 검증은 별도이며 장기 플레이나 실물GPU 검증을 대신하지 않는다.

로컬5205 정적 클라이언트만 새 출력으로 적용했다.21개 HTML/JS/CSS의 SHA가 빌드와 일치하고 서버 health·익명 인증401·1440×900/1366×768/1093×614 접속 행동을 확인했다. 기존8787 서버·스키마3·실제 사용자 저장을 그대로 두며 public junction 출력은 로컬 전용이다. 공개/Docker/집Linux/Cloudflare 배포·실물GPU/장기 부하는 이번 완료 범위가 아니다.
