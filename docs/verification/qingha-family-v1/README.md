# 청하현 로컬 적용 검증

2026-10-05. 일반 적3종·보스4종의 420개 방향별 기본 자세를 적용했다. 자동 검사와 직접 시각 검토는 아래처럼 구분한다. 세부 수치는 `summary.json`, 원화 선택·출처는 `../../source/qingha-family-v1/selected-art-audit.json`에 기록한다.

## 자동 검사

- 전체 단위56파일·1,265개 통과(`unit.json`). 마지막 후면 베기 교정 후 청하현 단위4개 재검사(`final-focused-unit.json`)와 빌드(`build.log`)를 통과했다.
- 원본420개 누락·잘림·이웃 연결·의도하지 않은 그림 공유0건. 최종 선택60개 PNG는 생성 도구의 원본 파일과 바이트가 같고 프롬프트·출처가 보관되어 있다. 420개 그림의 RGBA 해시도 모두 다르다. 생성 후보와 탈락 원본은 별도 보존한다.
- 원본 RGBA 1:1 패킹 후35개 lossless WebP를 재디코딩해420프레임과 최소32px 투명 여백을 검사했다.
- Canvas/WebGL × 일반/줄인 움직임4개 검사 통과. 각각7종×8방향×7상태×5진행도=1,960개, 합계7,840개 상태를 검사한다. 공통배율0.225·방향/반전·메시 비활성화·고정HP바·보스 피격 시 공격 자세 유지가 대상이다. 살아 있는 자세의 실제 HP바 하단과 불투명 그림 상단 간 최솟값은약11.22px였다.
- 보스20행동의24접촉×8방향=192회씩, 합계768회에 접촉 원화를 선택한다. 이는 모든 보스 행동을 실제 시뮬레이션으로 끝까지 실행한 검사는 아니다.
- 일반 적3종×8방향=24회 실제 tick 검사에서 도 베기·창 찌르기의 피해와 쇠뇌1발 발사를 접촉 원화와 비교했다(`actual-release.json`).
- 로컬 빌드1440×900·1366×768·1093×614의3개 검사 통과.35개 WebP 응답·전투 이동·검토 화면7종 선택·보행/공격·정지/프레임 이동·가로 넘침·페이지 오류를 검사하고 `production`에 캡처와 JSON을 저장했다.

브라우저 총8개 통과. localhost 소켓 제한 때문에 브라우저 검사는 샌드박스 밖의 독립 Playwright 컨텍스트에서 실행했다. 실제 사용자 저장은 변경하지 않았다. 외부 서버 배포는 수행하지 않았다.

## 직접 시각 검토

7개 인물의60자세 접촉표(`contact`)에서 머리·몸통 크기, 무기 손과 손잡이 연결, 관절, 발 기준선을 비교했다. 발 좌표 추정이 무기 끝과 다른9개 자세는 접촉표에서 별도로 확인했다. 창·칼·사슬 끝이 발보다 내려가는 그림을 인물 높이의 기준으로 삼아 축소하지 않는다.

실제 Canvas·WebGL의 보행·준비·접촉·회수 비교 캡처를 직접 열어 HP바와 무기 여백을 확인했다. 철무의8방향 사슬 접촉·후속은 `production/qingha-pose-2.png`와 `qingha-pose-3.png`, 좁은 전투 화면은 `production/combat-1093.png`에서 확인했다. 도적 후면 접촉이 여전히 준비처럼 보이는 문제를 발견해 새 원화로 교정하고 검사를 재실행했다.

이 검토는 해부학이나 모든 신체 치수를 수치 인증하지 않는다. 일부 보스 특수 행동은 기본 공격 주기를 공유하고 사망은 한 자세의 페이드다. 원본 크기의 미세한 차이가 전혀 없다는 의미도 아니다.
