# 2026-10-06 기관병 프레임 침범 검토

후속 작업: 사용자 승인으로 [세 프레임 재제작 및 로컬 적용](../../zhuge-boundary-v2.md)을 완료했다. 이 문서와 미리보기는 수정 전 문제를 기록한 것이다.

사용자가 지정한 `exec-3a85754b-f239-49cc-a6b4-912068ba06ae.png`는 해시가 `docs/source/zhuge-family-v1/attempts/engineer-front-right-original.png`와 일치하는 초기 원화다. 현재 선택 원화는 `engineer-front-right.png`이다. 원본 파일의 문제가 현재 적용본에 없는 것으로 단정하지 않고 적용 WebP도 확인했다.

## 확인한 문제

- 지정 원본은 1448×1086, 논리 칸은 362×362이다. 2행 2열 사망 그림은 왼쪽 35px·오른쪽 25px, 3행 2열 후속 그림은 오른쪽 38px 경계를 넘는다. 이것만으로 다른 그림과 붙었다고 단정할 수는 없다. 지정 원본의 12개 연결 그림은 각각 분리 가능하다.
- 현재 선택 원화의 기관병 앞 대각선 **10번째·11번째 자세(3행 2열·3열)** 는 연결된 그림 분리가 모호하다. 현재 게임용 WebP를 불투명 배경에 합성하여 직접 보니 10번째 자세의 기관함이 수직으로 잘리고, 11번째 자세에 잘린 기관함 조각이 포함된다. 이미 포장된 프레임에 잘린 내용이 들어간 것이므로 표시 배율을 변경해서 고칠 수 없다.
- 같은 제갈 지역의 실제 선택 원화 420자세를 같은 추출기로 검사하니 **진괄 측면 사망 자세**도 모호한 분리로 검출됐다. 원화에서 창끝이 옆 그림의 발과 닿는다. 적용된 사망 프레임의 직접 시각 검토에서도 왼쪽 발·오른쪽 머리와 창이 칸 경계에서 잘린 것을 확인했다. [해당 프레임 미리보기](jingwal-death-on-background.png).
- 제갈 적용 프레임 420개의 불투명 픽셀은 전달 칸의 32px 여백 조건을 통과한다. 따라서 **여백 통과는 그림 분리·완전성 통과가 아니다.** 현재 exporter의 `f.id < 0` 차단은 모호한 원화를 다시 생성하도록 요구하지만 과거에 내보낸 WebP를 자동으로 복구하지 않는다.

## 수정 기준

기관병 앞 대각선의 후속·회수 자세를 독립된 넓은 칸에서 다시 제작하고, 같은 몸·머리 크기와 하나의 기관함을 유지해야 한다. 원화 단계에서 그림 사이 투명 간격과 전체 기관함·손·머리카락의 완전성을 확인한 다음 공통 크기 칸에 최소 32px 여백으로 포장한다. 생성 이미지가 붙어 있으면 칸 경계로 강제 잘라 쓰지 않는다. 다른 방향도 같은 분리 검사를 적용하고 실제 추출 결과를 육안 검토해야 한다.

이번 요청은 검토이므로 적용 에셋·프레임 manifest·공개 배포는 변경하지 않았다. 진단 자료와 미리보기만 추가했다.

- [수치 검사](audit.json): 지정 원본의 경계 넘침, 실제 선택 원화의 모호한 분리, 적용 프레임 여백을 구분한다.
- [현재 적용 WebP의 배경 합성 미리보기](runtime-on-background.png): 투명 WebP 미리보기에서 숨겨진 RGB가 보이는 현상과 구분하기 위해 배경에 합성한 검토용 PNG다. 원본 에셋을 수정하지 않았다.
