## 확인한 동작

- 실제 체력/접근성 값 즉시 감소, 흰 손실 잔량, 유지·감쇠·안정, 회복, 25% 위험 상태. 1440×900·1366×768·1093×614.
- React HUD와 Phaser의 일반 적/보스가 같은 HealthTrail을 사용. WebGL에서도 실제 흰 구간을 그림. 기존 5px 막대와 원화 간격 보존.
- 카메라 충격 상한·감쇠·완전 복귀, 끄기, 움직임 감소, native shake 중복 없음. 테스트의 HUD 사각형과 시뮬레이션 위치/HP/경과 시간은 전후 일치, 조준 오차 0. [카메라 관측](camera.json).
- 설정 저장/재로드·키보드 선택·Escape 초점 복귀·5언어, 고대비/큰 글씨. 가방 공통 Meter와 성장 Enter 선택·저장 결과.
- 실제 전투의 검격/이펙트·Q/E·Space·반격·방어 입력, 가방 열기/닫기. 컴파일 게임은 개발 모듈을 가져오지 않고 검사.
- 컴파일 HTML/정적 JS·CSS와 HTTP SHA 일치. 실제 사용자 브라우저 저장은 변경하지 않고 독립 Playwright 컨텍스트에만 상태를 주입.

## 초기 실패와 수정

- 카메라 소멸 때 `-0`이 반환된 단위 실패를 진폭 0의 명시적인 0 반환으로 고쳤다. 전체 단위와 소스 검사가 이후 통과했다.
- 개발 서버 변경 중 모듈 관측이 끊긴 실행과, 실제 Phaser 렌더 전 관찰자 준비가 끝난 것으로 보던 회귀 코드를 구분한다. 관찰자가 실제 장면을 잡을 때까지 기다리고 서버를 새로 시작한 뒤 전투 5개가 통과했다.
- 기존 HUD 검사의 15개 독립 컨텍스트 합계 100초 제한, 그림 로딩 5초 제한이 부족했다. 합계 300초/그림 준비 45초로 바꾸되 기능 검증은 유지했다. 마지막 2개 실행은 4.6분에 통과했다.
- 오래된 모집 검사에 실제 모집권 사용·후보 선택·첫 무공 선택을 추가했다. UI에서 막힌 배경 가방을 강제로 누르지 않는다.
- 가방/성장 신규 fixture가 최대 Lv.5 무공에 Lv.6 업그레이드와 부족한 수련을 주입해 거부된 것은 게임 오류가 아니었다. Lv.2→3·수련2의 유효 fixture로 고쳐 Enter 선택이 통과했다.
- WebGL 생성자 이름의 Vite 접미사 `WebGLRenderer2`를 허용하도록 검사만 교정했다. 실제 WebGL 렌더·흰 잔량·동작 감소·장면 종료 검증은 유지했다.

## 적용과 한계

컴파일 로컬 게임은 `http://127.0.0.1:5205/`, 출력은 `dist-ui-feedback-v1`이다. 기존 5203 원화 검토 서버는 보존했다. 공개 서버 전송·main 병합·공개 배포는 하지 않았다. 로비 원본 화질·전 화면 미술 재제작·장시간 체감/실기기 성능·온라인 기능은 후속이다. [기법과 범위](../../ui-feedback-v1.md).
