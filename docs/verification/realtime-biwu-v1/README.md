## 두 브라우저의 실제 흐름

최종 Playwright는 서로 다른 독립 브라우저 컨텍스트 두 개와 **별도 테스트 SQLite DB**를 사용한다. 실제 사용자 IndexedDB/쿠키/온라인 DB를 사용하지 않는다.

1. 1440×900·1366×768·1093×614: 계정 생성→서버 표준 무인 선택→친선 방 코드 참가→양쪽 그림 준비/대전 준비→카운트다운→실제 서버 이동/피해→HP 막대의 실제 픽셀 폭 감소→항복/승패/저장 영수증. 친선 Elo변화0, 독립 테스트용 오프라인 저장의 전후 객체 일치를 확인했다. HUD/조작부/하단 행동 경계도 화면 안이다.
2. 순위전: 실제 두 계정 대기·취소/재진입→매칭→새로고침으로 같은 경기 ID 재접속→두 플레이어 무공 전환→항복→+12/-12→다시 새로고침해 동일 영수증·경기1회·1012점→실제 순위/기록 조회.
3. 방향 그림 요청을 실패시켜 준비 버튼을 막고, 재시도 후 같은 방으로 이어 시작했다.
4. 계정 생성 후 로그아웃→잘못된 비밀번호 거절→정상 로그인/같은 계정 ID 복원→로그아웃 뒤 API계정null.

단위/서버 검사는 변조된 피해·이전 순번/라운드 입력·200ms 입력 만료·같은 틱 KO·흡혈 부활 방지·독 피해 반격/게이지 중복 방지·카운트다운·제한 시간·5라운드 종료·원장 재정산·파일 재열기/서버 중단·같은 DB 중복 서버 소유 거절을 확인한다. 서버 통합은 재접속 유예를 테스트 전용150ms로 줄여 한쪽 종료와 양쪽 종료 무효를 확인하고, 첫 DB 정산 실패를 주입해 재시도 후1회 반영을 검사한다. 실제 기본 유예는30초다.

## 빌드·Docker·로컬 적용

두 Docker 이미지(web/pvp)는 의존성 설치·실행 에셋·타입·프런트/서버 빌드까지 성공했다. **이 이미지 빌드는 마지막 DB 배타 소유 가드 추가 전이며**, 그 최종 서버는 호스트 타입/빌드·전체 단위·실제 HTTP/WS 브라우저6개로 검증했다. 일반 Compose의pvp/web과 Cloudflare Compose의pvp/web/tunnel 구성 검사는 통과했다. 자동 CI의 선택적 runtime 작업도 두 컨테이너와 독립 DB의 두 사람 검사를 실행하도록 수정했으나 원격 CI 성공을 주장하지 않는다.

Docker 데몬이 `up`/`ps`에 응답하지 않아 컨테이너 실제 실행과 Nginx→WS→SQLite의 Docker 경로 검증은 **미완료**다. 이번 CLI만 중지했으며 Docker Desktop/데몬·다른 컨테이너는 재시작/삭제하지 않았다. `mugong-pvp-verify` 테스트 프로젝트에 일부 생성 상태가 남았는지는 데몬 응답 후 확인한다. 공개 집 Linux서버·Cloudflare/HTTPS 주소 적용도 아직이다.

로컬 파일 복사 빌드가 디스크 공간 부족으로 실패했다. 이번 실패 출력만 경로/사용 프로세스/재분석 지점을 검사하고 **880파일 / 968,129,408바이트** 모두 public 원본 SHA와 일치하는 복사본임을 확인한 후 제거했다. 과거 빌드·제작 원본·기존 미디어는 삭제하지 않았다. 최종 `dist-realtime-biwu-v1`은 로컬 전용 public 디렉터리 junction을 사용하며 원본은 유지한다. **이 로컬 링크 출력은 서버 배포용 압축본이 아니다.** Docker 빌드는 독립 미디어를 복사한다. 최종 JS/CSS는 최종 브라우저 검사본과 같다.

로컬5205는 `dist-realtime-biwu-v1`, 실제 로컬 비무 서버는127.0.0.1:8787와 별도`.local-online` DB다. 테스트 서버8788의 DB와 분리한다. 이번 검사 과정의 초기 소스 타입/DB 테스트 정리 실패, 로컬 smoke의 잘못된 링크 이름 선택은 수정 후 통과했다. 잘못된 selector로 실패한 smoke를 게임 기능 실패/성공으로 합산하지 않는다.
