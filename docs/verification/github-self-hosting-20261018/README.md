# GitHub 현재본 정리·개인 서버 준비 — 2026-10-18

후속 결정: 아래 LFS 전체 업로드는 예산 초과로 실패했다. 사용자가 소스와 에셋을 분리하기로 결정했으므로 최신 저장소 구조와 결과는 [소스/개인 서버 에셋 분리](../source-assets-split-20261018/README.md)를 따른다. 아래는 분리 전 Docker/Nginx 검사와 준비 기록이다.

기존 `ksh00500/mugong` main의 이력을 유지하고 `codex/self-hosting-setup` 브랜치에 현재 React19·Phaser4·Vite7 소스, 런타임 에셋, 제작 원본·프롬프트, 기능/검증 문서를 정리했다. main 병합·개인 서버 공개 배포·추가 원화 제작은 이번 범위가 아니다.

## 저장소 구성

- README·CONTRIBUTING·경로별 안내·현재 상태·Linux/Docker 설치/업데이트/복귀 문서와 PR 양식을 마련했다.
- 바이너리 2,414경로는 Git LFS 포인터로 등록했다. 제작 자료까지 약3.0GiB이며 서버에서는 `public/**`만 받도록 안내한다. `node_modules`, 임시 빌드, 실제 저장, 자격 정보, 옵시디언 사본, 검증 PNG/영상·대량 프레임 JSON은 제외한다. 파일을 삭제하지 않고 로컬에 보존한다.
- 제작 입력 텍스트1,977개는 줄바꿈 자동 변환을 끄고 Git 등록 내용과 원본 바이트가 모두 일치함을 확인했다. 원본 프롬프트의 공백을 일괄 정리하지 않았다.
- 자격 정보 패턴/과대 일반 Git 파일 감사에서 발견0개. 패턴 감사는 완전한 비밀 탐지 보장이 아니다. 기존 GitHub 프로토타입의 더 이상 사용하지 않는 파일은 브랜치에서 현재 소스 구조로 교체하며 기존 커밋은 보존한다.
- CI는 SHA로 고정한 Actions를 사용한다. PR·main 변경에서 런타임 LFS 수신·타입·단위·Docker 빌드·실제 Nginx 브라우저/HTTP 검사를 수행하며 배포/레지스트리 푸시는 하지 않는다.

## 이번 실제 검증과 수정

1. 단위 검사 초기에는 방향별37,800기하 표본(189,000검증)과 전체 번역 검사에서5초 시간 초과가 발생했다. 실행 병렬 수를4로 제한한 재시도에서도 기하 검사는 시간 초과했다. 검증 조건·표본을 유지하면서 두 대량 검사만15초로 설정했다. 최종62파일1,295검사 통과(27.43초).
2. 첫 깨끗한 Linux Docker 빌드가 Node 타입 누락으로 실패했다. 로컬의 간접 설치에 기대던 `@types/node`를22계열 개발 의존성과 잠금 파일에 명시했다.
3. 수정한 Docker 빌드에서891런타임 파일·195리터럴 참조·누락/포인터0개, TypeScript, Vite186모듈 빌드를 통과했다. 최종 재빌드9.37초. main번들3,141.74kB의 기존 크기 경고는 남는다.
4. 처음 실제 Nginx 브라우저 검사는 로비3해상도·전투/가방4개 통과, 자산 캐시 검사1개 실패였다. 일반 확장자 정규식이 `/assets/` 경로보다 우선해 캐시 헤더가 빠졌다. Nginx 경로를 `^~ /assets/`로 교정하고 최종 이미지를 다시 빌드했다.

최종 Nginx 재실행은5개 모두 통과(18.4초)했다. 1440×900·1366×768·1093×614 로비의 모집/닫기/초점 복원, 컴파일 전투의 자산 로드·이동·공격·가방 열기/닫기, healthz·해시 JS 장기 캐시·폰트 재검증·없는 art404·다음 단계 UI 경로를 확인했다. 컨테이너는 nginx 사용자·읽기 전용 루트·capability 제거 상태에서 실행했고 healthcheck가 healthy였다.

검사는 독립 브라우저 컨텍스트를 사용했다. 실제 사용자 저장을 변경하지 않았다. 전투1093캡처를 직접 검토했으며 전체 미술 품질 완료를 뜻하지 않는다. `final/`에는 수정 후 재실행 결과를 보관한다. 공개 Linux 서버의 SSH·TLS·도메인 연결은 실행하지 않았다. GitHub 업로드와 원격 CI 결과는 이 문서의 후속 기록 및 PR을 따른다.
