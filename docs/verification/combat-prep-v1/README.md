## 초기 실패와 수정

- 초기 전체 실행에서 구형70% 피해/HP·발 중심 경계와 달라진 기대값이 실패했다. 몸통에 닿는 창/돌진 경계는 적중, 몸 전체가 벗어난 경우는 빗나감으로 사례를 나눴다. 증가한 적 수로 RNG 소비가 바뀌어 무공 제안이 달라진 검사는 합법적인 최대 레벨 보유 목록을 명시했다. 최종 전체/소스 검사는 모두1,340개 통과했다.
- 첫 정비 브라우저 fixture는 레벨만 올리고 성장 계수가 없어 최대HP120인데150HP를 주입했다. 실제 성장 계수/시작 레벨을 명시해 최대280인 유효 fixture로 수정했다. 완전 품절에 supplies=[]를 넣은 잘못된 fixture도 저장 검증이 정상 거부했다. 기존3품목·stock0으로 수정하고 새로고침/품절 유지 검사를 통과했다. 저장 검증을 느슨하게 만들지 않았다.
- 새 증거 폴더를 단독으로 쓰는 카메라 검사에서 출력 디렉터리 누락이 있었다. beforeAll로 생성한 뒤 카메라 검사를 재통과했다.
- 독립 Playwright 두 실행이 같은 기본 추적 파일 폴더를 사용해 컴파일1093 종료 시 ENOENT가 발생했다. 실행별 output 폴더를 분리한 뒤 컴파일4개를 재통과했다.
- 돌진/방어 회귀는 한 검사 안에서5회 완전한 장면을 로드해45초 제한에 걸렸다. 검증 내용은 유지하고 제한120초로 수정한 뒤42.4초에 통과했다.
- 컴파일 촬영 fixture의 누적 경험치를 Lv.16 기준으로 맞추고 이름을 줄여 최종4개를 재실행했다. 실제 UI의 정상 경험치를 잘못된 fixture의 음수 값으로 판단하지 않는다.

## 로컬 적용과 한계

컴파일 실행은 http://127.0.0.1:5205/ (`dist-combat-prep-v1`), 검증용5207도 같은 출력이다.5205가 비어 있음을 확인한 뒤 같은 origin에 연결해 기존 브라우저 저장을 유지한다. 이전 빌드/원화 디렉터리는 보존했다. 최종5205 HTTP SHA와1093 정비·저장·보스·입력은 독립 컨텍스트에서 다시 확인했다. 개인 서버 전송·공개 배포·main 병합은 하지 않았다. 난이도는 첫 조정이며 장시간 자연 전투/원거리 밸런스·실기기/GPU·로딩/큰 번들·로비 원본 화질·온라인 기능은 후속이다.
