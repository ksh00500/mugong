# 높음 UI 항목 검증

2026-10-20. [구현](../../ui-high-v1.md). 최종 빌드 `dist-ui-high-v1`을 로컬5205에 적용하고 HTTP index SHA256을 대조했다. 원본 에셋/실제 사용자 저장은 변경하지 않았다. 공개 배포·main 병합은 하지 않았다.

## 확인된 자동 검사

- 전체 단위78파일·1,381개, 소스 전용78파일·1,381개 통과. 소스 전용 모드는 manifest 검사이며 실제 미디어 검사와 구분한다. 새4개 검사는 활성 상태의 우선순위/만료/원본 불변, 중첩 수 단위, 실제40보스 키트의2가지 안내, 표시 정밀도와 계산값 보존을 확인한다.
- 타입 검사 통과. 런타임 에셋1,058개·정적 참조792개·누락0·LFS포인터0. 최종 Vite 빌드206모듈 성공. 큰 mount 청크 경고는 남는다.
- 개발 UI의 구매·장비 이동/착용/사용·회전·저장 복원, 실제 조건 시계, 다섯 언어·설정/음소거 저장, 로딩 단계/입력 차단·실제 네트워크 실패와 재시도를 검사한다. 장면/그래픽 실패는 콜백 주입이며 실물 GPU 장애 재현과 구분한다.
- 저장 복구는 독립 저장에 실제 마지막 사망 결과를 커밋하고 원본을 손상시킨 뒤 원본 내보내기·검증 사본 복구·원본 보존/사망 유지 여부를 확인한다. 실패 주입 전에 기존 자동 저장을 멈추고 flush해 테스트 준비의 경합을 제거한다.
- 별도 컴파일5228에서 실제 구매 후 잔액·품절과 가방 진입을 확인했다. 소스 모듈을 주입하지 않는다.

최종 개발 UI10검사를 한 실행에서 통과했다. 기존 회귀21시나리오는 이번 실행의19통과와 최초 리소스 대기/준비 상태를 교정한 뒤 재통과한2개(1440성장 설명·WebGL2회 저장 재개)를 합친 최신 결과다. 세 해상도 정비·4개 정비 웨이브/5언어·품절/가득찬 체력, 성장 Shift/Esc/키보드3해상도, 흰 잔량/카메라/실제 WebGL·설정6개, 모집/HUD/성장3해상도·큰HUD/고대비/동작 감소·5언어 모집과 Canvas/WebGL재개를 포함한다.

최종 컴파일5228의4검사와 실제 적용5205의 별도4검사도 통과했다. 각4개는 상인 비교→실제 구매/잔액/품절·가방, Canvas/WebGL 각2회 저장 종료/재개,1093모집→첫 성장 설명/선택이다. 소스 모듈을 주입하지 않고 독립 테스트 저장과 실제 UI를 사용한다. 현재 UI10+회귀21+컴파일4+5205별도4의39시나리오이며 초기 실패/중간 중복 실행·과거 감사 캡처를 통과 수에 더하지 않는다.

PNG/추적/raw 단위 결과는 로컬 증거이며 선택한 요약 JSON과 이 문서는 Git에 보관한다. 유지보수한 모든 역사적 E2E 파일을 전부 실행한 결과는 아니다. 현재 작은 화면/언어/실패 주입 검증을 자연 플레이 전체나 실물 GPU 품질 보장으로 확대하지 않는다.

## 직접 시각 검토

1440 전투 상태,1093 정비/상인/가방/상태/저장 오류,1093 영어 설정과 최종1440확장 상태 목록 캡처를 직접 열어 확인했다. 열린 상태 상세가 기존 플레이어 패널의 `overflow:hidden`에 잘리는 것을 발견해 전용 CSS에서 해제했다. 추가 목록은 명시적인 버튼·aria-expanded·키보드/Esc를 사용하며 상위 잘림도 자동 검사한다. 최종 캡처에서 남은 시간·냉기 중첩까지 실제로 보이는 것을 확인했다. 모든 언어/모든 자연 플레이 상황의 수동 승인이나 접근성 인증을 주장하지 않는다.

## 준비 중 교정

- 브라우저 검사 두 실행이 같은 추적 디렉터리를 써서 파일이 사라진 초기 실행은 검증 성공으로 계산하지 않는다. 실행별 출력 디렉터리를 분리했다.
- 이미지 실패 주입이 실제 사용 중인 지역 경로를 가리키도록 고쳤다. 로비 fixture의 `run`은 `undefined`가 아닌 저장 형식의 `null`을 사용한다.
- 엔진 모듈 다운로드 실패가 같은 문서에서 계속 실패하는 실제 문제를 찾아 재진입 방식으로 고쳤다.
- 기존5초 장면 준비 제한의 검사는 최초 리소스 준비와 UI 행동을 혼동하지 않게 로딩을 먼저 기다린다. 과거 UI 이름을 사용하던 검사 선택자는 새 목적지/설정 문구와 상인 흐름에 맞춰 유지보수한다. 선택자 갱신만 한 모든 과거 테스트를 실행한 것으로 주장하지 않는다.
- 저장 복구 후 사망 UI를 곧바로5초 이내 기대하던 검사는 장면 준비 완료를 먼저 기다리게 했다. 마지막 사망 결과/원본 보존 검사와 렌더러 준비 시간을 분리한다. 동시에 별도 브라우저를 실행하던 중 처음 그림 준비에 실패한 WebGL검사는 단독 재실행에서 두 번 재개를 통과했다.

## 재실행

독립 개발 서버5225에서 `tests/e2e/ui-high.spec.ts`를 Playwright로 실행한다. 별도 config의 `testDir`는 `tests/e2e`, `testMatch`는 `ui-high.spec.ts`, workers는1, locale은ko-KR로 둔다. 컴파일 모드는 `MUGONG_HIGH_COMPILED=1`, 주소는 `MUGONG_HIGH_URL`, 증거 경로는 `MUGONG_HIGH_PROOF`로 지정한다. 기존 모집/재개 회귀는 `ui-priority.spec.ts`의 `MUGONG_PRIORITY_COMPILED/URL/PROOF`를 사용한다. 소스/컴파일/로컬 실행의 결과 디렉터리를 분리한다.
