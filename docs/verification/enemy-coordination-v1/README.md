## 직접 검토와 교정

1093 Canvas와1440 WebGL의 최종 협공 캡처를 직접 열어 근접/창병/궁수의 배치와 기존 그림·HP바가 표시되는지 확인했다. 첫 화면 검토에서는 여러 창병과 추가 근접병이 같은 좁은 지점으로 모여 대기 층 간격을 넓혔다. 추가 층 간격 회귀를 포함해 전체 단위와 전후 관측을 다시 실행했다. 캡처 한 장으로 모든 시간의 겹침이 사라졌다고 주장하지 않는다.

처음 비교 관측은 원본도3개 제한을 지킬 것이라고 잘못 가정해 실패했다. 원본이 먼 공격자를 세지 않아7개까지 겹치는 실제 값을 관측하도록 바꾸고, 현재 규칙의3개/0.22초는 별도 행동 검사와 보고 스크립트에서 강제했다. 최종 제품의 제한을 검사에 맞춰 느슨하게 하지 않았다.

컴파일 초기 검사에서는 고정650ms 대기가 느린 소프트웨어 렌더링에서 시뮬레이션0.23초만 진행한 것을 확인했다. 실제 저장된 이동 거리와 저장 완료를 기다리도록 검사를 교정했다. 초기 소스 관측의 HMR 모듈 중복으로 장면을 찾지 못한 문제는 실제 로드된 리소스 URL로 같은 모듈을 구독해 해결했다. 개발 서버는 생성된 dist/dist-* HTML을 감시하지 않도록 설정했다. 중간 실패·중단·이전 배치의 통과 수는 최종 결과에 합산하지 않는다.

Windows npm 래퍼가 출력 옵션을 루트 인자로 잘못 넘긴 빌드는 최종 결과에 사용하지 않았다. 명시적인 Vite `build --outDir dist-enemy-coordination-v1`로220모듈 빌드를 다시 만들었다. 최종 타입 검사는 검사용 콜백의 타입 누락도 수정한 뒤 통과했다.
