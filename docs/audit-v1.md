# 전체 구현 검토 · 2026-09-29

현재 React·Phaser 브라우저 게임의 코드와 실제 동작을 검토했다. 범위는 Lv.0 생성 → 20웨이브 전투·성장·전리품·정비 → 귀환·명부·가방·창고·수명과 저장·로딩·언어·화면 설정이다. 원래 구상 전체의 완성이나 모든 문제가 없다는 판정은 아니다.

## 발견하고 수정한 결함

| 중요도 | 문제와 근거 | 수정 |
| --- | --- | --- |
| P1 | 저장의 바깥 배열만 검사했다. 명부 무인의 `arts: null` 저장을 불러오면 화면이 멈추고 저장 오류 안내가 나오지 않았다. | [저장 형식 검증](../src/platform/save-validation.ts)을 추가해 무인·무공·물품·적·발사체·성장 선택·진행을 검사한다. 오류 안내와 재시도 후에도 원본 IndexedDB 값이 동일한지 확인했다. 없는 저장과 `false`·`0` 등 손상 값도 구분한다. 초기화나 덮어쓰기 복구는 하지 않는다. |
| P1 | [세션 잠금](../src/platform/session.ts)이 모든 `pagehide`에서 저장 권한을 반납했다. 캐시에 보존된 문서는 기존 메모리로 돌아올 수 있어 단일 쓰기 잠금이 끊긴다. | `persisted: true`에서는 잠금을 유지한다. 생명주기 이벤트를 재현한 독립 브라우저에서 두 번째 탭 차단과 첫 탭 종료 후 재시도를 검사했다. 실제 BFCache 진입 가능성 시험과 구별한다. |
| P2 | 대화상자 뒤의 화면을 입력 대상에서 제외하지 않았다. 배경 버튼에 초점을 보낼 수 있었다. | [공통 대화상자 계층](../src/ui/dialog-layer.ts)으로 최상위 창 외 영역을 `inert`로 격리하고 중첩 창을 닫을 때 아래 창과 초점을 복원한다. 설정·성장·설명·폐기 확인·저장 오류에 적용한다. |
| P2 | 가방의 전역 R키 처리로 폐기 확인·성장 창 뒤 물품의 회전 미리보기가 바뀌었다. | [가방 입력](../src/ui/Inventory.tsx)을 활성 가방 안에서만 처리한다. 폐기 확인 중 R → Esc, 비급 사용 → 성장 창 → R → 선택을 조작해 회전 상태 보존과 초점 복귀를 검사했다. |
| P2 | 만체력에서 금창약 사용 버튼이 켜졌다. 도메인은 사용을 거부해 약은 소모되지 않았지만 실패하는 행동을 제공했다. | 최대 체력에서는 버튼을 비활성화하고 사유를 제공한다. 전투 중 사용 금지는 유지한다. 의원의 120 체력 조건은 현재 규칙과 일치하며 결함이 아니었다. |
| P2 | 천마의 ‘돌진 찌르기’와 삼재의 ‘검로 확장’·정밀함 설명이 실제 판정과 달랐다. 천마는 연속 공격의 찌르기, 삼재 해당 단계는 공격력 증가다. | [성장 설명](../src/domain/content.ts)을 실제 동작에 맞추고 네 번역을 추가했다. 이동·사거리·피해·밸런스는 변경하지 않았다. |

첨부 파일 폴더를 `.gitignore`에 추가해 일괄 Git 추가에 사용자 첨부가 섞이지 않게 했다. 첨부·기존 에셋·사용자 저장을 삭제하지 않았다.

## 확인한 현재 동작

- 생성은 Lv.0·무공 없음에서 시작하고 세가 물품을 반입하지 않는다. 강호 중 일시 종료는 같은 여정의 이어하기다.
- 네 무공 제한, 레벨당 투자, 최대 단계 후보 제외, 오입력 방지와 성장 중 전투 정지를 유지한다.
- 기본 공격·방어·궁극·적 공격·사망·최종 보스·귀환·수명과 저장 후 복원을 검사한다. 합법적인 이동·전투·회복·성장 선택을 이용한 20웨이브 완주도 도메인 검사에 있다.
- 전투 중 이동·착용·연결 변경·소모품 사용을 거부한다. 정비에서는 수납·회전·착용·사용·폐기 확인·다음 웨이브를 조작한다.
- 무장 4×7·일반 10×8을 유지한다. 클릭·방향키·Enter·드래그, 경계·충돌, 중첩 분리, 가방↔창고, 장비 교체, 페이지 이동과 초점 복귀를 검사한다.
- 저장 실패 후 입력 차단·재시도·중복 출전 차단, 지원 브라우저 단일 탭 쓰기, 수명 만료 자산 회수·중복 회수 방지를 검사한다.
- 그림·모듈 지연과 실패, 재시도·기본 화면·새로고침에서 중복 생성과 로딩 중 전투 진행을 막는다.
- 필수 1440×900·1366×768·1093×614 배치·패딩·핵심 행동과 다섯 언어의 로비·설정·생성·안내·전투 가방을 확인한다. 모든 캐릭터 상태와 모든 언어의 조합을 검증한 것은 아니다.
- `npm audit`에서 알려진 취약점 0건을 확인했다. 이름 출력은 React·Phaser 텍스트이며 이름을 HTML로 삽입하지 않는다. 보안 인증이나 아직 없는 서버의 보안 검증은 아니다.

## 남은 작업과 우선순위

아래는 해결되지 않은 재현 오류와 구별하는 **구현 범위·운영·검증의 부족분**이다.

| 순서 | 현재 한계와 근거 | 다음 작업 |
| --- | --- | --- |
| 1 | 20웨이브 뒤 핵심 성장 루프인 레이드·비무·시장·계정은 미구현이다. 귀환 이후에는 명부·가방·창고와 비급 수련만 가능하다. | 기획 규칙대로 후반 루프와 서버 상태를 구현한다. 현재 프런트엔드 저장을 온라인의 권위 있는 상태로 사용하지 않는다. |
| 2 | [storage.ts](../src/platform/storage.ts)는 IndexedDB의 `current` 단일 저장이다. 이전 정상본·내보내기·가져오기·클라우드 복원이 없다. 손상 저장은 보존하지만 자동 복구는 없다. | 저장 세대 보관·원본 내보내기와 다음 스키마의 마이그레이션·복구를 먼저 마련한다. 삭제를 복구 기본값으로 삼지 않는다. |
| 3 | [game.ts](../src/domain/game.ts)의 수명은 클라이언트 `Date.now()`로 판정한다. Web Locks가 없으면 단일 쓰기 보호도 없다. | 지원 환경을 검증·명시하고 온라인에서는 서버 시각·원자적 저장·권한 판정으로 이전한다. 이번 형식 검증은 부정행위 방지가 아니다. |
| 4 | CSS 11개, 비어 있지 않은 줄 기준 9,234줄이 순서대로 덮어쓴다. 다음 변경 때 다른 해상도에서 재발할 유지보수 위험이 있다. | 공통 토큰과 화면별 스타일로 단계적으로 통합하고 캡처·조작 회귀를 유지한다. |
| 5 | [mount.ts](../src/game/mount.ts)는 Canvas·WebGL 분기를 사용한다. 자동 실행은 Chromium 소프트웨어 렌더링 중심이다. 실기기 GPU·발열·장시간 메모리·OS 실시간 움직임 설정 변경은 충분히 검증하지 않았다. | 저사양 노트북과 하드웨어 WebGL, 30분 이상 플레이, 숨김·복귀, GPU 컨텍스트 손실과 무공 경로별 난이도를 시험한다. |
| 6 | 자동 좌표·버튼 검사와 개발자 시각 검토는 첫 사용자의 이해도를 보장하지 않는다. 작은 화면 가방은 정밀한 클릭이 필요하다. | 출전 → 첫 성장 → 전리품 수납 → 폐기 취소 → 귀환 창고의 성공률·실수·시간을 관찰한다. 키보드 전용·스크린리더·긴 이름도 확인한다. |
| 7 | Daytona는 Nginx 정적 미리보기다. 자동 부팅 서비스·게임 서버·운영 모니터링이 없다. | 공식 서비스 배포에서 프로세스 복구·가용성·로그·구버전 모듈 요청·롤백을 검증한다. 미리보기를 상시 서비스로 평가하지 않는다. |

다음 진행 순서는 **저장 백업·복구 → CSS 구조 정리 → 새 사용자·실기기 검증 → 귀환 뒤 루프와 서버**로 제안한다.

## 검증 기록

프로덕션 빌드 성공, 단위 48개·로컬 브라우저 44개 통과. Daytona 공개 검사는 기존 8개와 새 결함 검증 6개, 총 14개가 통과했다. 공개 전용 1개는 로컬에서 제외하고 별도 배포 설정으로 실행한다. 최종 공개 배포 상태와 검사 결과는 [검증 JSON](verification/audit-v1/result.json)에 기록한다. [패키지 검사 원본](verification/audit-v1/npm-audit.json)과 [저장 오류 처리 캡처](verification/audit-v1/save-error.png)를 함께 보관한다.

초기 저장·배경 격리·폐기 확인 회전 세 검사가 실패하고 수정 후 통과했다. 추가로 페이지 보존 이벤트 잠금·만체력 약 사용 실패를 재현해 수정했다. 중간에 두 Playwright 실행이 같은 추적 출력 폴더에 접근해 파일 충돌 두 건이 발생했다. 최종 검사를 단일 실행으로 다시 수행해 44개가 통과했으며 출력 충돌을 게임 결함으로 계산하지 않았다.

수동 검토: 실제 로컬·공개 브라우저의 로비·설정·배경 격리·초점 복귀와 독립 브라우저의 저장 오류 캡처를 확인했다. 실제 브라우저에서 그림 준비 오류를 관찰했고 ‘다시 시도’로 로비에 진입했다. 그 장애 원인을 특정하거나 상시 재현되는 로딩 결함으로 판정하지 않았다. 실제 사용자 브라우저의 설정·무인·저장을 테스트 상태로 바꾸지 않았다.

결과는 현재 구현의 주요 흐름과 명시한 경계 조건에 한정한다. 서비스 수준·접근성 인증·모든 기기의 무결성을 주장하지 않는다.
