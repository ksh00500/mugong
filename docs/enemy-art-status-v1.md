사용자가 비교한 `dist/art/animation-rebuild-v2`의 네 번째 칸 축소는 런타임 배율만의 문제가 아니다. **전달 시트 내보내기 과정의 칸별 확대·축소**가 확인됐다. 이번에는 현황을 정리했으며 원화 재생성이나 에셋 교체는 하지 않았다.

## 실제 사용 경로

`dist/art`는 빌드 결과이고 `public/art`의 파일이 복사된다. 새 생성 PNG는 `docs/source/animation-rebuild-v2`에 있다. 사용자가 본 WebP는 이 PNG를 분리·재배치·리사이즈한 전달 파일이다.

| 에셋                                 | 현재 사용                                                        |
| ------------------------------------ | ---------------------------------------------------------------- |
| `enemy-motion-v1`                    | 이전 동작 원화 보존본. 현재 지역 동작 manifest에서 선택하지 않음 |
| `animation-rebuild-v2/region-*.webp` | 0·2·3·4·5·6·7·8지역의 대표 방향 동작                             |
| `animation-rebuild-v2/roles.webp`    | 빙탄·함정·기관·취권 보스 전용 역할 동작                          |
| `animation-rebuild-v2/identity.webp` | 낙검객·돌 투척 승려·지팡이 노승의 교체 동작                      |
| `hostile-consistency-v3`             | 앞·옆·뒤 방향 그림 및 후면 동작. 1·9지역의 대표 방향 동작도 교체 |

즉, 게임은 한 폴더의 시트만 사용하는 구조가 아니다. 소림의 돌 투척 승려·노승 등은 지역 시트의 행 대신 identity 시트가 선택될 수 있다. 실제 선택은 `src/platform/region-art.ts`, `assets.ts`, `CombatScene.ts`를 기준으로 확인해야 한다.

## 확인한 크기 변화

`scripts/export-animation-rebuild.mjs`의 각 칸 배율은 `min(220 / 전체 너비, 220 / 전체 높이)`이다. 무기·팔·옷자락까지 포함하므로, 창을 뻗는 공격 그림은 몸도 작게 내보내진다. 모든 칸을 가운데 정렬하고 이 배율을 적용한다. `hero` 기본 시트만 이 내보내기 리사이즈에서 제외된다.

생성 PNG의 연결 영역 경계와 내보내기 기록으로 계산한 예:

| 파일·행(1부터)          | 첫 칸 배율 | 네 번째 칸 배율 | 첫 칸 대비 공격의 배율 |
| ----------------------- | ---------: | --------------: | ---------------------: |
| region-4, 봉 승려 2행   |      1.140 |           0.812 |                 약 71% |
| region-4, 권갑 승려 1행 |      1.528 |           1.294 |                 약 85% |
| roles, 노인 4행         |      0.936 |           0.728 |                 약 78% |

region-3의 2행 창 캐릭터도 전체 너비가 231·229·270·264픽셀로 커서 네 첫 칸에 각각 0.952·0.961·0.815·0.833배가 적용됐다. 이것은 다른 인물과의 실제 머리 크기가 모두 같다는 측정이 아니라, 긴 무기가 축소 기준을 지배한다는 증거다. [관련 셀 전체 계산](verification/combat-startup-v1/export-scale-audit.json).

이전 `scripts/export-enemy-motion.mjs`는 칸별 리사이즈 없이 WebP 형식만 변환했다. 이전 소림·설원 시트를 직접 열어 동작 사이의 몸 크기가 상대적으로 일정한 것을 확인했다. 다만 이전 시트에는 인물·복장 불일치와 별도 보정 이력이 있어 전체를 무조건 되돌리는 근거는 아니다.

## 런타임 보정의 상태와 한계

현재 소림은 두피 실측값, 나머지는 기존 해부학 추정값으로 프레임 배율을 보정한다. 최근 수정으로 방향마다 목표 크기가 바뀌거나 걷기와 공격이 다른 단위를 쓰는 문제는 제거했다. HP바도 같은 인물의 살아 있는 그림 범위와 실제 메시 위쪽을 반영한다.

하지만 이 검사는 설정된 보정값과 렌더 결과의 일치를 검사한다. 모든 원화의 실제 머리·어깨·몸통 비율이 같다는 증거는 아니다. 다른 인물의 일부 보정값은 전체 그림 높이에 검토한 비율을 곱한 추정치다. 내보내기에서 생긴 축소를 항상 정확하게 상쇄한다고 볼 수 없고, 원화 내부 비율 차이나 확대 후 손실된 세부를 고칠 수도 없다.

이전 설명에서 배율 기준 혼용을 원인으로 확정한 것은 범위가 부족했다. 현재 구분해야 할 문제는 생성 원화의 비율 차이, 칸별 내보내기 배율, 여러 시트 간 런타임 보정, HP바 배치다. WebGL 메시 조각 현상은 별도다.

## 권장 제작 규칙

1. 인물마다 한 기준 원화와 기준 머리 크기·몸통·사지 비율·카메라 각도·복장 팔레트를 정한다. 보스와 일반 적의 의도된 차이는 유지한다.
2. 해당 인물의 모든 방향·걷기·준비·타격·피격·사망을 같은 기준과 같은 카메라 거리로 제작한다. 자세 때문에 몸의 전체 높이가 낮아지는 것과 인물 자체가 축소되는 것을 구분한다.
3. 내보내기는 같은 인물에 공통 배율을 적용하고 좌표·발 기준을 보존한다. 무기나 펼친 팔이 넘치면 투명 공간을 넓힌다. 칸에 맞추려고 몸을 줄이지 않는다.
4. 기준 머리·어깨·몸통과 프레임 경계·접지점·무기 끝을 기록한다. 머리·몸통 크기 차이의 검수 허용치를 먼저 정하고 넘는 그림은 재제작한다. 전체 불투명 영역 높이만 비교하지 않는다.
5. 생성 PNG → 전달 WebP → 실제 렌더의 세 단계 비교판을 같은 배율에서 검토한다. 정상적인 구부림·회전·원근 단축을 자동 수치 검사만으로 실패 판정하지 않는다.

대량 재생성 전에 봉 승려나 설원 창병 한 인물로 이 규칙을 검증하는 것이 좋다. 기존 PNG의 몸 크기가 정상인 셀은 내보내기만 바로잡을 수 있다. 생성 PNG 자체의 비율이 다른 셀을 골라 재생성해야 한다. 새 프레임 경계에 맞춘 보정 데이터·발 기준·실제 공격/HP바 검증도 함께 갱신해야 한다.
