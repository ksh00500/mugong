## 원화·패킹 규칙

- 원본은 3열×4행. 대기 / 왼발 / 통과 / 오른발 / 작은 피격 / 쓰러짐 / 초기 준비 / 최대 준비 / 접촉·발사 / 후속 / 회수 / 재준비 순서다.
- 각 캐릭터의 정면·앞 대각선·측면·뒤 대각선·후면을 직접 생성한다. 좌측은 검토한 우측 원화를 반전해 8방향을 지원한다.
- 서 있는 몸 약300–330px, 머리 약90–100px를 생성 목표로 사용한다. 목표치는 생성기의 보장값이 아니므로 결과와 실제 렌더를 수동 검토한다. 숙인 자세는 관절로 낮아지고 머리·몸통 자체를 축소하지 않는다.
- 한 캐릭터의 옷·색·몸·머리·무기 길이는 시점과 동작 사이에 유지한다. 한손 도와 사슬은 공격 손이 바뀌지 않고 양손 창은 동일한 직선 자루를 두 손으로 쥔다. 정면/후면 발사는 투시로 단축된 무기 방향을 그린다.
- 칼은 최대 준비에서 높이 들고 접촉 때 아래·전방으로 내려 벤다. 후속 뒤에 회수한다. 올려치기를 대표 베기로 사용하지 않는다.
- 원본 외곽 잘림·이웃 그림 연결을 검사한다. 문제 프레임은 생성 도구로 고치며 필요한 경우 교정용 시트의 이웃 셀을 비운다. 비운 이웃 그림은 게임에 선택하지 않는다. `poseSources`에 교정한 자세만 연결한다.
- 원본 RGBA 픽셀은 1:1로 복사한다. 캐릭터별 고정 칸에 사방 최소32px 투명 여백을 패킹한다. 런타임에는 공통 배율0.225를 쓰며 자세별 몸 맞춤 확대·축소, Mesh 변형, 별도 무기 자동 추적을 하지 않는다.
- 지면은 저장한 발 좌표이며 창끝·칼끝이 아니다. HP바는 살아있는 모든 자세의 최고점에16화면px를 더한 인물별 고정 높이다.

## 검증과 범위

원본 검사·RGBA 패킹 보존·인코딩된 여백 검사를 자동으로 수행한다. 카메라·무기 소유 손·관절·신체 크기는 원화와 브라우저 캡처를 눈으로 검토한다. 자동 검사가 해부학을 인증한다는 의미는 아니다.

Canvas/WebGL × 일반/줄인 움직임에서 7종·8방향·7상태·5진행도를 검사한다. 일반 적 3종은 실제 타격/발사 경계에서 접촉 그림을 확인한다. 보스20행동·24접촉의 시계와 기존 경직/CC 면역을 유지한다. 보스의 증원·방어·회전 등에는 대표 공격 자세를 공유하는 부분이 남아 있으며 모든 패턴에 별도 전용 원화를 생성한 것은 아니다.

로컬 전용으로 빌드하고1440×900,1366×768,1093×614에서 검사한다. 실제 사용자 저장은 변경하지 않고 Playwright 독립 컨텍스트의 테스트 저장을 사용한다.
