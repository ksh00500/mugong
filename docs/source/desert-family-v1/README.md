# 서역사막 기본 원화 적용

상태: **7종 기본 원화 420프레임 생성·게임 연결·로컬 검증 완료. 보스 패턴별 전용 자세는 기본 자세를 공유하는 부분이 남아 있다.**

최종 선택 원본은 41장이다. 원본 기본 40장에 아르칸 뒤 대각선의 후반 4자세를 담은 넓은 추가 시트 1장을 사용했다. 35개 게임 WebP는 RGBA 1:1, 고정 배율0.225, 최소32픽셀 여백으로 패킹했다. 잘림·연결 요소 공유·중복은 원본 검사에서 발견되지 않았다. 자세별 손·관절·크기는 생성 결과와 게임 캡처로 수동 검토했다.

검증: 전체 유닛55파일/1,261개 통과, 빌드 성공, Canvas/WebGL와 일반/줄인 움직임 4개 및 실제 타격·발사1개 통과, 로컬 배포 1440×900 /1366×768 /1093×614 브라우저3개 통과. 캡처와 실제 공격 기록은 `docs/verification/desert-family-v1`에 있다. 적용 범위와 남은 패턴별 시각 구분은 `docs/desert-family-v1.md`에서 확인한다.

2026-10-05 이전 계정의 첫 `image_gen.imagegen` 요청은 HTTP 429 `usage_limit_reached`로 실패했으나 사용자가 계정 변경을 알려준 뒤 재시도에 성공했다. 실제 원본은 프로젝트에 복사하고 `provenance.json`에 기록한다. 생성 진행 수는 `generation-status.json`에서 확인한다. 실제 사용자 저장은 변경하지 않는다.

## 생성 규칙

`generation-jobs.json`은 패킹용 기본 **35개 논리 시트·420프레임** 계획이다. `generation-requests.json`은 실제 생성할 **40개 원본 시트**와 프롬프트·참조 파일 목록이다. 이 숫자는 준비된 작업 수이며 완성된 이미지 수가 아니다.

- 7종 × 정면·앞 대각선·측면·뒤 대각선·뒷면 = 35시트. 좌측 방향은 검토된 우측 원화 반전으로 지원하되, 각도와 이동 방향을 8방향 모두 확인한다.
- 인간형은 시점당 3열×4행 12자세. 기마병은 넓은 말 공간을 확보하기 위해 시점당 2열×3행 이동/공격을 각각 생성한다. 기마병 원본 10장과 인간형 원본 30장이다.
- 기본 자세 순서: 대기 / 왼발 / 통과 / 오른발 / 작은 피격 / 쓰러짐 / 초기 준비 / 최대 준비 / 접촉·발사 / 후속 / 회수 / 재준비.
- 인간형 서 있는 몸은 약300–330 원본 픽셀, 머리는 약90–100픽셀을 목표로 한다. 기수 머리는 같은 범위를 유지하며 말까지의 높이는 약420–460픽셀로 더 큰 작업 공간을 사용한다. 이는 생성 목표이며 실제 원화 측정과 검토가 필요하다.
- 머리·몸통·팔다리·무기 길이를 프레임마다 유지한다. 숙인 자세의 높이가 낮아지는 것은 관절 동작이며 머리까지 함께 작아지는 것은 불합격이다. 무기까지 포함한 사각형 높이로 배율을 자동 맞추지 않는다.
- 원화 경계와 이웃 그림에서 최소32픽셀 투명 여백. 무기·발·머리·말 꼬리가 잘리면 다시 생성한다. 여백 부족을 신체 축소로 해결하지 않는다.
- 생성된 픽셀은 비율을 유지하며 1:1 패킹한다. 프레임별 확대·축소, Mesh 변형, 자동 팔/무기 추적을 사용하지 않는다. 캐릭터별 고정 출력 배율을 원화 검토 뒤 결정한다.
- 무기 소유 손을 고정한다. 칼의 손잡이/단검/환이 손목과 연결되어야 한다. 말의 고삐는 왼손과 연결되고 기수 골반은 안장에 붙어 있어야 한다.
- 환 투척 접촉과 후속 자세는 오른손이 빈 상태이고 왼손에는 예비 환을 유지한다. 재장전 뒤 다시 쥔다. 날아가는 환이나 궤적을 원화에 중복해서 그리지 않는다.
- 밝기·색·옷·머리 크기를 모든 시점에서 유지한다. 뒷면에서 얼굴을 정면으로 돌리지 않는다. 배경·빛·그림자·VFX 없이 실제 알파 투명으로 생성한다.

## 당초 검토 절차

1. 원본 생성 결과를 프로젝트에 복사하고 `provenance.json`에 실제 도구 결과와 프롬프트를 기록한다. 요청 성공 없이 완료 상태를 쓰지 않는다.
2. 40개 원본을 눈으로 검토한다. 특히 최대 준비·접촉·후속의 머리/몸 크기, 각 손의 무기, 관절·척추·기수/말의 연결을 확인한다. 잘림·잘못된 카메라·무기 이동은 재생성한다.
3. 새 `desert` 제품군을 분석/패킹/검토 도구에 등록하고 원본 RGBA 1:1·출처·여백을 검사한다. 완성된 원본 패킹 뒤 생성한 JSON을 런타임에 연결한다.
4. 발/발굽 지면 좌표를 프레임마다 저장한다. HP바는 살아있는 모든 자세의 최대 상단에 여유를 더한 고정 높이를 사용한다. 무기 궤적까지 겹침 여부를 확인한다.
5. region7 원화 선택을 역할별 0/1/2, 보스별 3/4/5/6으로 분리하고 레거시 원화 대신 검토된 35시트를 로드한다. 일반 환도병의 슬롯4 재사용을 여기서 제거한다.
6. 일반 3종과 보스 4종의 모든 8방향, 걷기·준비·접촉·후속·피격·사망을 독립 Playwright 컨텍스트에서 실제 렌더한다. 특히 위로 향하는 투척 공격의 손 펴기와 발사 시각을 확인한다.
7. 보스 18패턴에서 매 접촉 시점과 원거리 투사체 발생을 확인한다. 이동·공격·피격 머리 크기 및 HP바 간격을 측정한다. 기마병은 몸과 말이 함께 땅에 붙는지 별도 확인한다.
8. 유닛 검사·빌드·1366×768 / 1440×900 / 1093×614 로컬 브라우저 검사와 캡처를 남긴 후 적용 결과를 보고한다. 실제 저장 데이터는 사용하거나 변경하지 않는다.

위 적용 전 검토 목록은 처음 세운 작업 절차다. 기본 시트 생성·수동 교정·1:1 패킹·프레임별 지면 저장·역할 연결·렌더/판정 검사·로컬 빌드는 완료했다. 준비 파일 검증은 `node scripts/validate-desert-preparation.mjs`로 수행하며, 시각 및 게임 검증과 구분한다.
