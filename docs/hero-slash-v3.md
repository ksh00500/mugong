# 검을 들어 올리는 느낌 수정 · 2026-10-04

사용자가 제공한 네 애니메이션 시트를 참고해 플레이어 10종의 검·도 기본 공격을 다시 구성했다. 높은 준비에서 몸 앞을 가로질러 베고, 낮은 자세로 마무리한다. [참고 시트와 해석](source/hero-slash-v3/README.md)을 기록했다.

## 원인과 변경

v2는 조준 각도에 준비·마무리 회전값을 더하는 화면상의 회전이었다. 위쪽 공격은 검끝이 손 아래에서 출발해 위로 올라갈 수 있었고, 아래쪽 공격은 마무리 검끝이 다시 위를 향할 수 있었다. 방향에 따른 검날의 원근감도 없었다.

- `src/game/blade-motion.ts`: 낮은 수평면에서 검이 가로로 회전하는 궤적에 준비 높이를 별도로 적용한다. 모든 방향의 준비 검끝은 손보다 위에 있다. 접촉 뒤에는 조준 방향에 맞춰 검을 낮춰 마무리하고, 회수 중에는 낮은 대기 자세로 돌아간다.
- `src/game/held-weapon.ts`, `weapon-grips.ts`: 검·도의 각도와 화면상의 길이를 같은 투영 결과로 그린다. 앞·뒤로 뻗은 검날은 짧아 보이고, 옆 방향은 원래 길이를 유지한다. 손 부착은 실제 메시의 기준점을 따른다.
- `src/game/hero-slash.ts`, `CombatScene.ts`: 준비·타격·마무리 그림의 전환 시점을 조정하고 작은 몸통 비틀림, 숙임, 손 내림을 더한다. 기존 몸체 원화 150개를 사용하며 새 원화를 생성하지 않았다.
- `src/game/blade-smear.ts`: 검광도 바뀐 검끝 궤적과 원근감을 따른다. 실제 칼날 길이 안의 짧은 잔상이며 현재 손 기준점에서 계산하는 연출이다. 준비·회수·동작 감소 설정에서는 표시하지 않는다.

전체 기본 공격 0.28초, 피해 시점 0.09초, 실제 공격 범위는 유지한다. 봉·부채·암기·권갑의 전용 각도 곡선을 이번 검 궤적으로 바꾸지 않았다. 보행 방향 수정은 [별도 기록](hero-walk-directions-v1.md)을 따른다.

## 검증

프로덕션 빌드와 단위 검사 46파일·1,224개가 통과했다. 병렬 실행에서 기존 방향 데이터 검사가 기본 5초 제한을 한 번 초과해, 최종 전체 검사는 워커 2개와 10초 제한으로 실행했다.

Canvas/WebGL 연속 렌더 검사 각 2개 통과. 10종 × 6무기 × 8방향 × 두 렌더러에서 접촉 표본 960개의 축 정합성을 확인했다. 검의 준비·접촉·마무리 표본 480개는 실제 그려진 무기의 회전과 길이에서 검끝 위치를 확인했다. 단순히 투영 함수의 예상값을 같은 함수와 비교하는 검사가 아니다. 검증 화면의 브라우저 오류는 0개다.

일반/동작 감소 시간선의 전체 무장 부착 검사 4개와 실제 이동·반복 공격·가방 일시정지 검사 2개가 통과했다. 무장 부착은 10종 × 28개 장착 그림 × 8방향 × 173개 시간 표본 × Canvas/WebGL, 총 775,040개에서 실패 0개였다. 최대 손 부착 오차는 약 `2.55e-13` 월드 단위로 기준 `0.01` 미만이다. 결과는 `verification/hero-slash-v3/attachment/`의 JSON에 있다.

WebGL 연속 렌더 검사에서 브라우저 타이머의 반올림 때문에 90ms 접촉을 명시적으로 기록한 뒤 같은 시간의 화면 프레임에서도 중복 집계하는 검증 코드 문제가 발견됐다. 명시적 접촉 표본만 집계하도록 수정했고, 두 WebGL 배치를 다시 실행해 통과했다. 제품의 타격 횟수를 변경하는 수정은 아니다.

모든 시험 저장은 Playwright 독립 브라우저 컨텍스트를 사용했다. 테스트 포트는 5174로 분리해 사용자 로컬 프리뷰 5173을 유지했다. 최신 빌드는 로컬 프리뷰에 반영했으며 원격 Daytona 배포는 하지 않았다.
