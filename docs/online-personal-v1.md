# 온라인 개인 무인 · 성장 · 장비 저장

후속: [정상 수치 관측과 레이드 추격 교정](online-balance-v1.md)에서 자연 도메인20웨이브와 개인1~4인 저장/보상 관측을 추가했다. 인간 밸런스·전체 효과 동등성은 여전히 별도다.

2026-10-23. `/online/`에서 서버가 생성한 무인을 강호20웨이브로 육성하고, 완주한 무인의 무공·HP·수명·가방·창고를 서버에 저장한다. `/raid/`의 **개인 무인 출전**은 이 명부를 사용한다. 기존 표준 체험·친선/순위전과 로컬 강호는 유지한다. 로컬 IndexedDB를 온라인 무인으로 업로드하지 않는다.

## 실행과 사용

Node22.16 이상에서 `npm run pvp:build` 후 `npm run pvp:start`, 별도 터미널에서 `npm run dev`로 실행한다. 같은 온라인 계정으로 `/online/`, `/raid/`, `/pvp/`에 접속한다. Vite는 `/api/pvp`의 HTTP/WS를8787로 전달한다. Docker도 같은 경로를 사용하며 새 외부 포트는 필요하지 않다.

1. 온라인 세가에서 모집권으로 후보를 생성하고 Lv.0 무인으로 출전한다. 후보·성장 선택은 서버 저장이며 새로고침으로 재추첨하지 않는다.
2. 기존 강호20웨이브·정비 NPC·성장 선택·가방 규칙을 서버에서 실행한다. 1인 강호는 창/가방/일시정지와 연결 중단 시 멈춘다.
3. 완주 시 명부에 등록하고 서버 UTC로 현실7일 수명을 시작한다. 로비에서 선택·장비 착용·무기 연결·회전·창고 이동을 사용한다.
4. 레이드에서 개인 무인을 선택해 파티를 생성/참가한다. 현재 강호와 수련을 마쳐야 하며 입장에는 잔여30분 이상이 필요하다.
5. 전투는 계속 진행한다. 층 정비에서 실제 소지 약·성장·가방을 사용하고, 수납/보류 후 전원이 다시 준비하거나 개인 귀환한다.

## 서버와 저장 경계

- SQLite 스키마3에 `online_families`, `online_operations`, `online_reservations`, `online_raids`를 추가한다. 기존 계정·세션·비무·표준 레이드 기록은 유지한다.
- 세가 저장은 기존 `GameState` 검증, revision·commit UUID를 사용한다. 클라이언트는 의도만 보낸다. HP·XP·물품 속성·승리·seed·업로드 저장은 받지 않는다.
- 온라인 강호는100ms마다 최대6개의 고정1/60초 단계로 계산하고, SQLite FULL 동기화 저장 성공 후 상태를 전송한다. 입력은30Hz,250ms 시한과 순서를 검사한다. 성능/동접 보장 수치는 아니다.
- 명령 작업 ID는 계정별로 한 번 소비하고, 같은 ID에 다른 요청을 보내면 거절한다. 등록 무인의 ID는 서버 UUID다. 로컬 저장 모듈의 읽기/쓰기·세션 잠금을 온라인 경로에서 실행하지 않는다.
- 미확정 시뮬레이션 저장이 실패하면 해당 세션을 멈추고 같은 결과를 재시도한다. 새 소켓이 접속해도 미확정 결과를 이어받으며 그동안 이전 상태 조회·새 명령·레이드 출전을 막는다. 프로세스가 종료되면 **마지막 DB 확정 결과**를 읽는다. 미확정 프레임의 영구 보존을 주장하지 않는다.
- 출전 예약과 대기실 사본, 대기 취소/만료와 잠금 해제를 같은 트랜잭션으로 처리한다. 개인 레이드 시작·방 상태·계정별 원장, 사망·보상·유품·귀환 영수증도 같은 커밋에 포함한다.
- 개인 레이드는 저장한 방/배치/HP로 서버 재시작 후 복구한다. 표준 체험과 미완료 비무는 기존처럼 장애 무효 처리한다. 이미 확정한 개인 사망을 장애 무효로 되돌리지 않는다.

## 레이드의 개인 자산

실제 HP·무공·장비·소지품을 전투 사본에 사용한다. 개인 기본 공격에는 연결 무기와 근력, 방어에는 도포/철벽, 이동에는 신발/기민을 반영한다. 기존 강호의 모든 특성·장비 효과와 동일하다는 의미는 아니며 전 무공/효과 동등성 및 밸런스는 후속이다. 비무는 표준 무인 규칙을 유지한다.

층 보상은 개인별 XP30/40/50/60/80, 수련3점, 품질80~120의 비급/도포1개다. 완료 층과 보상 진행을 저장해 중복 지급을 막는다. 은전은 생존 귀환/완주 때 완료 층×20을 한 번 지급한다. 보상 다양화·장시간 경제 검증은 미완료다.

무장4×7·일반10×8을 유지하고 성장·장비 변경은 레이드 정비에서만 허용한다. 세가 창고는 레이드에서 사용할 수 없다. 수련 후보를 처리/보류하고 개인 전리품을 수납/폐기해야 다음 층을 준비할 수 있다. 마지막 층 보상은 귀환한 세가에서도 정리할 수 있다.

사망하면 명부에서 영구 제거하고 소지 장비/물품을 현장 유품으로 전환한다. 생존자는 정비에서 실제 일반 가방 공간을 써서 수습한다. 유품은 장비/소모품으로 사용할 수 없으며 운반자가 죽으면 같은 유품을 다시 남긴다. 생환하면 원래 주인의 창고로 전달하고 미수습분은 레이드 종료 시 소실한다. 새로운 시체/드롭 전용 원화는 제작하지 않았다.

## 수명 만료

최초 입장과 실제 출발, 다음 층 준비에서 예상 남은 최대 전투 시간+5분을 검사한다. 전투 틱 전에 서버 UTC 만료를 판정하며 이미 확정된 사망은 만료로 바꾸지 않는다. 대기/정비가 수명을 정지시키지 않는다.

만료된 무인은 공격을 중단하고 파티 준비를 풀며 자기 물품은 자기 창고로, 운반 중 유품은 원래 주인의 창고로 반환한다. 사망 횟수·처치 보상·귀환 은전을 만들지 않는다. 대기실 만료도 잠금 해제/방 변경과 함께 저장한다. 반로환은 아직 구현하지 않았다.

## 배포와 남은 범위

`.dockerignore`에 `/online/index.html`을 포함했다. SQLite 스키마3 적용 전에 일관된 DB 백업을 보관한다. 스키마2까지만 지원하는 이전 서버 이미지는 새 DB를 열 수 없다. 롤백을 이유로 확정 사망 이전 DB를 복원하지 않는다.

이번 로컬 출력 `dist-online-personal-v1`은 public junction을 공유하는 미리보기이며 배포용 압축본이 아니다. Docker 표준 빌드는 독립 미디어를 포함한다. Docker 데몬 조회는10초 무응답으로 최신 이미지 빌드/컨테이너 실행을 확인하지 못했다. 데몬/다른 컨테이너를 재시작하지 않았다. 집 Linux/Cloudflare/HTTPS 공개 배포는 별도다.

다음은 정상 수치의 자연20웨이브·개인1~4인5층 밸런스, 실제 지연/손실/부하와 움직임 보간, 방 전체 자산 전송 축소, 전 무공/장비 효과와 새 무기 로딩 동등성, 계정 복구/운영 관측, 다양한 레이드 기믹·보상이다. 개인 무인 PvP·생사결·시장·시즌·반로환을 이번 완료로 합산하지 않는다.
