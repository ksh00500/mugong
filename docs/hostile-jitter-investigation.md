# 공격 후 적 떨림 조사

2026-10-03. 아래 원인 조사 후 이동 상태 수정과 AI 방향 보간을 구현했다. 배포 상태는 별도 검증 기록을 따른다.

## 적용한 수정

- `src/domain/game.ts`의 고정 전투 갱신에서 실제 좌표 변화를 계산해 `Enemy.moving`으로 유지한다. `CombatScene.drawEnemy`는 이 상태를 사용하며 중간 렌더 프레임의 좌표 무변화를 정지로 해석하지 않는다.
- 2.4초 주기의 횡이동 부호 변경 전후를 계측해 순간 방향 반전을 확인했다. `enemy-tactics.ts`에서 전술 속도를 시간 기반 지수 보간(12/s)하고, 접근/회복의 방향 변경을 10rad/s로 제한한다. 공격 진입 시 보간 상태를 초기화한다. 발사된 공격/돌진/최종 준비의 조준은 변경하지 않는다.
- 보간 속도는 적 데이터에 저장하므로 저장 복원/상태 복제에서 동일한 결과를 낸다. 원화 뒤집기도 동일한 방향 샘플을 사용한다.
- `tests/hostile-movement-state.test.ts`: 실제 전투 tick과 MotionClock를 함께 사용해 60/120/144Hz에서 회복 중 지속 이동 판정의 반복 교대가 사라진 것을 검증했다. 실제 정지/경직, 횡이동 반전 완화, 방향 변경 상한, 복제 상태 일치도 검증했다. 사용자의 실제 모니터에서 촬영한 결과는 아니다.
- `tests/e2e/hostile-simulation-movement.spec.ts`: 실제 Phaser의 일반 적/보스 7개에 각 렌더 주기를 적용하여 좌표가 갱신되지 않는 중간 프레임에서도 이동 원화가 유지되고, 실제 정지 시에만 회복 원화로 전환되는 21개 조합을 검사했다. `docs/verification/character-growth-v2/renderer-movement.json`에 결과를 남겼다.

## 확인한 로직 원인
- src/game/CombatScene.ts:334: 시뮬레이션은 accumulator 기반 고정 1/60초 갱신.
- src/game/directional-motion.ts MotionClock.moved: 직전 렌더 시점 좌표와의 거리 >0.05만으로 이동 여부 판단. sample은 매 렌더 프레임에 기록 좌표를 갱신.
- src/game/CombatScene.ts:585: recover && moving이면 recoveryStep=true, drawingPose=null. 그렇지 않으면 회복 원화(0번) 사용.
- 같은 클래스 action 선택: recoveryStep이면 walk/idle, 그렇지 않으면 recover. 따라서 좌표가 갱신되지 않은 중간 렌더 프레임에서 텍스처/원점/표시 크기/리그가 함께 전환될 수 있음.

## 재현
실제 MotionClock를 Node 타입 제거 모드로 불러와, 초당60회 일정 속도80으로 이동하는 좌표를 각 렌더 주기로 샘플링함. 사용자 저장이나 런타임 상태를 변경하지 않음.

| 렌더 Hz | moving 판정 프레임/초 | 정지 판정 프레임/초 | 회복 그림↔걷기 그림 전환 조건 변화/초 |
|---|---:|---:|---:|
|60|60|0|1 (초기 전환)|
|120|60|60|119|
|144|60|84|119|

이 결과는 지속 이동인데도 정지로 오판하는 프레임과 recoveryStep 교대 발생을 확인한 로직 재현이다. Daytona에서 실제 렌더 캡처로 확인한 결과는 아님. 사용자의 실제 모니터 주사율도 확인하지 않았음.

## 추가 가능성(미확정)
- 전술 이동은 거리 임계값, 장판 회피, 탄 회피, 군집 분리에 따라 즉시 속도가 달라지고 감속/방향 보간 없이 좌표를 갱신함. 경계에서 작은 진동이 발생할 가능성이 있으나 아직 계측되지 않음.
- 회복 중 facing은 현재 타깃을 따르지만 원화 flip은 이전 aim을 사용. 원화와 방향 그림을 오가면 방향 차이도 튀어 보일 수 있음.

## 수정 제안
이동 판정은 시뮬레이션 이동 속도 또는 짧은 유지 구간을 사용하는 지속 상태로 만들고, 렌더 간 좌표 무변화를 정지로 해석하지 않는다. 회복→걷기 전환도 일관된 시뮬레이션 상태를 따른다. 이후 60/120/144Hz 지속 이동과 실제 정지에서 프레임/방향/발 기준점을 계측한다. 주사율을60으로 제한하는 것은 원인 수정이 아니다.
