# 전체 화면 UI·UX v2

2026-09-28. 화면을 줄이거나 문서를 스크롤해야 관리할 수 있었던 가방을 전체 화면 작업 공간으로 변경했다. 게임 규칙과 저장 형식은 유지한다.

## 적용

- 로비는 화면 전체 배경과 가용 너비를 사용한다. 전투의 외부 프레임·하단 문서형 조작 바를 제거하고 HUD를 화면 가장자리에 배치한다. Phaser FIT로 플레이 가능 영역 전체를 유지한다. 화면 비율이 달라도 맵을 잘라 확대하지 않는다.
- 가방·창고는 전체 높이의 헤더, 격자·상세 영역, 하단 물품 영역, 상태 바로 구성한다. 크기를 가용 공간에서 계산하며 CSS scale이나 브라우저 배율 축소로 문제를 감추지 않는다.
- 큰 화면은 두 가방과 무인·선택 물품 정보를 함께 보여준다. 좁은 화면은 보조 정보 또는 가방 영역을 버튼으로 전환한다. 무공·착용 장비도 같은 자리에서 전환한다.
- 전리품·임시 정리판·세가 창고는 하나의 하단 영역을 공유한다. 긴 목록은 이전·다음 페이지로 찾는다. 창고 이동과 정리판 이동 직후 해당 영역을 자동으로 표시한다.
- 수납 가능한 칸만 활성화한다. 클릭 배치를 유지하고, 방향키로 다음 가능한 빈 칸에 초점을 이동할 수 있다. 선택·회전·물품 정보는 영역을 바꿔도 유지된다.
- 누른 버튼이 이동 결과로 사라져도 초점이 창 밖으로 빠지지 않는다. Esc 닫기, Tab 순환, 닫은 뒤 원래 버튼 복귀를 검증했다. 정리판 폐기는 물품 개수와 최대 네 개의 미리보기를 보여주고 계속 정리할 수 있다.
- 모서리·표면·그림자를 부드럽게 통일하고 버튼 반응에 180ms easing을 사용한다. 전투 HUD의 배경 블러는 불필요한 소프트웨어 렌더링 비용을 줄이기 위해 제거했다.
- 화면 설정에서 브라우저가 지원하는 경우 네이티브 전체 화면을 켜고 끌 수 있다. 높은 대비·큰 HUD 글씨와 기존 저장은 유지된다.

## 참고 기준 설정

[가이드 목록과 라이선스](reference/ui-ux-guides.md)에 Vercel Labs, IBM Carbon, Radix 공개 Markdown 원문을 보관했다. 기존 Google Labs DESIGN.md 명세도 함께 사용했다. `AGENTS.md`가 앞으로의 UI 변경 전에 `DESIGN.md`·`UX.md`·가이드 목록을 읽고 실제 화면과 조작을 검증하도록 연결한다. 업무용 웹 UI를 게임에 그대로 복제하거나 새 UI 라이브러리를 설치하지 않았다.

## 검증

- TypeScript 검사 및 Vite 프로덕션 빌드 성공.
- 전체 Playwright 17개 통과. 이후 실제 앱의 작은 패널에서 발견한 낮은 높이의 배치 문제를 수정하고 관련 로비·가방·성장·폐기 확인 4개 검사를 다시 통과했다.
- 가방: 1920×1080, 1440×900, 1366×768, 1093×614, 1024×768, 390×844, 602×546. 1093×614는 1366×768 화면의 125% 배율과 비슷한 CSS 가용 공간이며 실제 브라우저 배율 변경 테스트와는 구분한다.
- 가방 격자와 하단 영역 겹침, 상세 행동 버튼의 화면 밖 배치, 내부 overflow, 많은 전리품의 페이지 이동, 클릭 수납, 네 무공·장비 정보, 창고 왕복과 저장을 검사했다.
- 성장 선택의 세 카드와 선택 버튼이 가용 화면 안에 들어오는지 확인했다. 아주 낮은 좁은 패널에서는 긴 소개문을 생략하고 성장 단계·방어 동작·선택 행동을 유지한다. 전체 소개문은 일반 화면과 카드 도움말에서 확인한다.
- 실제 Codex 브라우저에서 최신 `viewport-ui.css` 적용, 로비의 세로·가로 스크롤 없음, 버튼 겹침 없음, 콘솔 오류 없음을 확인했다. 사용자 저장을 초기화하거나 테스트 데이터로 바꾸지 않았다.

이 검증은 Windows Chromium과 현재 UI 범위다. 화면을 감추는 대신 읽기 위해 필요한 안내 문서의 스크롤은 허용한다. 고배율 접근성·다른 브라우저·모바일 전투 조작의 완전한 인증을 의미하지 않는다.
