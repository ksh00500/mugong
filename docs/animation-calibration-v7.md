# 애니메이션 크기·기관 장치 보정 v7

2026-10-03. 사용자 제보: 공격 때 축소, 사망 때 확대, 기관 장치 몸체 전체 회전.

## 원인과 변경

- v6의 얼굴색 연결 영역은 손·모자 장식·가려진 얼굴과 사망 자세에 민감했다. 현재 렌더링은 이 측정을 사용하지 않는다.
- `src/game/pose-calibration.ts`의 `silhouetteUnit`은 알파 200 이상인 실루엣 면적의 제곱근을 사용한다. 반투명 그림자/효과를 제외하며 가로로 누운 자세도 세로 높이로 확대하지 않는다. 무기·의복 면적도 포함하는 시각 크기 기준이다. 해부학적 키나 얼굴 크기 측정이라고 주장하지 않는다.
- `src/game/enemy-motion.ts`: 각 원화의 표시 배율을 동일 캐릭터 기준 면적으로 보정한다. 방향 원화와 동작 원화 사이도 같은 단위를 비교한다.
- `src/game/cavalry.ts`: 기병 방향 이미지와 동작 이미지의 별도 크기 차이를 같은 기준으로 보정한다.
- `src/game/character-sheet.ts`: 주인공에도 방향별 기본 자세에 대한 면적 보정을 적용한다. 기존 손 좌표를 유지하므로 장착 무기 위치 매핑은 보존한다.
- `src/game/CombatScene.ts`: 주인공의 준비·공격 원화에 팔다리 변형을 중복 적용하지 않고 잔여 움직임을 12%로 줄인다. 적 원화도 동일한 기존 제한을 유지한다. 사망 원화에는 추가 접기 변형을 적용하지 않는다.
- 화면의 회오리 장치는 수리 드론(프레임 5)과 다른 회전 칼날 장치(프레임 6)다. 칼날 장치가 통째로 회전하던 처리를 제거했다. 공전 위치와 피해 판정은 그대로다. 드론은 몸통을 돌리지 않고 작은 상하 부유만 사용한다. 기관 장치의 표시 종횡비를 원본 셀 비율에 맞춘다.
- 원본 그림을 새로 생성하거나 덮어쓰지 않았다. 기존 독립 프레임 추출과 런타임 크기/변형을 수정했다.

## 검증과 증거

- 빌드 성공, 31개 파일의 단위 검사 794개 통과.
- 10지역 표시 배율 비교 10건과 모든 지역 역할·보스 8방향 동작 정책 검사 10건 통과.
- 주인공 기본/준비/공격 실제 actor 배율과 드론/칼날 장치 회전 검사 통과.
- WebGL 및 Canvas 동작 검사와 영상 기록. 최초 WebGL 실행은 영상/trace 파일 전송 실패로 종료되었으며 trace를 끄고 재검사했다.
- 캡처 시 수동 지정한 사망 자세를 다음 자동 draw가 덮어쓰는 문제를 발견해 검사 장면의 업데이트를 일시정지했다. 사용자 게임 상태와 실제 저장에는 적용하지 않는다.
- `docs/verification/animation-calibration-v7/`: 주인공 40프레임, 지역별 동작/방향 비교판, 전용 역할/기병 비교판, 실제 전투 이미지 및 두 렌더러 영상.
- 모든 지역 동작 비교판과 주인공/기병 비교판을 시각적으로 검토했다. 면적 일치 자동 검사는 체형·무기 자세의 예술적 자연스러움을 인증하지 않는다.
- Daytona `20261003-animation-v7`: 서버 266개 파일 SHA-256 일치, 공개 출전/전투/가방/저장 복원 검사 통과. 이전 릴리스 백업 유지.

## 남아 있는 아트 제약

- 후면 3방향 전용 공격·피격 원화는 여전히 없다. 방향 원화에 변형 모션을 적용하는 기존 경로를 사용한다.
- 기존 6자세 원화의 중간 그림을 새로 그린 작업은 아니다. 자세 사이의 체형·얼굴·의상 세부 차이는 원화 제작 검토 대상이다.
- 실루엣 기준은 장식·무기가 커지는 향후 캐릭터에 대해 시각 검토가 필요하다. 알파/영역 추출 오류를 이 배율 보정으로 숨기지 않는다.
