# 전체 시스템 완성도 점검

후속 갱신: 이 문서는 효과 v2 직후의 감사 기록이다. 아래 보스 대체 동작 항목은 이후 승인받아 구현했다. 현재 규칙/증거는 [보스 기믹 구현 v1](boss-mechanics-v1.md)을 우선한다. 온라인 목업과 인간 난이도·실기기 검증의 한계는 여전히 남아 있다.

후속 원문 대조와 보스별 전체 개선 대상은 [대체 동작 개선 목록](boss-mechanic-rebuild-list.md)을 참조한다. 반사는 원문의 **대나무 반사 투사체**, 오아시스는 **접근 차단**을 뜻하며 플레이어 탄 반사나 오아시스 회복을 필수 원문 기능으로 단정하지 않는다.

2026-10-02. 실행 코드, 데이터, 관련 단위/브라우저 검사를 대조했다. 이름이나 설계 문서가 있다는 이유로 완성으로 계산하지 않는다. 아래 '동작 구현'은 서비스 출시 완료나 모든 버그 부재를 뜻하지 않는다.

## 이번에 고친 불완전 처리

1. 먼지·눈보라·연막의 그림만 있는 플레이어 효과와 설치 즉시 구역 밖 보스 은폐.
2. 불·술·독뢰·기관 함정의 공통 5 피해 반복 분기.
3. 혈교 기본 투척과 보스 착탄이 독 장판/중독 개념을 재사용하던 부분.
4. 정화초가 새 상태를 없애도록 확장하고, 새 상태의 전투 정지·웨이브 초기화·저장 검증 연결.
5. 제거된 예고 범위를 회피하라는 설명을 현재 위험 구역 이탈 문구로 교체.
6. 환경 구역 도중 반격 처치가 성장 선택을 열 때 남은 구역 처리를 즉시 중단하도록 보완.

## 완성으로 처리하면 안 되는 항목

| 우선순위 | 코드에서 확인한 차이 | 필요한 후속 작업 |
| --- | --- | --- |
| P1 | `reflect`는 회수형 3발 발사다. 원문의 대나무 충돌 반사는 없다 | 대나무 충돌면·반사 방향/횟수 제한, 판정·그림·설명 연동 |
| P1 | `exchange`는 봉인+혈지대다. 보스와 플레이어 체력 교환은 없다 | 의도에 맞는 교환 규칙 확정 후 방어/사망/저장 안전성 구현, 또는 명칭/기획 수정 |
| P1 | `rotate`는 벽 두 개+진법이며 회전하는 문이 아니다 | 실제 회전 충돌/탈출 공간·경계 판정, 또는 패턴 이름 수정 |
| P2 | `repair`는 쇠뇌를 직접 수리한다. 수리 드론 개체는 없다 | 파괴할 수 있는 지원 개체가 필요한지 정한 뒤 구현 |
| P2 | `bamboo`·`oasis`는 돌벽 판정을 사용한다. 대나무 쓰러짐·실제 오아시스 접근 차단은 없다 | 전용 오브젝트와 실제 지형/동작. 오아시스 회복은 원문에서 확인되지 않음 |
| P2 | `grab`은 사슬 끌어당김이고 전용 잡기 동작/상태는 없다. 정화초는 파괴 대신 접촉 사용 | 실제 현재 규칙을 기준으로 원문 기획 정리, 필요하면 독립 패턴 제작 |
| P2 | 적 강화 깃발/봉인, 보스 안전지대/플레이어 진법은 일부 같은 그림 사용 | 진영과 목적이 다른 그림·색·짧은 피드백 구분 |
| P2 | 전체 화면 모래바람·죽림 연막은 연출이며 플레이어 시야 시스템은 없음 | 이번 작은 보스 구역과 구분. 시야 축소 도입 여부는 미확정 |
| 별도 단계 | 온라인 레이드·비무·생사결·시즌/유품/매칭·계정은 설계/목업, 실제 서버 기능 없음 | 서버 권한·영속 자산·모드 판정부터 구현. UI 완성을 게임 완성으로 계산하지 않음 |
| 운영 전 | 새 피해·이동 배율과 중첩 상태의 인간 난이도 검증, 모든 보스 개별 반복 플레이는 미완료 | 사람의 플레이 기록으로 회피 가능성·체감·빈도 조정 |

근거는 `src/domain/boss-encounters.ts:signatureCast`, `boss-attacks.ts`, `src/next-stage/NextStageApp.tsx`다. 기획 이름의 재현 여부와 실행 오류를 구분한다. 신규 무공 가방 만석 문제는 `eligibleOffers`에서 이미 후보를 제한하므로 단순히 `choose`의 실패 분기만 보고 막힘으로 판정하지 않았다.

## 문서/기술 부채

- 과거 개발 문서에는 4지역/4계열, 정리판, 공유 물품 그림, 공격 예고에 관한 **당시 상태**가 남아 있다. 예: `docs/next-stage-design.md`, `docs/gangho-completion-v1.md`. 최신 코드보다 우선하는 사양이 아니다. 삭제하지 않고 현재 상태 문서와 변경 날짜로 구분한다.
- `Item.kind === 'sword'`는 현재 여섯 무기 유형의 공통 분류다. 실제 종류는 `weaponStyle`과 호환 규칙을 확인해야 한다. 모든 무기를 검으로 바꾸는 분기는 잘못된 수정이 된다.
- `src/domain/game.ts`는 진행·거래·전투를 함께 담은 큰 모듈이다. 책임 분리는 기술 부채지만 이번에 넓은 리팩터링은 하지 않았다.
- 로컬 단일 플레이 검증과 서버의 동시성/치트 방지 검증은 서로 다른 범위다. 현재 저장 검증은 온라인 서버 검증을 대신하지 않는다.

## 검사 범위와 제한

전체 단위 검사는 전투·진행·물품·성장·지원 효과·저장·번역·에셋을 포함한다. 브라우저 검사는 이번 구역 5종, 기존 적 8항목, 가방/성장/창고, 보스 소품, 웨이브 흐름과 주요 화면 크기를 확인한다. 새 상태 저장 호환성과 잘못된 타이머 거부도 검사한다. 자동 입력의 통과가 인간 난이도·서비스 완성·모든 동작의 원화 품질 인증은 아니다.

실제 사용자 저장은 건드리지 않았으며 테스트 상태는 분리된 브라우저 컨텍스트에만 넣었다. 이 요청에서 공개 서버 재배포는 하지 않았다.
