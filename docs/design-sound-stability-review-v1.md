# 디자인 통일·사운드·안정성 사전 조사

2026-09-29. 사용자가 수정 전 조사와 보고를 요청했다. 게임 코드·에셋·설계 기준·배포 설정은 변경하지 않았다. 조사 스크립트와 이 보고서, 독립 Playwright 브라우저의 캡처·측정만 추가했다. 실제 사용자 저장과 실제 브라우저 설정은 사용하지 않았다.

## 판단

현재 화면의 정체성은 **카툰 무인과 넓은 전투 공간 + 한지·먹·옥·황동의 무협 UI**로 유지하는 편이 맞다. 사용자가 이미 승인한 조합이므로 화면마다 새로운 화풍을 도입할 이유는 없다. 다음 작업의 중심은 공통 규칙의 정리, 작은 화면의 정보 위계, 소리의 질감과 믹싱, 입력·저장·배포 복구다.

한 번에 전체 코드를 재작성하면 지금 확보한 조작과 반응형 배치가 다시 깨질 위험이 있다. 현재 최종 화면을 기준으로 컴포넌트별로 통합하고 기존 검사와 비교하는 방식을 추천한다. 아래 방향은 제안이며 아직 적용하지 않았다.

## 디자인 통일에서 다룰 범위

- **기준 문서의 충돌:** `DESIGN.md` 초기 색 기준은 어두운 전투 HUD이고, 최신 부분은 종이 리본·부채다. 경험치는 청록으로 적혀 있지만 실제 최신 HUD는 황동색이다. frontmatter 모서리 값 3/5/7px, 본문 14~20px, 컴포넌트 실측값도 서로 다르다. 동작 시간도 110~150ms와 180ms가 함께 남아 있다. 최신 사용자 요구를 기준으로 하나의 현재 규칙을 만들고 이전 규칙은 이력으로 분리해야 한다.
- **가방 규칙:** `AGENTS.md`의 전리품·정리판·창고 탭 문구와 최신 사용자 요구·`UX.md`의 동시 표시가 다르다. 사용자가 지적한 한눈에 보는 가방을 기준으로 유지하고 페이지 이동은 각 보관 영역 안에서만 사용하도록 기준을 정리할 것을 제안한다. 4×7·10×8은 유지한다.
- **스타일 구조:** `main.tsx`에서 CSS 13개를 순서대로 불러온다. 빈 줄 제외 11,857줄, `!important` 46곳이다. 이 숫자가 곧 속도 결함을 뜻하지는 않는다. 같은 요소의 크기·색·여백을 여러 파일에서 바꿔 회귀와 기준 혼동이 생기기 쉽다는 유지보수 문제다.
- **공통 컴포넌트:** 주요/보조/위험 행동, 닫기, 페이지 이동, 게이지, 선택, 포커스, 비활성·저장 중·실패 상태를 같은 규칙으로 정리한다. 화면의 목적 때문에 크기가 달라지는 것은 허용하되 그 차이를 명시한다. 가방 닫기와 설정 닫기는 현재 높이·글자 크기가 다르다.
- **글자·수치:** DOM은 고운 서체와 언어별 서체 토큰을 사용하지만 전투 피해·방어 문구는 `Malgun Gothic`으로 고정된다. 전투 내 숫자와 HUD 숫자의 선명도·표시 단위를 함께 맞추고 CJK 언어의 줄바꿈도 확인한다.
- **실제 그림:** 그림의 먹선·재질 강도·외곽선과 실제 클릭/선택 영역을 함께 본다. 작은 가방에서 칸은 맞지만 검 그림의 유효 폭이 작아 종류·방향의 첫 인지가 어렵다. 점유 규칙을 바꾸기보다 그림의 여백과 표시 크기를 조정한다. HUD 장식을 가방 모든 칸에 반복하지 않는다.
- **정보 위계:** 1093×614의 현재 성장 화면은 한 장과 `1 / 3` 페이지 표시다. 큰 제목·여백을 줄이고 세 후보의 이름·핵심 효과·방어·선택을 함께 보여주는 방향을 검토한다. 전투 중앙과 가방 전체 작업 공간을 확보하는 요구도 함께 지킨다.

## 사운드 현황과 제안

현재 오디오는 `src/platform/audio.ts`의 Web Audio 합성 8종이다. 베기/접촉은 잡음과 필터, 피격·성장·사망·반격·방어·회피는 짧은 발진음이다. `public`에서 별도 음악·효과음 파일은 발견하지 않았다. BGM·환경음·발걸음·수납/선택 UI음은 구현되어 있지 않다.

이미 맞춘 실제 접촉 시점은 유지한다. 다음에는 검 바람·실제 접촉·내 피해·반격·방어의 음색을 분리하고 각 효과의 작은 변형을 준비해 반복감을 줄인다. 중요한 알림이 다수 타격에 묻히지 않도록 동시 재생 수와 우선순위를 정하고, 효과음·음악·환경음 버스와 전체 볼륨을 마련한다. 현재 소스별 gain은 바로 출력에 연결되어 있어 공통 믹싱과 동시 재생 한도가 없다. 한 프레임의 적중 소리를 묶는 처리는 이미 있다.

UI음은 실제 선택·수납 성공·불가·확인처럼 결과가 있는 동작에 짧게 붙인다. 모든 호버와 매 입력에 소리를 추가하는 방식은 피한다. 전투 음악/환경음은 위 방향 선택 후 준비하며, 필수 전투 효과음이 준비되기 전에 일반 음악 로딩 때문에 출전이 지연되지 않게 한다. 음소거에서도 게임 정보를 화면으로 확인할 수 있어야 한다.

이번 조사는 소스·발생 조건·오디오 준비·설정 동작을 확인했다. 사람이 청취한 음질·피로도·음량 평가나 스피커/헤드폰별 검증은 수행하지 않았다. 실제 음원 시안을 같은 전투에 올려 듣는 단계가 따로 필요하다.

## 안정성의 남은 범위

- **저장 복구:** 현재 IndexedDB `current` 단일 저장과 version 1 검증만 있다. 이전 정상 세대·원본 내보내기·마이그레이션이 없다. 복구를 설계할 때 사망·획득 결과를 임의로 되돌리는 플레이 기능과 구분해야 한다. `open()`의 오래 걸리는 요청·blocked·versionchange와 일반 런타임 예외 복구도 조사 범위에 포함한다.
- **저장과 입력:** 자동 저장은 약 1초마다 또는 처치·레벨·단계 변화 때 실행하며 가족 자산까지 복사한다. 규모가 커졌을 때 복사·쓰기 비용과 입력 지연을 측정해야 한다. 기존 사망·성장·난수 보존, 실패 시 정지는 유지할 조건이다.
- **브라우저 수명주기:** 숨김·포커스 상실 시 정지와 단일 탭 Web Locks 보호는 있다. Web Locks가 없는 환경은 보호 없이 진행한다. 지원 환경, 실제 BFCache 복귀, 저장 완료 전 종료, AudioContext 중단·재개를 검증해야 한다.
- **렌더러 차이:** Canvas와 WebGL을 나누고 있으며 Phaser 자체에는 WebGL 컨텍스트 복원 처리가 있다. 따라서 엔진의 복원 기능이 없다고 판단하지 않는다. 다만 앱의 정지/안내/복원 처리와 실제 GPU 시험은 별개다. 적·피격의 tint에 의존하는 구분도 Canvas에서 동일한지 비교해야 한다.
- **성능:** 이번 Canvas 3초 표본은 181프레임, p95 약 16.7ms였다. 한 적이 있는 짧은 표본이며 장시간·후반 보스·다수 투사체·기기 성능의 보증으로 사용할 수 없다. 30분 이상 플레이, 전투 재진입 반복, 큰 명부·창고, GPU 메모리와 오디오 동시 재생을 측정해야 한다.
- **배포·네트워크:** 위 구버전 모듈 404를 우선 처리하고 지연 모듈/그림/소리 로딩 실패·재시도도 검증한다. 이전 공개 검사에서 HTTP/2 수신 지연을 검증용 HTTP/1.1로 우회한 기록은 일반 사용자 Chrome의 복구 검증을 대신하지 않는다. Daytona 정적 미리보기의 프로세스 재시작·모니터링은 서비스 운영 검증과 구분한다.
- **범위 경계:** 레이드·비무·시장·계정은 아직 구현되어 있지 않다. 이번 디자인·사운드 통일을 위해 온라인 기능이나 전투 규칙을 새로 도입할 필요는 없다. 이후 서버 작업의 안정성은 별도로 평가한다.
- **변경 관리:** 현재 Git에서는 주요 소스가 추적되지 않은 파일로 표시된다. 다음 수정 전에 검토 기준이 되는 버전을 기록하는 절차도 필요하다. 이번에는 커밋·푸시·파일 삭제를 하지 않았다.

## 승인 후 진행 순서 제안

1. 위 시각·읽기·음악 방향을 확정한다. 문서의 현재 기준과 이력을 분리하고 현행 캡처를 비교 기준으로 둔다.
2. 저장 중 전환 입력, 논리 불일치 저장의 복구 화면, 큰 HUD 설정, 음소거 보존, 키보드 오디오 준비, 구버전 모듈 제공을 각각 재현 검사와 함께 수정한다.
3. 공통 토큰과 버튼·게이지·창을 정리한 뒤 로비 → 가방/창고 → 성장 → 전투 HUD 순으로 옮긴다. 최종 동작을 유지하며 낡은 덮어쓰기 규칙을 단계적으로 제거한다.
4. 실제 효과음 한 세트와 믹서를 붙이고 같은 전투에서 청취한다. 선택한 음악 방향을 적용한다. 작은 화면에서는 소리 설정도 스크롤 없이 핵심 조작이 가능하게 배치한다.
5. 세 해상도·다섯 언어·큰 글씨·고대비·움직임 줄이기, 수납/드래그/키보드/초점, 새로고침·탭·오프라인·저장 실패·배포 교체를 검증한다. 하드웨어 WebGL과 장시간 플레이도 별도로 확인한다.

## 이번 검증의 범위

- 현재 소스의 단위 테스트 6개 파일·63개가 다시 통과했다.
