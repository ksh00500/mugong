# 로딩 v2 — 필요한 전투만 먼저 준비

2026-10-19. 사용자 체감 로딩 지연을 조사하고 로비·첫 전투·정비/지역 전환의 필수 경로를 줄였다. 게임 규칙·원화 픽셀·캐릭터 배율·무기 손 좌표·HP바 간격은 그대로다.

## 확인한 원인

기존 지역 목록은 일반 적3종과 보스4명/모든 패턴을 함께 준비했다. 지역에 따라52~93MiB이며, `syncRegion`이 최초 장면 구성 중 다음 지역 전체까지 다운로드/등록했다. 설산 첫 전투에서는 입장 때 시작한 그림 요청 범위가 약195.5MiB/190URL이었다. 이는 완료된 네트워크 전송량이나 필수 파일만의 합계가 아니라, 시작한 요청 URL의 원본 파일 크기 합계다.

로비는 모집·장비·보스 전리품처럼 아직 열지 않은 화면의 그림까지12개/8.41MB를 기다렸다. 지역 로딩 경로가 모든 원화 프레임 JSON을 정적으로 가져와 초기 main JS도5.35MB였다. 현재 외형 외에 같은 묶음의 다른4명 공격 그림과, 새 원화를 쓰는 적에게 보이지 않는 구형 적 그림도 분석/등록했다. 이미지 수가100%에 도달한 다음의 픽셀 처리·GPU 등록도 하나의 긴 동기 구간이었다.

## 바꾼 구조

- `UI_BOOT_IMAGES`: 로비 첫 화면5개/1.74MB만 대기한다. 나머지 화면의 그림은 실제 표시할 때 브라우저가 가져온다. UI_IMAGES의 전체 목록/그림은 보존한다.
- 지역 프레임 전체를 초기 화면에 import하지 않고112KB 생성 인덱스로 경로를 조회한다. 원본 메타데이터에서 `npm run assets:art-index`로 만들며, 단위 검사가 생성본과 원본의 완전 일치를 확인한다. 큰 원화/프레임 모듈과 Phaser는 전투 의도 이후에 로드한다.
- 일반 전투는 해당 지역의 일반 적3종과 바닥, 보스전은 일반 적 지원군과 현재 보스의 기본/특별 패턴만 필수다. 실제 추가 보스 ID도 포함한다. 검토/회귀용 `regionArtManifest`는 여전히 전체 목록이다.
- 정비 때 다음 보스, 보스 처치 뒤 다음 지역의 일반 적을 idle 시간에 낮은 우선순위/동시2개로 준비한다. 최초 전투와 다음 지역 전체 다운로드를 경쟁시키지 않는다. 데이터 절약/2G에서는 선택적 선읽기를 생략한다. 필요한 순간에는 캐시를 공유하고 우선순위를 올린다.
- 현재 외형의 공격 시트1개만 준비한다. 같은 묶음의 방향/행동 시트는 원본 그대로 받되 현재 행만 분리·분석한다. 각 프레임 원본 RGBA와 발/신체 메타데이터를 기존 전체 행 방식과 대조했다.
- 현재10지역은 새 적 원화를 사용하므로 표시하지 않는 구형 적7텍스처의 다운로드/분석을 건너뛴다. 구형 fallback 목록/등록 경로는 남긴다. 무기 전환용 그림은 유지한다.
- 그림 준비와 실제 전투 화면 구성을 구분해 표시하고, GPU 등록 전에 그 상태를 한 번 그릴 기회를 준다. 임의 진척도나 수 초짜리 인위적 대기는 없다. 준비 중 입력/시뮬레이션은 재개하지 않으며 실패한 필수 그림은 저장된 여정을 유지한 채 재시도한다.

## 로컬 비교

같은 Chromium에서 브라우저 캐시를 지운 첫 진입과 재로딩을 이전/개선 컴파일본으로 각각 실행했다. 네트워크/CPU 제한은 걸지 않았다. 한 환경의 표본이며 사용자의 실물 GPU·저사양·개인 서버 네트워크 결과와 구분한다.

| 조건 | 이전 | 개선 | 시간 감소 |
| --- | --- | --- | --- |
| 설산 일반전 Canvas · 첫 진입 |4.65초|2.51초|45.9%|
| 설산 일반전 Canvas · 재로딩 |4.10초|2.46초|40.0%|
| 제갈 최종전 WebGL · 첫 진입 |5.33초|3.59초|32.6%|
| 제갈 최종전 WebGL · 재로딩 |5.36초|4.06초|24.3%|

설산 입장 그림 요청 범위는195.5→40.4MiB/190→69URL, 제갈은93.5→46.3MiB/123→76URL이었다. 초기 main JS는5,350,488→443,357바이트(91.7% 감소)다. 전체 전투 코드를 없앤 것이 아니라 큰 프레임 모듈을 초기 로비 경로에서 분리한 것이다. 가장 긴 작업은 첫 진입에서 설산2,207→777ms, 제갈3,791→1,957ms였다. 큰 mount 청크와 약2초의 동기 작업은 추가 개선 여지가 있다.

## 적용

`codex/loading-v2`, 출력 `dist-loading-v2`. 검증용 http://127.0.0.1:5210/ 에서 확인 후 기존 사용자 주소 http://127.0.0.1:5205/ 에 연결했다. 확인한 기존 미리보기 프로세스만 교체했고 동일5205의 HTTP SHA/1093 정비·저장·보스·입력도 재통과했다. 동일 origin의 실제 사용자 저장을 건드리지 않고 테스트 데이터는 독립 컨텍스트만 사용했다. 개인 서버 공개 배포와 구분한다. 이전 `dist-combat-prep-v1`과 원화 자료를 보존했다.
