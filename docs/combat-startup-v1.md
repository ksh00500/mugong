# 그림 완료 뒤 전투 초기화 지연 · 2026-10-04

사용자의 `63 / 63개 그림 준비` 화면에서 10~20초 대기하는 현상을 재현했다. 그림 파일을 받는 시간과, 받은 그림을 게임에서 쓸 수 있도록 처리하는 시간이 분리되어 있었다.

## 원인

`prepareImages`의 개수 표시는 파일 다운로드·이미지 디코딩이 끝났을 때 완료된다. 이후 Phaser가 원본을 등록하고 `CombatScene.create`에서 앞·뒤·방향·공격 시트를 프레임별로 분리한다. 연결된 캐릭터 픽셀과 가장자리의 반투명 픽셀을 추출하고, 주변 그림 조각을 제외한 렌더용 시트로 다시 묶는다.

이 단계는 브라우저 주 실행 흐름에서 동기적으로 실행됐다. 큰 시트의 각 픽셀마다 이웃 배열을 새로 만들고, 반복적인 나눗셈·나머지 계산과 RGBA 채널별 복사를 수행해 시간이 길어졌다. 따라서 개수가 모두 찬 뒤에도 화면 갱신과 입력이 기다리게 됐다. 다운로드 재시도나 의도적인 대기 타이머가 주된 원인은 아니었다.

소림 지역·플레이어 외형 6으로 측정한 수정 전 값:

| 렌더러 | 그림 완료 이후 준비 완료까지 | 그중 Scene.create |
| --- | ---: | ---: |
| Canvas | 15.06초 | 15.03초 |
| WebGL | 17.17초 | 15.25초 |

WebGL은 최초 텍스처 등록에도 약 1.87초가 들었다. 테스트 Chromium의 소프트웨어 WebGL로 강제 실행한 값이며, 사용자 GPU의 시간을 직접 측정한 것은 아니다.

## 수정

- 연결된 픽셀 탐색에서 픽셀마다 만드는 이웃 배열을 제거하고 탐색 순서를 유지했다.
- 셀 내부 탐색은 현재 픽셀 위치에서 이웃 알파값을 직접 읽는다.
- 투명한 열을 찾는 집계는 이미지 메모리를 연속해서 읽는다.
- 캐릭터와 반투명 가장자리 복사는 RGBA 네 채널을 한 번에 복사한다. 투명 픽셀 안의 RGB도 보존한다.
- 적·플레이어 시트가 같은 함수를 사용한다. 프레임 자르기 기준, 손 좌표, 무기 각도, 배율·HP바 계산은 변경하지 않았다.

수정 후 최종 단독 측정은 Canvas **2.33초**, WebGL **3.72초**였다. [수치 요약](verification/combat-startup-v1/summary.json)과 렌더러별 `before/after-*-profile.json`에 남긴다. 최초 개선 확인은 2.63초/4.44초였고, 두 브라우저와 빌드를 동시에 실행한 회귀 검사에서는 3.63초/5.76초였다. 파일 다운로드 시간은 이 비교에서 제외한다. 초기화와 GPU 등록이 모두 없어지는 것은 아니며 하드웨어·캐시·동시 작업에 따라 대기 시간은 달라진다.

## 검증

- 수정 전후 렌더용 시트 22장의 크기와 전체 RGBA SHA-256이 Canvas/WebGL 각각 일치했다. 검은 테두리나 반투명 부분도 비교에 포함한다.
- 최종 단독 프로파일 재실행도 2건 통과했다. 중간 재실행에서 후속 지역 예열 텍스처 3장이 최초 22장 비교에 섞여 계측 검사가 실패한 적이 있다. 비교 대상은 `create` 완료 시점에 존재하는 텍스처로 고정했다. 기존 22장에 픽셀 차이가 발생한 실패는 아니었다.
- 단위 검사 48파일·1,234개 통과. 픽셀 복사의 반투명 테두리, 셀 경계, 격리된 다른 그림 제외, 비영점 버퍼 오프셋을 검사했다.
- 전투 초기화 프로파일 2건, 10지역의 적·보스 방향·모션·HP바 검사 20건, 플레이어 무기 연결·원화 비교 검사 6건, 총 28건 통과. 적 크기·HP바 표본 11,200개와 무기 연결 표본 775,040개에서 회귀 오류가 없었다. 이는 모든 그림의 미적 완성도를 보증하는 검사는 아니다.
- [Canvas 준비 완료 화면](verification/combat-startup-v1/canvas-ready.png)과 [WebGL 준비 완료 화면](verification/combat-startup-v1/webgl-ready.png)을 직접 확인했다. 픽셀 일치·수치 검사와 화면 확인은 별개의 검증이다.
- 프로덕션 빌드 통과. `http://127.0.0.1:5173/`와 새 메인 번들이 HTTP 200으로 제공된다. 사용자 저장은 건드리지 않고 독립 테스트 브라우저의 저장만 사용했다.

로컬에만 적용했다. 기존 WebGL 메시 조각 현상은 이 성능 수정으로 해결했다고 주장하지 않는다.
