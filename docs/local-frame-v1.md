# 로컬 강호 프레임 개선

2026-10-23. 첫 화면에서 시작하는 로컬 강호의 연속적인 끊김 보고를 조사하고 화면 보간과 WebGL 설정을 수정했다. 사용자 PC에서 보고한 10~20FPS 자체는 재현하지 못했으므로 모든 끊김 해결로 판정하지 않는다.

## 수정

- 전투 판정은 기존 60Hz로 유지한다. 그 사이 화면에는 플레이어·적·투사체의 직전/현재 위치를 보간한다. 공격/적 행동의 남은 시간도 같은 행동일 때만 보간한다. 새 공격, 방어 이동, 큰 순간 이동, 사망, 새 개체, 웨이브/단계/저장 교체는 이전 위치를 끌고 오지 않는다.
- 보간은 렌더용 얕은 사본에만 적용한다. HP/판정/저장은 현재 실제 상태이며 입력을 대기시키지 않는다. 통상 이동의 표시에는 최대 한 판정 틱(약16.7ms)의 지연이 있다. 일시 정지·가방·선택 중에는 실제 상태를 그린다. 온라인 경로는 이번 대상이 아니다.
- 전장을 덮는 캔버스의 투명 버퍼와 WebGL MSAA를 해제하고 고성능 GPU 선호를 요청한다. GPU 선택은 브라우저의 결정이다. 원화·텍스처 필터·캔버스 해상도·캐릭터 크기·밸런스는 그대로다.

## 관측

수정 전 144Hz/240Hz 제어 일정에서 화면 위치가 바뀐 비율은 약42%/25%였다. 60Hz 판정 결과를 그대로 반복해서 그렸기 때문이다. 수정 후 초기 이력 준비 구간을 제외한 모든 화면에서 위치가 전진하며 같은 판정 횟수의 실제 상태는 대조군과 같다. 이는 제어된 갱신 일정 검사이고 실제 모니터의 FPS 측정은 아니다.

소프트웨어 WebGL의 18웨이브/적13명 장면에서 렌더 설정만 전후로 번갈아3회씩 비교했다. 약3초 표본의 FPS 중앙값은37.34→53.28, 프레임 간격 P95 중앙값은30.8→22.4ms였다. 두 조건에 같은 보간 코드를 사용했다. 기본 Canvas 단순 장면은 이미 약60FPS였으며 사용자 실제 GPU에서도 같은 개선 폭이 나온다는 뜻은 아니다. [측정·한계](verification/local-frame-v1/README.md).

## 실행과 검증

로컬 http://127.0.0.1:5205/ 에 `dist-local-frame-v1`을 적용했다. 새로고침하면 개선본을 사용한다. 기존8787 서버·실제 저장은 변경하지 않았다. 이 출력은 public 미디어 junction을 사용하는 로컬 전용이며 집 서버 배포용 독립 패키지는 아니다.

전체100파일/1579단위, 타입·에셋 검사·Vite254모듈 빌드, 소스 브라우저5개/컴파일 브라우저3개를 통과했다. 실제 키보드 이동과 저장, 마우스 공격 후 attackSeq 저장, 가방·일시 정지,1440×900·1366×768·1093×614 HUD 경계를 독립 브라우저에서 확인했다. 최신 작은 화면/혼잡 전투 PNG를 직접 검토했으며, 실제 사용자 브라우저나 실물 GPU 검사로 합산하지 않는다.

후속은 사용자 환경의 재확인이다. 계속 끊기면 그 환경의 실제 렌더러·프레임 간격·GPU 합성 비용을 측정해야 한다. 온라인 스냅샷 보간, 실제 망 지연/부하, Docker·공개 배포는 이번 범위가 아니다.
