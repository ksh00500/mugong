# 모드 전체 전투 표시·프레임 점검

2026-10-24. 로컬 강호·온라인 강호·친선/순위 비무·표준/개인 레이드의 갱신 경로를 조사했다. 서버 신호 수신 빈도로 인한 뚝뚝 끊기는 표시와 실제 렌더 비용을 분리해서 확인했다. 이전 [로컬 프레임 개선](local-frame-v1.md)을 유지한다.

## 확인한 원인과 수정

온라인 강호는 여섯 판정 틱을 한 번에 처리한 서버 상태를 초당10회 받는다. 비무·레이드는 서버가60Hz로 판정하고 보통3틱마다 상태를 보낸다. 세 화면은 받은 좌표/동작 시계만 그대로 그려 렌더러가60FPS여도 인물은10~20번만 움직였다. 같은 화면에서 원격 위치가 바뀐 비율을 별도로 측정해 확인했다. 서버 판정률이나 저장 간격을 늘리는 것으로 해결하지 않았다.

화면 전용 사본에서 마지막 두 확정 상태의 속도를 짧게 이어 그린다. 온라인 강호는 최대100ms, 비무·레이드는 통상50ms이며 누락 신호에서도100ms를 넘지 않는다. 늦은 신호의 작은 위치 오차는 다음 갱신 동안 보정하고, 큰 이동·회피·사망·새 공격·무공 전환·새 여정/층/라운드·재접속 경계는 즉시 확정 상태를 따른다. 이동은 월드 경계를 넘지 않는다. 긴 단절은 이력을 버리며 계속 떠다니지 않는다.

공격·준비의 남은 시간은 같은 행동 안에서만 표시용으로 흐른다. 서버가 발사하지 않은 투사체를 미리 만들거나 접촉/HP·보상·시뮬레이션을 진행하지 않는다. 비무의 내 이동 예측에는 실제 서버 무인과 정수 tick/ack를 계속 넘겨 중복 예측하지 않는다. 가방·일시 정지·오류·선택 중에는 실제 상태를 표시한다. 사망/피격을 늦추는 버퍼는 넣지 않았다. 이는 망 지연 자체의 제거가 아니다.

온라인 강호의 투사체 사본은 시전자/공격·위치·남은 수명으로 이전 그림과 연결해 유지한다. JSON을 새로 받을 때마다 같은 화살을 새 발사로 간주해 효과음을 재생하지 않는다. 종류/공격별 후보 묶음만 검색하며 매번 전체 목록을 복사하지 않는다. 사라진 개체의 그림은 즉시 정리한다.

비무·레이드가 모든 PC에서 Canvas만 강제하던 설정을 제거했다. 강호와 같은 GPU 판별/고성능 선호·불투명 버퍼·WebGL MSAA 해제를 사용한다. 소프트웨어 GPU/사용 불가에서는 Canvas를 유지하며 해상도·텍스처 필터·원화 크기를 낮추지 않는다. WebGL 문맥 손실은 기존 오류/재준비 경로로 연결하고 준비/복구 중 입력은 중립으로 보낸다. 비무의 활성 버튼도 실제 그림 준비와 일치시킨다. 레이드 준비 문구는 준비 완료 후 공간을 남겨 버튼 위치가 갑자기 변하지 않게 했다.

강호의 `PaintedEffects`가 화살·암기까지 매 프레임 폭탄 아틀라스에서 조회하던 불필요한 코드를 제거했다. 실제 그림은 이미 별도 아틀라스로 그렸지만 잘못된 선행 조회가 매 프레임 `has no frame` 경고를 쌓았다.18종 투사체의 실제 그리기 경로를 검사하고 반복 프레임 경고도 브라우저에서 수집한다.

## 유지한 규칙과 한계

판정60Hz·서버의10/20Hz 발행/SQLite 커밋·성장·무공·피해·보상·실제 사용자 저장은 변경하지 않았다. 공격 범위선·착탄점 예고를 추가하지 않는다. 기능적 이동은 부드럽게 표시하고 기존 동작 감소 설정의 장식 제한은 유지한다.

제어된 신호/주사율 검사와 실제 HTTP/WS/저장 검사를 구분한다. 소프트웨어 렌더러의 짧은 FPS 표본을 사용자의 실제 GPU나 모든 전투의 성능으로 확대하지 않는다. 실물 PC의10~20FPS 문제, 실제 인터넷의 지연/손실·서버 다중 파티 부하·장기 GPU 메모리는 별도 재확인이 필요하다. [이번 검증·로컬 적용](verification/all-mode-frame-v1/README.md).
