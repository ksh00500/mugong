# 디자인 통일·사운드·안정성 적용

2026-09-29. 사용자가 사전 조사의 추천 방향을 승인했고 효과음은 밝고 과장된 카툰 질감으로 변경했다. **로컬 구현·검증과 Daytona 공개 배포·검증을 완료했다.** 실제 사용자 저장을 지우거나 테스트 상태로 바꾸지 않았다. 이 보고서는 [사전 조사](design-sound-stability-review-v1.md)의 후속 결과다.

## 화면과 조작

카툰 세계·무인과 한지·먹·옥·황동 UI를 유지했다. 현재 규칙은 `DESIGN.md`, `UX.md`, `AGENTS.md`에 정리하고 이전 디자인/UX 문서는 `docs/history`에 보존했다. 전리품·가방·정리판·창고의 동시 표시는 최신 사용자 요구를 따른다. 무장 4×7, 일반 10×8과 게임 규칙은 유지한다.

- CSS 진입점을 `src/ui.css` 하나로 모으고 기존 화면과 컴포넌트 규칙의 계층을 명시했다. 성장 216개, 설정 79개의 분산 선택자를 제거해 각 화면의 CSS로 옮겼다. 기존 모든 화면을 한 번에 재작성하지 않았다.
- 버튼의 곡률·선·포커스·짧은 전환과 황동 토큰을 맞췄다. 큰 HUD는 체력 레이블과 실제 숫자도 커진다. 전투 피해 문구는 현재 언어의 UI 서체를 사용한다. Canvas의 정예/보스도 색 이외의 표식으로 구별한다.
- 1093×614 성장 선택에서 세 후보를 함께 비교한다. 좁은 창에서는 후보 이동을 유지하고 카드의 반복 여백을 줄인다. 이름·효과·방어·선택을 숨기거나 화면 전체를 축소하지 않는다. 선택의 최초 1초 오입력 방지는 유지한다.
- 가방 검 그림의 투명 여백을 줄여 칸 안에서 방향과 형태를 읽기 쉽게 했다. 실제 점유 면적이나 회전 규칙은 바꾸지 않았다.
- 설정은 화면/소리 탭으로 나누고 키보드로 이동한다. 다섯 언어와 작은 창에서도 네 음량, 음소거, 닫기가 보인다. 성장/가방의 초점·회전·착용·수납·폐기 확인도 회귀 검사를 통과했다.

## 소리

효과음은 짧은 바람·둥근 팝·목재 접촉·상승음이다. 무거운 징이나 긴 금속 잔향을 기본으로 삼지 않았다. 베기·접촉·내 피격·회피·방어·반격·위험·성장·사망과 선택·수납·성공·불가·발걸음 14종을 실제 행동에 연결했다. 호버마다 소리를 재생하지 않는다.

로비는 80 BPM의 느린 오음계 플럭/플루트, 전투는 96 BPM의 낮은 목재 리듬이다. 원본은 `scripts/compose-audio.py`로 만든 프로젝트 음악이며 외부 녹음이나 상업 샘플을 사용하지 않았다. 재생용 Opus 두 곡 합계는 532,024 bytes이고 WAV는 호환성 복구용이다.

전체/음악/효과/환경 버스와 리미터를 마련했다. 기본 음량은 각각 75%/35%/80%/20%이며 음소거와 함께 기기에 저장한다. 효과 동시 재생은 최대 12개이고 경고·피격·반격 등 중요한 소리가 먼저 나온다. 중요한 소리에서는 음악을 잠시 낮춘다. 버퍼는 재사용하고 화면을 숨기면 정지한다. 첫 키보드 또는 포인터 입력으로 시작한다.

음악은 게임 진입과 별도로 받는다. 요청 실패와 손상된 Opus 디코딩은 WAV로 대체하고 두 파일이 실패해도 전투를 막지 않는다. 다음 사용자 입력에서 재시도한다. 음악 원본의 피크는 0.58, 잘린 샘플은 0이다. 이는 청취 품질이나 모든 출력 장치의 음량 보증이 아니다.

검토용 [실제 믹서 효과음 시안](verification/unification-v2/sound-preview.webm)은 선택→수납→성공→불가→베기→접촉→회피→방어→반격→피격→경고→성장→사망 순서다. 독립 브라우저에서 기본 전체/효과 음량으로 녹음했다. [로비 음악](../public/audio/lobby-v1.wav), [전투 음악](../public/audio/combat-v1.wav), [음원 정보](../public/audio/manifest.json)도 보관한다. 사람의 스피커/헤드폰 청취 평가는 수행하지 않았다.

## 저장·복구·렌더러

| 조사 문제 | 적용 결과 |
| --- | --- |
| 저장 완료 대기 중 Q/E와 전투 진행 거부 | 일반 자동 저장은 입력과 분리했다. 쓰기는 직렬화하고 대기 중 최신 상태를 모은다. 성장·사망·단계 변경·물품 이동은 결과 보존을 위해 저장 완료를 기다린다. 실패 시 정지하고 현재 결과를 재시도한다. |
| 논리적으로 불가능한 성장 후보에서 빈 화면 | 후보와 보유 무공·최대 단계·투자 상태를 함께 검사한다. 렌더링 예외에도 복구 화면과 원본 내보내기를 제공한다. |
| 이전 배포의 해시 모듈 404 | 이전 릴리스의 해시 파일을 공유 보관하고 Nginx가 그곳에서 제공한다. 기존 `mount-CbowN5Tw.js`가 공개 200으로 복구됐으며, 이전 로비 HTML을 유지한 독립 탭에서 실제 출전·전투 모듈 로딩을 확인했다. |
| 큰 HUD의 체력 글씨 고정 | 실제 자식 레이블/숫자의 크기를 조정하고 다섯 언어에서 확인했다. |
| 새로고침 후 음소거 해제 | 소리 상태를 한 곳으로 모으고 저장·복원한다. |
| 전투의 첫 키보드 입력으로 소리가 준비되지 않음 | 실제 키보드/포인터 입력을 공통으로 처리하고 오디오 재개 실패를 처리한다. |
| 미정의 황동 선 토큰 | 공통 선 토큰에 연결했다. |

저장 DB 이름·버전은 유지한다. 현재 상태와 revision, 검증 사본을 한 트랜잭션으로 쓴다. 복구는 **최신 revision과 일치하는 정상 사본만** 허용한다. 최신 사본도 손상되면 이전의 살아 있는 무인으로 되돌리지 않는다. 복구 전에 손상된 원본을 별도로 남긴다. 기존 저장에 검증 사본이 없다면 자동으로 새 데이터를 만들지 않고 원본 내보내기를 제공한다.

IndexedDB 열기/트랜잭션 시간 제한과 연결 변경을 처리한다. Web Locks가 없는 환경에서는 보호 없이 쓰기를 계속하는 대신 지원 브라우저 안내를 표시한다. 다중 탭과 BFCache 관련 기존 보호도 유지한다.

실제 WebGL 컨텍스트 손실을 발생시켜 정지·안내·렌더러 재시도를 확인했다. 같은 무인을 유지하며 저장을 되돌리지 않는다. 소프트웨어 WebGL 검사이며 실제 기기 GPU 장애 복구 인증은 아니다.

추가로 전투 화면의 전체 엔진 폐기 시 입력 이벤트가 남아 재진입 후 E가 두 번 처리되는 결함을 발견했다. shutdown과 destroy 모두에서 같은 정리 함수를 실행하며 중복 실행도 막는다. 8회 재진입과 캔버스 1개·무공 전환 1회 검사가 통과했다.

### 장시간 검사

Canvas 1093×614, 적 28명·투사체·공격 입력·30초마다 E 전환을 **1,801,885ms(30분)** 실행했다. 60개 표본에서 전투 유지, pageerror 0, 캔버스 최대 1개, 오디오 소스 최대 5개였다. 표본 p95 프레임 간격의 최대는 약 16.8ms다. JS heap 표본은 16.1~27.6MB이며 후반은 27.6MB로 관측됐다. 거친 브라우저 메모리 표본이며 GPU 메모리/모든 기기의 누수 보증은 아니다. [원본 결과](verification/unification-v2/soak-result.json), [마지막 화면](verification/unification-v2/soak-combat.png).

이 검사는 HMR 영향이 없는 당시의 고정 빌드 `index-D534a_OY.js`/`mount-DNATg80F.js`에서 했다. 이후의 작은 창 CSS·오디오 디코딩 복구·엔진 폐기 입력 정리 등 최종 변경은 위 72개 전체 검사로 별도로 확인했다. 마지막 배포 파일 자체를 다시 30분 실행한 결과로 표현하지 않는다. 처음 내구성 데이터는 회피 입력이 테스트용 무적 시간을 덮어써 무인이 사망했다. 이를 테스트 구성 문제로 분리하고 실제 제품의 사망 규칙을 바꾸지 않았다.

최종 로컬 빌드:

- `index-cEYQ_umP.css`
- `mount-LPZfRF_x.js`

배포 패키지 `.cache/mugong-20260929-unification-v2.tar.gz`에는 실행 파일, 배포용 WebP, 폰트/라이선스, 음악과 Nginx/start 설정을 넣었다. 원본 고해상도 PNG와 테스트 데이터는 제외했다. 크기와 SHA256은 [패키지 정보](verification/unification-v2/release.json)에 기록한다. 변경 전 소스는 `.cache/before-unification-v1.zip`에 보존했다. 커밋·푸시·기존 릴리스 삭제는 하지 않았다.

첫 연결은 시간 초과로 배포를 보류했으나, 사용자가 새 SSH 접속 명령을 제공한 뒤 연결·전송·전환을 완료했다. 릴리스는 `/srv/mugong/releases/20260929-unification-v2`다. 압축 파일의 원격 SHA256이 패키지 정보와 일치하고, 공개 JavaScript/CSS 네 파일의 해시도 로컬 패키지와 일치한다. Nginx 검사·갱신 후 오류 로그는 비어 있었다.

이전 `combat-feel-v1` 릴리스는 삭제하지 않았다. 이전 설정·시작 스크립트·릴리스 경로를 `/srv/mugong/backups/20260929-unification-v2`에 보존했다. 새 인덱스를 공개하기 전에 이전/새 해시 파일 35개를 공유 영역에 두었고 링크를 원자적으로 전환했다. 전환 실패 시 이전 설정과 링크를 복원하는 절차도 마련했다.

[공개 게임](https://8080-aeae46c6-f6b0-455f-878b-f2381900a712.proxy.daytona.work/)에서 **6개 서로 다른 시나리오**를 확인했다. 기본 Chromium을 사용하며 `--disable-http2`를 적용하지 않았다. 음악 검사에서 실제 리소스 프로토콜은 `h2`였다. 출전 검사의 해상도 기록을 실제 뷰포트로 수정해 해당 검사를 한 번 더 실행했다. 최초 4개와 추가 3개 실행 모두 통과했다(출전 시나리오 1개 중복).

- 출전→이동/공격→전투 중 가방 사용 제한→일시 종료→이어하기→새로고침 저장 복원, 1093×614. 오류·실패 에셋 0.
- 새 코드/CSS 해시 일치, 오래된 모듈 3개 HTTP 200, 음악 Opus/WAV 4개 HTTP 200, 인덱스 no-cache와 해시 파일 immutable 정책.

- 네 무공의 Q/E 순환과 회피의 실제 재사용 시간.
