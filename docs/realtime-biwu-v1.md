# 실시간 친선 비무와 순위전

2026-10-23. `/pvp/`는 실제 두 계정이 같은 서버에서 대전하는 기능이다. 로비의 비무장 링크로 들어간다. `/next-stage/`의 친선/순위전 행동도 이 화면을 연다. 레이드·거래·생사결 시안과 구분한다.

## 출전과 전투

- 온라인 계정을 생성하거나 로그인한다. 이 서버의 별도 계정이며 브라우저의 세가·무인·물품·체력·수명을 업로드하거나 변경하지 않는다.
- 서버가 소유한 표준 무인 네 종류를 선택한다. 검객(매화/무당), 소림(소림/삼재), 암영(당문/천마), 기문(개방/제갈)으로 기존 여덟 계열의 기본·방어·궁극 행동을 사용한다. 체력240, 동일 이동 속도, 정해진 무공 레벨과 무장을 사용한다. 새 라운드는 체력·게이지·재사용 시간을 초기화한다.
- 친선은 6자 방 코드로 참가한다. 두 사람 모두 그림 준비와 대전 준비를 마치면 3초 후 시작한다. 순위전은 실제 다른 계정을 기다리는 대기열이며 봇으로 채우지 않는다.
- 90초 라운드, 2승 선취. 동시 쓰러짐은 해당 라운드 무승부이며 최대5라운드에서 승수가 같으면 경기 무승부다. 시간 만료는 체력 비율로 판단한다. 항복 또는 연결 종료 패배는 상대에게 최소2승을 부여한다.
- WASD 이동, 좌클릭 기본 공격, Q/E 무공 전환, Space 또는 방어 버튼, 우클릭 또는 궁극 버튼. 가방·물품·회복약은 사용하지 않는다. 설명과 확인창을 열거나 창을 벗어나도 서버 전투는 계속되며 해당 클라이언트 입력만 중립이 된다.
- 친선 결과는 기록하되 점수를 바꾸지 않는다. 순위전은 시작1000점·K24 Elo이며 같은 점수의 승패는 +12/-12다. 점수차는 결과 전에 고정한 실제 두 계정 점수로 계산하고 합산 변화는0이다. 경험치·금전·물품 보상은 없다. 순위는 순위전을 마친 계정의 상위100개, 개인 기록은 최근20개를 조회한다. 화면의 최근 기록은8개다.

## 전송과 판정

`src/pvp/engine.ts`가 서버의60Hz 고정 간격으로 이동·행동·충돌·피해·라운드·승자를 계산한다. 기존 무공 수치/방어 규칙과 몸통 캡슐 충돌을 재사용하며 PvP 전용 피해 보정을 둔다. 두 플레이어의 같은 틱 접촉을 모은 뒤 피해를 적용하므로 처리 순서만으로 동시 KO를 승리로 바꾸지 않는다. 흡혈은 실제 잃은 체력에 비례하며 쓰러진 자신을 부활시키지 않는다.

클라이언트는 방향·조준·버튼과 순번/라운드 세대만 보낸다. 위치·피해·체력·승리를 보내면 허용 필드 검사에서 거절한다. 오래된 순번/이전 라운드 입력은 무시하며 입력이200ms 없으면 중립으로 전환한다. 상태는20Hz, 입력은30Hz다. 자기 이동만 서버 확인 순번을 기준으로 예측/재적용한다. 체력·접촉·결과는 예측하지 않는다. 과거 위치를 되감는 지연 보정은 이번에 추가하지 않았다.

연결이 끊기면 재접속을 시도하고 같은 계정의 방과 자리를 복구한다. 전투는 계속되며 30초 유예가 지나면 연결된 상대가 승리한다. 양쪽 모두 끊긴 상태에서 먼저 유예가 만료되면 무효이며 Elo를 바꾸지 않는다. 같은 계정의 새 창이 자리를 복구하면 이전 연결을 종료해 두 창이 번갈아 입력하지 못하게 한다. 서버 재시작은 메모리 방을 복원하지 않으며 미완료 원장을 무효 처리한다.

## 저장과 계정

`src/pvp/server/database.ts`의 SQLite가 계정·세션 해시·경기 원장/영수증·점수를 저장한다. 한 경기 ID를 한 트랜잭션으로 정산하고, 재시도/새로고침은 이미 저장한 영수증을 반환한다. 쓰기 실패는 저장 대기 상태로 표시하고 재시도하며 미저장 결과로 재대전하지 않는다. WAL·synchronous FULL과 단일 서버의 배타적 DB 소유를 사용한다. 같은 DB를 두 서버가 동시에 열 수 없다. 진행 방은 메모리이므로 수평 복제 구성은 지원하지 않는다.

비밀번호는 임의 salt와 비동기 scrypt로 처리하고 세션은 임의 토큰의 SHA256만 DB에 보관한다. 브라우저에는 HttpOnly/SameSite=Strict 쿠키를 사용한다. 운영은 HTTPS Origin만 허용해 Secure 속성을 적용한다. API/소켓은 지정 Origin을 검사하고, JSON 크기·인증 계산 동시성·입력 빈도·송신 버퍼·방/연결 수를 제한한다. 비밀번호·쿠키·사용자 저장을 검증 문서나 로그에 남기지 않는다. 저장 DB와 백업은 자격 정보에 준해 보관한다.

## 실행

Node22.16이상에서 다음을 두 터미널로 실행한다.

```sh
npm ci
npm run pvp:build
npm run pvp:start
# 다른 터미널
npm run dev
```

개발 기본 서버는127.0.0.1:8787, Vite는5173이다. `/api/pvp` HTTP/WS를 같은 주소의 서버로 프록시한다. `PVP_API_TARGET`으로 개발/preview 대상만 바꿀 수 있다. 직접 운영할 때는 Nginx의 같은 Origin 프록시를 사용한다.

서버 환경 변수: `PVP_HOST`, `PVP_PORT`, `PVP_DATABASE`, `PVP_ORIGINS`(정확한 Origin 쉼표 목록, 경로/마지막 슬래시 제외). 기본 로컬 DB는`.local-online/pvp.sqlite`이며 Git에서 제외한다. 운영 Docker는`/app/data/pvp.sqlite`와 명명 볼륨을 사용한다. [개인 서버 설치](self-hosting.md), [Cloudflare 설치](home-server-cloudflare.md).

## 실제 적용과 후속

기존 검토된 플레이어 방향/공격 그림과 프레임별 무기 위치를 재사용하고 같은 신체 배율로 표시한다. 이름·HP·점수·접속 상태·피해 잔량·방어/궁극 버튼을 제공하며 동작 감소 설정을 존중한다. 세 기본 해상도에서 독립 브라우저 두 개로 실제 대전을 검사했다. [이번 검증과 한계](verification/realtime-biwu-v1/README.md).

시즌/티어 보상·비밀번호 복구/외부 인증·온라인 소유 무인·영구 사망 생사결·관전·친구·다인 레이드는 후속이다. Elo 매칭은 먼저100점 범위, 대기30초마다25점 확대해 최대300점이다. 인원 부족 시 대기를 유지한다. 계정 다중 생성/승부 조작 탐지, 원거리/근접의 사람 대상 밸런스, 30/80/150ms 지연·손실 행렬, 동시 부하 한계는 운영 전 추가 검증 대상이다. 설정한128연결/64방은 성능 보장 수치가 아니다. 프록시 뒤 인증 시도 제한은 해당 프록시 연결 주소 단위로 합산되므로 공개 운영의 인원 규모에 맞춰 검토해야 한다.

기술 근거: [Node22.16 SQLite](https://nodejs.org/download/release/v22.16.0/docs/api/sqlite.html), [Node crypto](https://nodejs.org/docs/latest-v22.x/api/crypto.html), [ws](https://github.com/websockets/ws), [SQLite locking mode](https://www.sqlite.org/pragma.html#pragma_locking_mode). Node22.16은 SQLite 실험 경고를 출력한다. 검증 성공과 장기 운영 안정성/보안 인증은 별개다.
