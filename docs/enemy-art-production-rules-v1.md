# 적 원화 제작 규칙 초안 · 2026-10-04

같은 인물이 공격하거나 방향을 바꿀 때 몸 자체가 축소되는 것을 막는다. 사용자의 128칸/64몸 영역은 원칙을 설명하는 예시이며 실제 출력 크기로 채택하지 않는다. 봉 승려 시범에 이어 [소림 7종 전체 방향·동작](shaolin-family-v1.md)을 적용했고, [제갈 7종 전체 방향·동작](zhuge-family-v1.md)까지 확장했다. 두 지역은 원본 픽셀·공통 배율·투명 여백·저장 접지 좌표를 사용한다. 그 외 지역은 이전 방식이 남아 있다.

## 현재 문제의 구분

`animation-rebuild-v2`는 각 칸을 무기 포함 외곽의 긴 변 220픽셀에 맞춰 리사이즈했다. `hostile-consistency-v3`는 방향·대표 방향 동작을 크기 변경 없이 변환하고, 후면 동작은 원래 픽셀 크기로 재배치한다. 후면 칸의 크기는 최대 외곽에 총 32픽셀을 더한다. 따라서 두 폴더를 같은 내보내기 축소 버그라고 분류하면 안 된다.

v3 생성 PNG에서도 크기 차이가 보인다. `region-1-actions.png`의 네 번째 열은 여러 행에서 머리·몸 자체가 작게 보인다. 후면 시트는 별도로 재생성한 보정 행도 섞인다. 소림 봉 행의 추출 높이는 126~170픽셀인데 권갑 보정 행은 약 500픽셀이다. 서로 다른 체형을 모두 같게 하라는 뜻이 아니라, 제작 해상도·몸 크기의 기준이 통일되지 않았다는 증거다. 실제 화면에서는 이를 런타임 보정으로 맞추고 있다.

기존 프롬프트에도 동일한 머리 크기·몸 비율·넉넉한 여백을 요구했다. 문구만으로 준수가 보장되지 않으므로 생성 후 검수와 거절 기준이 필요하다.

## 공간과 좌표

- 처음 제안한 전달 프레임은 **512×512픽셀**, 서 있는 기준 몸 높이는 **약 200~220픽셀**이었다. 실제 봉 승려 8방향 시범에서는 생성 원본의 몸 크기를 유지하고 **704×576픽셀** 전달 칸을 사용한다. 최소 32픽셀 여백을 확보하고 게임 배율 0.225를 모든 프레임에 적용한다. 생성 모델의 출력 해상도와 전달 프레임 크기는 별개다.
- 기준 접지점 예시는 `(256, 352)`이다. 서 있는 몸은 위쪽에 있고 좌우·위·아래에는 동작 공간을 둔다. 중앙 몸 영역은 측정 기준이지 팔다리를 가두는 제한선이 아니다.
- 무기·팔·옷자락은 몸 영역 밖으로 나갈 수 있다. 최종 칸 경계에는 최소 24~32픽셀 투명 여백을 확보한다. 같은 인물의 모든 자세를 공통 배율로 놓은 최대 외곽에서 필요한 캔버스를 계산한다.
- 동작이 칸을 넘으면 해당 인물의 전 프레임 캔버스를 함께 넓힌다. 공격 칸만 축소하지 않는다. 프레임별 자동 중앙 정렬로 의도된 접지·체중 이동·돌진을 지우지 않는다.

## 생성 규칙

1. 한 인물의 기준 원화를 승인하고 머리·어깨·몸통·사지 비율, 카메라 거리·높이, 복장·무기·장식, 색상·조명을 기록한다. 일반 적과 보스의 고유 체형은 유지한다.
2. 같은 기준에서 방향과 동작을 제작한다. 카메라 줌과 칸에 맞춘 몸 축소를 금지한다. 숙임 때문에 전체 높이가 낮아지는 것과 머리·몸통이 함께 축소되는 것을 구분한다.
3. 다인물·다프레임을 한 번에 빽빽하게 생성하기보다 한 인물의 작은 동작 묶음을 만든다. 묶음 사이에서도 기준 머리·몸통 크기를 대조한다.
4. 검·도는 몸 회전과 베기 궤적, 봉·창은 쥔 손과 찌르기/휘두르기, 투척은 준비·방출, 권갑은 지지발과 체중 이동을 구분한다. 모든 무기에 같은 공격 자세를 사용하지 않는다.
5. 공격은 준비·타격·회수를 구분한다. 피격은 공격 자세를 가리는 과도한 반동을 피한다. 사망에서도 인물 자체의 픽셀 배율은 유지한다.
6. 무기 모양만 보지 않고 목·척추·골반 및 어깨·팔꿈치·손목의 연결, 지지발과 무게 중심을 함께 확인한다. 고개와 몸통의 회전이 분리되거나 봉을 잡기 위해 팔·목이 꺾인 자세는 다시 그린다. 생성기에 숫자 좌표를 지정한 것은 실제 위치 검증을 대신하지 않는다.
7. 캐릭터 원화에는 외곽 발광·후광·배경 안개·빛 번짐·바닥 그림자를 넣지 않는다. 인물과 무기 실루엣 바깥은 알파 0인 실제 투명 배경으로 생성한다. 외곽의 자연스러운 안티앨리어싱은 유지하되, 그 주변에 반투명한 색 구름을 남기지 않는다. 공격 효과는 게임에서 별도로 표시하며 원화 배경으로 굽지 않는다.
8. 긴 창의 전방 찌르기는 허리에서 창을 당겨 싣고 두 손을 떨어뜨려 잡는다. 머리 위 준비를 무조건 찌르기에 연결하지 않는다. 창대는 한 줄로 곧게 유지하고 각 손목과 팔꿈치가 해당 손에 연결되는지 확인한다. 반대 손이 몸 뒤에 가려지는 것과 손 자체가 없는 것을 구분하고, 여분의 손이 창대 중간에 생성된 그림은 거절한다. 후면에서도 창끝의 투영 방향을 공격 방향과 대조한다.
9. 긴 무기의 공간은 생성 단계에서도 확보한다. 원본 셀이 빽빽하면 적은 수의 그림과 넓은 셀·빈 행을 사용한다. 출력 시트의 여백만 늘려 원본의 몸 축소나 잘림을 숨기지 않는다. 부분 보정은 해당 칸만 재검수하고 선택한다. [진괄 공격 보정](jingwal-attack-v2.md)에 이 규칙을 적용했다.

## 내보내기와 검수

- 같은 인물에는 공통 배율·좌표계를 적용한다. 개별 프레임 외곽에 맞춘 `fit`/`contain` 리사이즈를 금지하고 빈 부분은 투명 공간으로 남긴다.
- 프레임 경계, 인물·방향·동작 ID, 접지점, 몸 중심, 손·무기 연결점, 배율과 생성 출처를 manifest에 기록한다. 같은 행이나 무기라는 이유로 타인의 그림을 섞지 않는다.
- 머리·어깨·몸통 등 최소 두 몸 기준을 비교한다. 같은 방향의 머리 크기 차이 ±5%는 초기 검수 후보 기준으로 삼고 회전·원근 단축은 사람이 판정한다. 전체 그림 높이만으로 승인하지 않는다.
- 경계 접촉·잘림·다른 프레임 혼입·접지점 점프를 검사한다. 명시된 프레임 경계를 우선하고 투명도만으로 격자를 추측하는 것은 보조 검사로 둔다.
- 생성 PNG → 전달 시트 → 실제 게임을 같은 몸 배율로 나란히 본다. 걷기→준비→타격→회수와 방향 전환을 재생하고 무기 위치·HP바도 확인한다.
- 투명도는 PNG의 알파 채널과 밝은 배경·어두운 배경의 실제 합성 결과를 함께 확인한다. 투명 픽셀에 남은 RGB와 실제 반투명 후광을 구분한다. 알파가 남은 후광 수정본은 제외하고 배경을 제거한 선택본만 내보낸다. 봉 승려 뒤 대각선 공격의 `attempts/rear-right-combat-alpha-haze.png`는 제외본이며 `rear-right-combat.png`가 적용본이다.
- 잘못된 원화를 런타임 배율로 승인 처리하지 않는다. 원본이 정상인 셀은 내보내기만 수정하고, 원본의 인체 비율·자세가 다른 셀만 재생성한다.

긴 무기에 의한 축소가 두드러진 소림 봉 승려 한 인물로 먼저 검증한 뒤, 같은 시스템의 모든 적·보스로 확장한다. 기존 원본은 보존하고 새 버전·명시적인 적용 경로를 사용한다.
