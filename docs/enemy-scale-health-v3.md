# 적 크기·HP바 공통 수정 · 2026-10-04

추가 조사: [적 원화·내보내기·렌더 배율 현황](enemy-art-status-v1.md)에서 전달 시트의 칸별 리사이즈가 무기 폭에 따라 몸까지 축소하는 별도 원인을 확인했다. 아래 수정은 런타임 계산과 HP바 문제를 다루며 원화/전달 파일의 전체 크기 통일성을 보증하지 않는다.

같은 적이 방향을 바꾸거나 공격을 시작할 때 크기가 달라지는 원인은 배율 **기준의 혼용**이었다. 소림은 걷기에 서 있는 키, 공격·정지에 두피 너비를 사용했다. 공격의 목표 머리 크기를 현재 방향의 보행 그림에서 다시 구했기 때문에 방향 전환도 목표 크기를 바꿨다. 다른 적도 현재 방향을 기준으로 삼는 공통 경로를 사용했다. HP바는 이 크기 계산과 별도로 발 위치에서 고정 높이 `82 × rankScale`에 표시해, 큰 준비·타격 그림이 바를 뚫었다.

## 적용

- 모든 적은 같은 캐릭터의 앞 방향 그림 하나를 영구 크기 기준으로 사용한다. 일반 적·40보스·정체성 교체·역할 전용·기마병이 같은 계산을 따른다. 보스의 의도된 1.4배, 기마병의 기준 높이 125는 유지한다.
- 두피 실측값이 있는 소림 원화는 걷기 두 프레임·준비·타격·회수·피격·사망에 같은 두피 기준을 적용한다. 기준이 있는 가족에서 실측값이 빠지면 다른 단위로 조용히 바꾸지 않고 오류로 탐지한다.
- 머리카락·모자 등 다른 원화에는 기존 수작업 추정 보정값을 유지하면서 **목표 크기**를 방향과 무관하게 고정한다. 이 원화들의 모든 머리 윤곽을 새로 실측했다는 뜻은 아니다.
- HP바는 해당 적의 모든 살아 있는 원화의 위쪽 경계를 기준으로 공간을 확보한다. 사망 그림은 이 계산에서 제외한다. 실제 메시의 움직임으로 경계가 더 올라갈 때도 바의 아래쪽과 메시 사이에 최소 7 월드 단위 간격을 둔다. 보스·정예 표식도 바 위에 배치한다.
- 원본 비율은 유지한다. 그림 전체 높이를 같게 강제해 무기·벌린 팔·숙인 자세까지 늘리는 방식은 사용하지 않는다. 원본 100%는 서로 다른 시트의 원화 크기 차이를 그대로 노출하므로 해결책이 아니다. 이미지 생성·픽셀 편집은 없었다.

## 검사와 시각 검토

자동 검사:

- 단위 검사 48파일·1,232개 및 프로덕션 빌드 통과.
- 10지역 × 일반 역할 3종·보스 4종 × 8방향 × 10상태 × Canvas/WebGL = **11,200 표본**. 정지·보행 두 프레임·준비·타격·회수·움직이는 회수 두 프레임·피격·사망을 포함한다. 실제 렌더러의 배율·메시 경계·HP바 간격을 기록했다.
- 두피 원본 픽셀 실측과 비교한 소림 표본은 1,120개다. 나머지는 기존 보정값과 렌더 크기의 일관성 검사다. 독립적인 실측 검증과 보정값 일치 검사를 구분한다.
- 소림의 기존 보행·연속 전환 검사도 수정한 기준으로 통과했다. 기존 보행 검사처럼 몸 전체 높이만 맞추면 머리 크기 차이를 놓칠 수 있다.
- 실제 키보드 이동·마우스 공격·방어 입력은 1440×900, 1366×768, 1093×614에서 진행했다. 접근·준비·타격·회수 중 HP바 간격을 계속 수집했다. 독립 브라우저 저장만 사용했다.

직접 본 화면:

- 10지역 전체의 걷기·준비·타격, 옆·앞·뒤 비교판과 소림의 Canvas/WebGL 비교판을 검토했다. 모든 11,200표본을 사람이 각각 눈으로 확인한 것은 아니다.
- 소림의 같은 캐릭터가 원화 자세 때문에 폭을 넓히거나 몸을 숙이는 것은 자연스러운 차이로 남긴다. 공격 때 머리 자체가 확대되는 배율 전환은 제거했다.
- 소림 실전 화면의 세 해상도에서 자신의 HP바와 캐릭터가 분리되는 것을 확인했다. 밀집한 다른 적의 몸이나 HP바끼리 겹치는 것은 이번 자신의 몸/HP바 배치 검사와 다른 문제다.

## 배포·남은 별도 현상

로컬 `http://127.0.0.1:5173/`에만 반영한다. 사용자 저장·적 판정·전투 수치·보스 패턴에는 변경이 없다.

일부 정체성 교체 원화의 WebGL 메시 조각 현상은 남아 있다. [현재 WebGL 비교](verification/enemy-scale-health-v3/webgl-R4-comparison.png)의 노란 수도승·노승 뒤 공격에 보이며, 이번 크기와 HP바 수정으로 해결되었다고 주장하지 않는다.
