# 표준 무인 협동 레이드

2026-10-23. `/raid/`에서 같은 온라인 계정으로 1~4명이 같은 보스를 상대한다. 로비의 레이드 링크와 비무장/다음 단계 화면에서 진입한다. 기존 온라인 무인 육성·소유 장비 기반은 아직 없으므로 이번 버전은 **표준 출전**이다. 도전 기록만 서버에 저장하며 개인 무인·아이템·XP·금전·유품을 생성/이전하지 않는다. 이 제한을 출전 전과 규칙에 표시한다. 오프라인 여정/무인/HP/장비/수명·IndexedDB를 읽거나 쓰지 않는다.

## 파티와 진행

- 비무와 같은 온라인 계정·표준4무인/8무공을 사용한다. 방 코드는6자, 최대4명, 혼자도 출발할 수 있다. 봇을 파티에 채우지 않는다.
- 참가자 모두 그림 준비·대전 준비 후 방장이 첫 출발을 선택한다. 도중 새 참가자는 받지 않는다. 같은 계정은 비무 대기/대전과 레이드를 동시에 진행할 수 없다. 같은 자리 재접속은 이전 소켓을 종료한다.
- 흑풍산채5층: 외곽 경계(베기/돌진), 훈련 마당(부채 사격/지면 표식), 병기고(정면 방어/베기/돌진), 내원(돌진/표식/베기), 본당(네 패턴 조합). 각 층 보스1명이며 추가 잡몹·새 전용 원화는 이번 범위에 넣지 않았다. 죽림의 검토된 방향별 기본 원화를 재사용하고 고정0.225×1.2 배율/발점을 유지한다. HP/피격 중 배율을 바꾸지 않는다.
- 기본 보스 HP1600/1800/2000/2200/2500에 층 시작 생존 인원 N의 `1+0.65×(N−1)`을 적용한다. 전투 도중 사망/연결 해제로 HP를 다시 줄이지 않는다. 피해는 인원으로 높이지 않고 지면 표식을 최대2명에 배치한다. 각 층 제한5분, 시작 대기3초다. 이 수치는 조정 시작값이며 인간 체감 난이도 인증이 아니다.
- 공격 전에1.05초 예고하고 위치/방향을 고정한다. 베기 부채꼴, 실제 발사 방향, 돌진 경로, 실제 원형 표식을 표시한다. 이후 약1.1초 회복을 둔다. 목표는 생존 참가자 사이에서 순환한다. 정면 방어는 방향이 맞을 때만 피해를 줄인다. 반사/아군 공격으로 동료에게 피해를 주지 않는다.
- 아군은 서로 이동·탄을 막지 않고 공격 피해도 없다. 모든 플레이어와 보스는 하나의60Hz 전투 상태에서 판정한다. 같은 틱의 접촉을 모아 처리하며 보스와 마지막 생존자가 동시에 쓰러지면 클리어를 지급하지 않는다. 보스에게 경직/넉백/CC를 추가하지 않았다. 서버가 실제 HP 손실에 따라 유효 피해/받은 피해를 기록한다.

## 정비·귀환·사망

클리어 뒤 생존자의 HP·게이지·회복약 수량을 유지한다. 임시 방어·독·강화 상태/행동과 재사용 시간은 다음 층 시작에 정리한다. 표준 출전마다 제공한 회복약2개는 정비에서만 각각75HP 회복하며, 전투 중에는 사용할 수 없다. 소모품 구매/경제 보상은 없다.

층 사이에는 개인 귀환 또는 다음 층 준비를 선택한다. 귀환/이탈로 구성이 바뀌면 `revision`을 올려 남은 전원 준비를 취소한다. 새 인원과 다음 난이도를 확인한 뒤 전원이 다시 준비해야 출발한다. 정비 제한 시간으로 자동 출발하지 않는다. **다음 층 카운트다운 중에도 준비 취소/귀환이 가능**하며, 이 경우 정비로 돌아와 새 구성으로 다시 시작한다. 이미 전투가 시작된 후의 요청은 허용하지 않는다.

쓰러진 참가자는 이번 도전에서 부활하지 않고 관전/기록 확인 후 나갈 수 있다. 전투 중 명시적으로 포기하면 해당 도전의 무인은 쓰러짐으로 처리한다. 실제 로컬 무인 사망은 아니다. 전멸·시간 초과·5층 완료는 서버 결과를 저장하고 다음 출전에 재사용하지 않는다. 같은 경기/계정의 결과는 재접속/재시도로 중복 저장하지 않는다.

## 연결과 저장

입력은30Hz, 상태는20Hz이며 입력200ms 누락은 중립이다. 순번·세대·파티 revision·소유 자리·유효 단계·액션 필드를 검증한다. 클라이언트의 피해/승리/스탯 요청은 거절한다. 자기 이동만 예측하며 HP/진행/정산은 서버 소유다. 설명·확인창·창 이탈은 해당 입력만 중립으로 만들고 전투는 계속된다.

연결이 끊겨도 자리를90초 보존하고 캐릭터는 전장에 남는다. 전투 중 유예가 끝나도 안전 추출하지 않는다. 층을 살아서 끝냈을 때 정비에서 귀환 처리하고 남은 준비를 다시 받는다. 전원이 끊긴 채 유예가 끝나면 도전을 종료한다. 준비 단계의 빈 방은 정리한다. 서버 재시작은 방을 복구하지 않으며 미완료 기록을 무효로 남기고 마지막 저장된 클리어 층을 보존한다. 완료 영수증은 유지한다.

기존 Node 서버의 `/api/pvp/raid-socket`과 계정 인증을 사용하고 `/api/pvp/raids`는 로그인한 자기 기록20개만 반환한다. 별도 외부 포트를 열지 않는다. SQLite 스키마2는 기존 계정/비무 표를 보존하고 `raid_results`만 추가한다. 최초 출발·체크포인트·개인 결과를 저장하며 실패 시 저장 대기/재시도한다. Elo·비무 승패를 바꾸지 않는다. 최종 결과/귀환에는 저장 확인을 표시한다.

한 DB/서버 인스턴스 원칙·Origin/세션·입력 제한과 프록시는 [비무 기반](realtime-biwu-v1.md)을 따른다. 실행 명령도 `npm run pvp:build`, `npm run pvp:start`, 다른 터미널의 `npm run dev`다. Docker의 기존pvp 서비스/명명 볼륨에서 함께 실행한다. [서버 설치·DB 주의](self-hosting.md).

## 검증과 후속

[이번 검증](verification/cooperative-raid-v1/README.md)에 전체·협동·비무/로비 회귀와 정상 규칙 관측을 구분한다. 전환 UI 검사에 첫 보스 HP만40으로 낮춘 독립 fixture를 썼으며, 기본 수치 서버의 실제 피해/예고와 기본 수치 시뮬레이션도 별도로 실행했다. fixture는 서버 코드 주입 지점이며 공개 API/운영 환경 변수로 활성화하지 않는다.

개인 소유 무인의 온라인 육성·성장 선택·장비/가방·개인 전리품·유품 회수/반환·실제 수명/영구 사망, 새 산채/보스 원화, 잡몹/추가 기믹·매칭·관전 카메라, 장시간 사람 대상 밸런스·지연/손실·동시 부하는 후속이다. 기존 개인 자산 레이드 설계 전체가 구현됐다는 뜻은 아니다. 원본/이전 원화는 삭제하지 않았으며 Docker 최신 이미지/공개 집 서버 배포도 별도다.
