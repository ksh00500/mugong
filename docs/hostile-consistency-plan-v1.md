# 적 원화·동작·성장 화면 수정 계획 · 2026-10-04

사용자가 제공한 다섯 이미지의 문제를 공유 시스템 전체에서 해결하기 위한 초기 계획이다. 아래 조사 내용은 수정 전 상태다. 이후 구현과 최종 검증 범위는 [적 외형·동작 정합성 v3](hostile-consistency-v3.md)에 기록한다.

## 범위와 공통 기반

일반 적 원화 30종, 보스 40종, 별도의 역할/기마/기관 원화를 포함한다. 역할에 따라 같은 원화를 재사용하는 경우도 전부 매핑한다. 실제 명부는 `src/platform/region-art.ts`, `assets.ts`, `character-identities.json`, `src/domain/region-enemies.ts`, `campaign.ts`와 로딩된 프레임에서 생성한다. 공유 크기/피격 경로의 회귀 대상에는 주인공 10종과 기존 외형도 포함한다.

각 실제 외형 ID를 기준으로 방향 그림·동작 그림·투척 도구·무기·기준 크기·발 위치를 한 명부에 연결한다. 파일명/행 번호가 맞거나 기존 승인 표시가 있다는 이유만으로 동일 캐릭터라고 판정하지 않는다. 모든 원화를 앞/옆/뒤 및 걷기/준비/접촉/회수/피격/사망으로 펼친 비교판을 만든다. 자동 수치 검사와 육안/연속 재생 검토를 분리한다.

## 1. 앞뒤 밝기와 색 차이

확인한 사실: 방향 그림은 `public/art/direction-v2`, 동작 그림은 `public/art/animation-rebuild-v2` 및 역할 전용 시트 등 여러 출처를 사용한다. 런타임에는 피격·광폭·방어에 따른 tint도 있다. 색 차이가 원화 때문인지 상태 tint 때문인지는 캐릭터별 추가 대조가 필요하다.

작업: 같은 캐릭터의 기준 원화와 복장/피부/머리/무기의 팔레트를 지정한다. 흰 tint에서 출처별 차이를 먼저 확인한 뒤 실제 상태를 대조한다. 의도한 피격/강화 표현과 재료 명암을 보존한다. 원화의 색이나 복장이 다르면 기준 캐릭터를 참조해 보정/재제작하고 새 버전 경로로 등록한다. 서로 다른 색을 일괄 평균내는 방식으로 캐릭터 고유 색을 없애지 않는다.

완료 조건: 모든 외형의 원화 비교판과 실제 방향 전환 영상에서 복장·머리·무기 팔레트가 유지되고, 상태 tint 종료 후 기본색으로 돌아온다.

## 2. 위쪽 공격이 보이지 않음

확인한 사실: `src/game/hostile-pose.ts`의 `direction >= 5` 조기 반환으로 뒤쪽 3방향에서 동작 그림을 사용하지 않는다. 해당 방향은 방향 그림과 `hostile-motion.ts` 리그에 의존한다. 따라서 공격 원화의 방향별 지원 자체가 비대칭이다. 사막 환 투척수만의 문제로 제한하지 않는다.

작업: 모든 역할/보스의 8방향에서 준비→접촉/발사→회수의 가시적인 동작을 구성한다. 실제 조준 고정, 근접 접촉/투사체 생성 시계와 맞춘다. 뒤쪽 팔/도구/몸통이 보이는 동작 원화가 필요하면 기준 외형을 참조해 추가한다. 정면 공격 그림을 뒤쪽에 그대로 붙여 방향이 뒤집히게 하지 않는다. 기마병·환 투척수·활·독병·빙옥·기관 등은 도구별로 대조한다.

완료 조건: 8방향 모두 준비와 접촉이 구별되고, 실제 발사/타격 시점과 일치한다. 방향 원화 유지 여부만 확인하는 기존 검사를 동작 가시성 검사와 연속 재생으로 보강한다.

## 3. 성장 화면 버튼과 후보 수

확인한 사실: 이미지 2의 흰 버튼은 `수련 기회 보관`이다. 성장 화면은 밝은 글자색을 상속하지만 이 버튼에 별도 글자색을 지정하지 않는다(`src/ui/Choices.tsx`, `src/ui/growth.css`). 실제 computed style과 enabled/disabled 색을 검증한다.

후보 수: 이미지의 수련은 2점이고 표시 후보는 2성→3성이므로 각각 비용 2점이다. 코드의 `eligibleOffers`는 만렙 외에도 수련 비용, 새 무공 보유 한도, 호환 무장/수납 조건으로 후보를 제외한다. 나머지 무공의 성급과 보유/수납 상태는 이미지에 없으므로 당시 후보 2개가 오류였다고 확정할 수 없다. 앞선 재현 검사도 사용자의 실제 당시 저장을 읽은 것은 아니다.

작업: 후보 원본에서 각 제외 사유와 남은 후보 수를 추적해 충분한 후보가 있는데 사라지는지 조사한다. 전투/로비, 웨이브 보상/연속 수련/저장 재개를 포함한다. 후보가 3개 미만일 때 현재 수련과 선택 가능한 수를 알리고 부족한 이유를 설명한다. 새로운 후보를 채우기 위해 기존 비용/성급/보유 한도를 몰래 변경하지 않는다. 버튼 스타일은 소유 파일 `growth.css`에서 수정하고 성장 화면의 다른 보조 버튼도 검사한다.

완료 조건: 버튼이 활성/비활성/초점 상태에서 읽히고, 실제 유효 후보 수와 표시 수가 일치한다. 1·2·3개 및 후보 없음, 다섯 언어, 1366×768·1440×900·1093×614에서 핵심 행동을 확인한다.

## 4. 큰 피격 그림과 공격이 가려짐

확인한 사실: `CombatScene.drawEnemy`와 `hostileDrawingPose`는 최근 0.2초 피격을 준비/타격보다 우선한다. 연속 피해가 계속 들어오면 공격 그림이 반복해서 대체될 가능성이 있다. 현재 `matchedPoseHeight`와 `silhouetteUnit`은 얼굴이 아닌 불투명 실루엣 면적을 사용한다. 무기·망토·자세에 따라 몸체 크기와 면적이 다르게 변할 수 있다.

작업: 공통 크기를 머리/몸통 등 검토된 해부학적 기준점으로 보정하고 무기/장식/이펙트를 기준 측정에서 분리한다. 원화 교체, 메시 변형, 피격 반동의 중복 확대도 점검한다. 단순 피격 피드백은 공격을 유지하는 짧은 색/반동 합성으로 처리하고, 실제 전투 경직/중단만 피격 자세로 전환한다. 사망은 최우선이다. 피해 이벤트 빈도가 준비/접촉 그림을 무한히 덮지 않게 한다. 표현을 바꾸려고 실제 피해/경직/공격 판정을 임의로 변경하지 않는다.

완료 조건: 보행/공격/피격/사망에서 같은 캐릭터의 신체 비율과 지면 기준이 유지된다. 단타·연타·중독 지속 피해·반사·공격 중 피격·진짜 경직·사망을 구분해 검사한다. 같은 경로를 쓰는 일반 적/보스/주인공에 적용한다.

## 5. 보행과 공격의 외형 불일치

확인한 사실: 일부 방향/상태에서 출처가 다른 방향 시트와 동작 시트를 바꿔 사용한다. 이미지 4·5의 스님에게 복장/색/체형 차이가 보이지만 파일 손상인지 다른 디자인 원화가 연결된 것인지는 원본 대조 전 미확정이다. 크기 수치만 맞춰도 복장/얼굴이 다른 문제는 해결되지 않는다.

작업: 모든 외형의 얼굴·머리·복장·무기·장식 동일성을 검토한다. 잘못된 행/프레임/역할 매핑이면 연결을 고치고, 원화 자체가 다른 사람이면 기준 캐릭터를 참조해 재제작한다. 프레임 분리/알파 경계/인접 칸 유입/중복 프레임도 검사한다. 승인 명부에는 실제 비교 근거와 버전을 기록한다. 외형별로 사용 파일과 동작을 명시해 여러 시트를 암묵적인 행 번호로 연결하지 않도록 한다.

완료 조건: 보행→준비→접촉→회수→피격→사망의 연속 재생에서 동일 인물과 도구를 유지한다. 이전 자동 승인 목록과 별도로 새 비교판을 육안 검토한다.

## 실행 순서와 배포 기준

1. 전 캐릭터 명부/원화 비교판, 현재 오류의 재현 영상 및 후보 제외 사유를 확보한다.
2. 공통 피격 우선순위·몸체 기준 크기·방향별 동작 선택을 수정하고, 성장 보조 버튼/후보 안내를 병행한다.
3. 같은 명부를 기준으로 팔레트/외형 불일치와 누락된 뒤쪽 동작 원화를 보정·재제작한다. 그림 제작에는 내장 imagegen을 사용하고 원본/프롬프트와 버전 경로를 보존한다.
4. 각 캐릭터의 8방향·모든 동작/전환을 Canvas/WebGL, 일반/감소된 동작 설정에서 검사한다. 원화 검토는 접촉판, 동작 검토는 실제 연속 영상으로 수행한다. 주인공 무기 부착 회귀 검사도 유지한다.
5. 빌드·관련 규칙/저장 검사, 화면/키보드 조작, 그림과 영상 검토가 통과한 뒤 Daytona 새 릴리스에 배포한다. 공개 파일 해시·실제 공격·저장 재개를 확인한다. 사용자 저장은 유지하고 테스트 데이터는 독립 브라우저 컨텍스트에서만 사용한다.

이전의 유한 좌표/메시 검사 통과를 원화 동일성이나 애니메이션 자연스러움의 완료 증거로 사용하지 않는다. 실제 결함 목록이 해소된 외형만 완료로 표시한다.
