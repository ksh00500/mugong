# 무공 후보 수 조사 · 2026-10-04

사용자가 확인한 화면은 성장 특성이 아니라 무공 선택/성급 업그레이드다. 현재 코드의 후보 조건으로 1개와 2개를 재현했다. 카드 누락이나 중복 난수 추첨 문제는 이번 재현에서 확인되지 않았다. 게임 규칙과 실행 코드는 변경하지 않았다.

## 코드에서 확인한 원인

`src/domain/game.ts`의 `eligibleOffers`는 배운 무공이 최대 성급 미만이며 현재 수련으로 비용을 낼 수 있을 때만 업그레이드를 제시한다. 업그레이드 비용은 현재 성급이다. 새로운 무공은 보유 4개 미만이고 수련 1점 및 호환 무장/수납 조건이 충족될 때만 제시한다. `rollOffers`와 로비 `trainFamily`는 이 후보를 섞은 뒤 최대 3개를 제시한다. 유효 후보가 1개나 2개이면 그 수 그대로다.

- 네 무공 중 두 개가 최대 성급이고 두 개만 성장 가능하면 후보 2개다. 하나만 성장 가능하면 1개다.
- 모든 무공에 성장 여지가 있어도 수련이 부족하면 비용을 낼 수 없는 후보는 제외한다. 수련 1점에서는 1성→2성만 가능하며 4성→5성에는 4점이 필요하다.
- 일반 무공 상한은 5성, 삼재 상한은 10성이다. 원본은 `src/domain/content.ts`다.
- `src/ui/Choices.tsx`는 저장된 후보 배열을 그대로 렌더링한다. 760px 이하 너비 또는 480px 이하 높이에서는 한 장씩 보여주고 후보 페이지로 이동한다. 이는 후보 총수를 줄이는 동작은 아니다.
- 별도의 Lv.10/25/50 성장 특성은 8개 중 미보유 후보를 3개 제시한다. `src/domain/character.ts`, `src/platform/save-validation.ts`에서도 비어 있거나 고유한 3개만 허용한다. 이번 사용자 확인 대상은 이 화면이 아니다.

## 검증

- 단위 검사 28개 통과(기존 성장 검사 20개와 새 후보 수 검사 8개): 전투/로비 1·2·3개 후보, 비용 부족 제외, 중복 없음, 저장 복원 및 실제 비용 차감.
- 브라우저 검사 2개 통과: 독립 저장 컨텍스트의 1093×614 화면에서 후보 1·2개의 수가 저장 배열과 일치하고 모두 화면 안에 보이는지 확인했다. 새로고침 후 동일 후보와 선택 완료를 확인했다. JavaScript 예외 없음.
- 추가 검사 코드의 TypeScript 검사 통과. 실행 코드/에셋 변경이 없어 새 배포는 수행하지 않았다.
- 자동 검사와 별도로 아래 두 캡처를 육안 검토했다. 실제 사용자의 당시 저장 상태를 읽은 것은 아니므로 그 판의 무공 성급과 수련 수치는 미확정이다.
