# 강호 밸런스 v2

2026-10-02. 사용자 요청에 따라 장비 정수 반올림과 빠른 보스 처치를 함께 조정했다. 기준 수치는 `src/domain/balance.ts`; 자동 검사와 인간 플레이 평가는 구분한다.

## 장비 수치

전체 단위 10배 확대 대신 장비 공격·피해 감소·이동 보너스 원값을 소수점 한 자리로 저장하고 계산한다. 단위 확대만으로는 피해/체력 비율이나 처치 시간이 변하지 않으므로 난이도는 별도 조정했다. 예: 기본 도포 품질70/90은 기존 1/1에서 0.7/0.9, 기본 공격6 무기의 품질70/90은 4.2/5.4. 등급별 기본값과 품질을 함께 적용한다. 품질 1 차이가 모든 작은 스탯에 반드시 차이를 만드는 규칙은 아니다.

도포/신발 보스 보상은 단계별 기본값 2.6/3.2/3.8/4.4로 구분했다. 공격·비교 숫자는 한 자리로 표시하고 강화 +1은 그대로 보존하면서 부동소수점 꼬리를 반올림한다. 소비약/경험치/화폐/드랍 수량은 단위를 바꾸지 않는다.

`src/platform/save-migrations.ts`는 유효 저장에 있는 알려진 옛 장비의 반올림만 보정한다. 강화 횟수와 기존 정수 계산이 일치할 때만 적용하며, 품질120 상한으로 강화 전 품질을 특정할 수 없는 경우와 사용자 정의 수치는 보존한다. 선택 필드 `Item.statRevision=1`로 반복 적용을 막는다. 원본/HP/사망/진행/자산 ID는 바꾸지 않는다. 이미 전투 중인 적 HP를 재설정하거나 회복시키지 않으며 강화된 HP는 다음 소환부터 적용한다.

공격·이동 범위, 마지막 조준 고정, 회피 무적 시간은 유지한다. 기믹 전용 피해·지속 장판·상태 누적을 전체 공격 배율로 중복 증폭하지 않는다. 고유 패턴 순서는 유지하고 기본 공격 사이의 빈틈을 줄여 더 자주 쓰게 했다. XP/레벨 후보/약 공급을 줄이는 추가 압박은 넣지 않았다.

## 검증

`tests/balance.test.ts`는 작은 품질 차이, 보스 장비 차이, 강화 정밀도, 기존 저장의 일회성 보정/원본 보존, 성장한 화산 궁극과 후속 공격을 실제 tick으로 적용했을 때 네 단계 보스의 생존을 검사한다. `tests/campaign.test.ts`의 고정 행동 봇은 기존 승리 강제 조건을 승리 또는 사망 정산까지 진행되는지 검사하도록 바꿨다. 이번 수치에서 마지막 보스 사망 사례가 생겼으며 봇의 실패를 실제 사람의 승률로 해석하지 않는다. 승리·귀환·자산 정산은 별도 기존 회귀 검사에서도 확인한다.

최종 TypeScript/Vite 빌드와 단위27파일472개, 브라우저41개 모두 통과. 브라우저 검사는 장비 비교·착용·저장 재개·보스 그림/상태·정비 흐름을 독립 컨텍스트에서 확인했다. 소수점 비교 캡처: `docs/verification/balance-v2/decimal-comparison.png`. 5언어/3기준 화면과 추가 작은 화면의 비교·착용 흐름을 검사했으며 해당 소수점 캡처를 직접 시각 검토했다.

이번 값은 강한 1차 조정이다. 장시간 40보스·8무공 조합, 장비 품질과 기술 숙련도에 따른 실제 처치 시간·피격 횟수·초보 사망률은 후속 인간 플레이로 조정해야 한다. 공개 서버 배포는 이번 작업에 포함하지 않는다.
