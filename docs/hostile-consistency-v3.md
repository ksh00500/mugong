# 적 외형·동작 정합성 v3

2026-10-04. [사용자 승인 계획](hostile-consistency-plan-v1.md)의 다섯 문제를 공통 렌더링과 성장 화면에서 수정한다. 배포와 최종 검사 결과는 아래 검증 기록을 따른다.

## 적용 내용

10지역의 70개 원화 행(일반 30·보스 40), 전용 역할 4행, 기병과 교체 인물 3행을 앞/옆/뒤·준비/접촉/피격/사망 비교판으로 대조했다. 같은 인물의 머리·복장·도구 팔레트를 참조해 방향 원화 13장과 뒤쪽 동작 원화 13장을 새 버전으로 연결한다. 독병 후드와 왕조 봉 보스 등 다른 인물처럼 보이던 동작은 1·9지역 동작 시트도 교체한다. 원본과 정확한 생성 프롬프트는 `docs/source/hostile-consistency-v3/`, 전달 WebP는 `public/art/hostile-consistency-v3/`, 파일 해시와 조립 출처는 `production.json`에 둔다. 내장 imagegen으로 제작했으며, 후처리는 무손실 변환·연결 성분 분리·격자 재배치다.

뒤쪽 3방향에서 공격 그림을 건너뛰던 정책을 제거했다. 뒤 대각선/정후면마다 준비·접촉을 구별하고 NW는 승인된 뒤 대각선의 좌우 반전으로 처리한다. 현재 뒤쪽 시트는 4열: 뒤 대각선 준비·접촉, 정후면 준비·접촉이다. 뒤쪽 회수/보행/경직은 같은 방향 그림의 리그를 사용한다. 근접 보스는 실제 `strike.duration`과 각 `melee.contacts` 시간에 접촉 자세를 맞춘다. 준비·접촉을 변경하려고 전투 피해 시계를 바꾸지 않는다. `hostile-pose.ts`, `CombatScene.ts` 참고.

실루엣 면적으로 크기를 맞추면 넓은 망토·긴 봉·수평 사망 자세 때문에 몸이 커지거나 작아진다. 45개 시트에 프레임별 두개골 크기 추정 기준을 기록하고 같은 렌더링 경로의 적·보스·기병·주인공 10종 및 기존 외형에 적용한다. 무기와 머리 장식은 기준에 포함하지 않는다. 이미지 치수가 바뀌면 보정값 재사용을 거부한다. `anatomical-landmarks.json`, `anatomical-calibration.ts`, `enemy-motion.ts`, `character-sheet.ts`, `cavalry.ts` 참고. 이 값은 비교판에서 수동 검토한 추정치이며 자동으로 측정한 정확한 해부학 좌표가 아니다.

단순 피해는 짧은 색/반동으로 합성하고, 실제 경직에서만 피격 원화를 사용한다. 타격 상태는 피해 원화가 덮지 않으며 사망은 우선한다. 주인공도 공격·방어 중 단순 피격 원화가 이를 덮지 않는다. 공격 중단 여부는 실제 전투 상태가 결정한다. 기존 공격·피해·경직 수치를 변경하지 않았다.

성장 `수련 기회 보관` 버튼에 활성/비활성 글자색과 배경을 명시했다. 유효 후보가 3개보다 적으면 선택 가능 수와 제외 사유(비용·보유 한도·무장 공간·만렙)를 펼쳐 볼 수 있다. 예를 들어 보유 성급이 2·3·2·4이고 수련이 2점이면 만렙이 없어도 2성 무공 두 개만 업그레이드 가능하다. 충분한 유효 후보를 임의로 누락시키는 현상은 이번 재현에서 확인되지 않았다. 사용자의 당시 저장을 읽은 것은 아니므로 원래 스크린샷의 정확한 원인을 확정하지 않는다. `offerAvailability`와 `Choices.tsx`, `src/ui/growth.css`, `training-messages.ts` 참고.

## 에셋 관리 규칙

- 인물 ID·실제 역할·소스 행·도구를 명시한다. 같은 행 번호나 무기 종류만으로 인물 동일성을 승인하지 않는다. 세 교체 인물은 방향/전면 동작/뒤쪽 동작을 모두 전용 행으로 연결한다.
- 새 파일은 새 버전 경로로 보존한다. 원본·프롬프트·전달 해시·수정 행·크기 기준을 같이 기록한다. 칸 가장자리 무기 잘림이나 인접 성분 유입은 확대해서 검토한다.
- 방향 열의 요청 이름을 믿고 반전하지 않는다. 실제 후면 대각선 시선 방향을 검토해 `enemyDirectionFlip`과 교체 인물 반전을 정한다.
- 크기 수치가 유한하거나 기준값으로 정규화됐다는 사실은 자연스러운 자세의 증거가 아니다. 같은 얼굴·복장·도구, 정상적인 몸통 길이·발 위치·무기 접촉을 원화와 실제 표시에서 따로 확인한다.
- 연속 재생에서 과도하게 눕는 공격 때문에 몸이 사라지는 그림은 배율만으로 고치지 않고 선 자세의 접촉 원화로 다시 제작한다.
- Canvas/WebGL·감소된 동작 설정을 고려한다. 상태 표현을 바꿔도 실제 피해, 공격 접촉, 이동 판정, 사용자 저장을 임의로 변경하지 않는다.

## 검증 기록

자동 검사와 직접 시각 검토를 분리한다. 테스트 데이터는 독립 Playwright 컨텍스트에만 넣었다. 실제 사용자 저장은 변경하지 않았다.

- 전체 단위 검사: 43파일 1,168개 통과. 모든 보스 근접 패턴의 실제 접촉 시계와 8방향 공격 중 피격 우선순위를 포함한다.
- 성장 화면: 1·2·3 후보, 만렙 없이 수련 비용으로 2후보, 한국어·영어·일본어·중국어 간체/번체 및 1366×768·1440×900·1093×614. 선택·키보드·보관·저장 후 재개 검사 4개 통과. `docs/verification/hostile-consistency-v3/training-*.png`.
- 전 지역 역할·보스 8방향 동작 경로 10개와 실제 배율 비교판 10개 통과. `hostile-action-poses.spec.ts`, `animation-calibration.spec.ts`. 크기 기준 일치 검사는 수동 추정값을 기준으로 한 수치 회귀 검사다.
- 지역 소스 비교판은 70행×15열=1,050개 그림을 담는다. `region-*-sources.png`는 원본 크롭이므로 주변의 분리된 조각이 보일 수 있다. 실제 렌더링은 연결 성분 분리 후의 `calibrated/` 비교판과 전투 캡처를 기준으로 검토한다.
- 연속 재생: 3·4·7·9지역의 일반 역할과 보스, 앞/뒤 대각선 3방향에서 준비·타격·회수·피격·사망을 Canvas/WebGL로 재생한 8개 영상. 승려 후면 접촉 그림을 선 자세로 재제작한 뒤 4지역 배율·8방향·양 렌더러 4검사를 다시 통과했다. `docs/verification/hostile-consistency-v3/motion/`. 이는 상태를 지정한 모션 재생이며 모든 AI 전투 상황을 재현한 영상은 아니다.
- 무기 부착: 플레이어 10외형·무장 이미지 28종의 방향·프레임 회귀 검사를 Canvas/WebGL에서 통과했다. 감소된 동작 설정도 포함한다. 기하학 검사와 대표 화면 검토를 구분하며, 모든 무기 프레임의 자연스러움을 자동 판정한 것은 아니다. `weapon-attachment.spec.ts`.
- 후면 원화 조립: 312프레임의 소스 칸 가장자리 접촉 0건. 잘림·옆 행 인물 혼입을 고친 9개 행의 별도 원본과 프롬프트를 출처 기록에 남겼다. `rear-export.json`, `docs/source/hostile-consistency-v3/production.json`.
- 최종 TypeScript/Vite 빌드 성공. Daytona `20261004-hostile-consistency-v3` 활성화 후 전체 346파일 SHA-256 검증, 공개 URL의 변경 35파일 해시 검증 통과. 기존 릴리스는 보존했다. `docs/verification/daytona-20261004-hostile-consistency-v3/release.json`, `activation.txt`.
- 공개 배포 검사 5개 통과: 변경 파일, 외형 9 암기·7 권갑·3 검의 공격/방어/가방/저장/이어하기/새로고침, 1093×614 성장 화면의 두 후보·제외 사유·수련 보관·재개. 브라우저 실행 오류와 에셋 실패가 없었다. `docs/verification/daytona-20261004-hostile-consistency-v3/public/`. 독립 테스트 저장만 사용했다.

서체 접근성 인증이나 모든 상황의 자연스러움을 자동 검사로 보장하지 않는다. 원화의 세부 장식 단순화와 방향별 재료 명암은 남지만, 이를 서로 다른 인물·무기·공격 크기 오류와 구분해 검토한다.
