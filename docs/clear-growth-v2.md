# 클리어·성장·가방 중첩 입력 수정 — 2026-10-03

성장 창이 먼저 입력 레이어를 등록한 뒤 클리어 저장의 비동기 콜백이 가방을 열면, 가방이 최상위 입력 레이어가 된다. CSS에서는 성장 창이 위에 보이므로 사용자는 보이는 성장 카드를 클릭할 수 없었다.

`src/App.tsx`는 성장 후보가 남아 있을 때 가방을 마운트하지 않는다. `src/platform/store.ts`의 로드·재개·저장 재시도·클리어 자동 열기는 성장 후보가 없을 때만 가방을 연다. 마지막 성장 선택이 저장된 뒤 전리품 가방을 자동으로 연다. 여러 레벨의 후보는 모두 선택할 때까지 성장 창을 유지한다. 기존 사용자 저장은 삭제하거나 수정하지 않는다.

검증: 전체 단위 테스트 31파일 793개 통과(부하로 시간 초과한 동작 검사는 제한된 worker 수로 전체 재검사 통과), 프로덕션 빌드 통과. `tests/store.test.ts`는 저장 후 재로드와 연속 성장→가방을 검증한다. `tests/e2e/clear-growth.spec.ts`는 1440×900·1366×768·1093×614에서 카드 클릭과 가방 입력 및 진행, 20웨이브 귀환을 검증했다. 추가로 성장 창이 먼저 열린 뒤 늦은 가방 요청이 도착하는 순서도 최종 웨이브에서 통과했다. 화면은 `docs/verification/clear-growth-v2/`에 보관한다.

Daytona 릴리스 `20261003-clear-growth-v2` 활성화. 서버 266파일 해시 검사와 HTTP 200 응답 확인. 공개 index/main/mount 해시가 로컬 검증 빌드와 일치한다. 인증정보는 기록하지 않는다.
