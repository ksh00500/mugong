# 텍스트와 이미지·전투 로딩 개선

2026-09-29. [UI·UX 전략](ui-ux-strategy-v3.md)에 추가한 개선안과 구현 기록이다. 기존 150% 글자·조작 영역, 가방 규칙, 카메라와 게임 밸런스를 유지한다.

## 개선안과 적용

| 영역    | 문제                                          | 적용                                                                |
| ------- | --------------------------------------------- | ------------------------------------------------------------------- |
| 텍스트  | 긴 이름·다국어 문구의 읽기 순서               | 제목·본문의 줄바꿈과 본문 대비 개선. 글자를 줄여 맞추지 않는다      |
| 숫자    | 자릿수 변화·큰 값 비교                        | 같은 폭 숫자와 언어별 숫자 구분자                                   |
| 무공    | 전체 설명이 주로 호버 도움말에 있다           | 클릭·키보드로 전체 설명을 여는 별도 창                              |
| 수납    | 불가능한 위치의 사유가 모호하다               | 충돌·가방 경계·종류 제한의 구체적 문구                              |
| 첫 실행 | JS 준비 전 빈 화면                            | HTML 시작 안내, 모듈 실패 시 새로고침                               |
| UI 그림 | 배경·메뉴가 각각 나타난다                     | 공통 그림 병렬 요청, 디코딩 완료 후 로비 표시                       |
| 전투    | 엔진 다음 그림의 순차 다운로드, HUD 먼저 표시 | 출전 의도 시 사전 준비, 엔진·그림 병렬 요청, 장면 준비 후 전투 시작 |
| 실패    | 긴 대기·복구 행동 부족                        | 재시도·새로고침·기본 UI, 실제 준비 개수 표시                        |

## 텍스트

본문 21px·보조 설명 18px와 기존 화면별 150% 크기를 유지한다. 제목·이름은 줄바꿈과 긴 단어의 영역 내 분할을 지원한다. 본문은 단어와 문장 묶음을 우선해 읽는다. 물품 상태 안내의 말줄임표를 제거하고, 공간이 좁으면 중복 단축키 안내를 먼저 덜어낸다.

체력·경험치·칸 수·성장 단계·페이지 수치에 같은 폭 숫자를 적용한다. 번역 변수의 숫자는 현재 언어의 `Intl.NumberFormat`으로 표시하며 저장 값과 사용자가 붙인 이름은 변경하지 않는다.

성장 카드의 짧은 특징은 유지하고 `무공 자세히`에서 전체 설명과 방어 동작을 읽는다. 좁은 화면은 후보 페이지 옆에 설명 버튼을 둔다. 설명 창의 읽기 스크롤은 허용하고 닫기는 상단에 유지한다. 배경 선택을 막으며 닫으면 원래 버튼에 초점을 돌린다. 1초 오입력 보호와 네 무공 제한은 유지한다.

드래그에서 충돌·경계·검 전용 가방 제한을 문구로 표시한다. 배치 미리보기와 클릭·키보드 대안은 유지한다. 새 문구는 한국어·영어·일본어·간체·번체를 제공한다.

## 전달 용량

사용하는 PNG 10개의 원본은 보존하고 같은 크기의 무손실 WebP를 만든다. 변환 후 RGBA의 모든 픽셀을 비교했으며 차이가 없었다. 기존 그림 좌표와 비율은 유지한다.

|    원본 PNG 합계 |   전달 WebP 합계 |  감소 |
| ---------------: | ---------------: | ----: |
| 18,742,357 bytes | 13,296,224 bytes | 29.1% |

이는 그림 파일 크기 비교이며 실제 인터넷 로딩 시간이 29.1% 줄었다는 측정이 아니다. 원본을 포함하는 로컬 `dist` 전체 크기 감소도 뜻하지 않는다. 원본 PNG는 로컬과 이전 릴리스에 보존하고 새 배포 압축에는 현재 코드가 쓰는 WebP를 포함한다.

변환: `scripts/optimize-art.py`. [파일별 크기·픽셀 비교](verification/text-loading-v3/asset-sizes.json).

## 로딩 흐름

1. HTML 시작 안내는 기존 언어 설정과 브라우저 언어를 따른다. 시작 모듈 실패에는 새로고침 버튼을 제공한다.
2. 저장 읽기와 UI 그림 요청을 함께 진행한다. 공통 그림 다섯 개를 디코딩한 뒤 로비를 표시한다.
3. 한국어·영어에서 실제 쓰는 본문·제목 폰트 두 개를 미리 요청한다. `font-display: swap`을 유지하고 폰트 대기로 UI 진입을 막지 않는다. 일본어·중국어는 운영체제 서체를 유지한다.
4. 출전 버튼의 호버·키보드 초점과 생성 창 진입에서 전투 자료를 미리 준비한다. 이 단계에서는 렌더러 생성이나 게임 진행을 하지 않는다.
5. 엔진 모듈과 전투 그림을 병렬 요청한다. 성공·진행 중 요청을 공유해 중복 다운로드를 피하고 실패한 그림은 재시도한다.
6. 다운로드·디코딩한 이미지 객체를 Phaser에 전달하여 같은 그림을 다시 요청하지 않는다.
7. 실제 장면 초기화 후 HUD·전투를 보여준다. 그 전에는 시뮬레이션·전투 입력을 막는다. 준비 플래그는 사용자 저장에 기록하지 않는다.

진행 막대는 다운로드 바이트 퍼센트가 아닌 **준비된 그림 수**다. 그림을 모두 받아도 엔진이 준비되지 않았다면 로딩을 유지한다. 5초 이상이면 첫 실행·느린 연결 안내를 표시한다. 그림 요청은 20초, 전투 준비는 25초 상한 후 복구 행동을 제공한다. 이 시간은 목표나 보장 로딩 시간이 아니다.

UI 그림 실패에는 기본 화면으로 계속하여 텍스트 메뉴·창고·설정을 사용할 수 있게 한다. 필수 전투 자료 실패에는 불완전한 전투를 시작하지 않는다. 브라우저가 실패한 모듈을 캐시한 경우 새로고침으로 요청한다. 복구는 저장 초기화나 새 무인 생성으로 처리하지 않는다.

참고: [MDN image.decode](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/decode), [React 리소스 준비 API](https://react.dev/reference/react-dom), 프로젝트의 [UI·UX 가이드](reference/ui-ux-guides.md).

## 검증

TypeScript·Vite 빌드, 단위 검사 32개, 로컬 Playwright 35개, 공개 Daytona Playwright 8개가 통과했다. 로컬 실행에서 공개 배포 전용 검사 하나는 의도적으로 건너뛰고 별도 설정으로 실행했다. 최종 수치와 배포 상태는 [검증 결과](verification/text-loading-v3/result.json)에 기록한다.

- 단위: 준비 전 시뮬레이션 정지·준비 후 이동, 다국어 숫자와 번역 변수, 기존 게임·저장 규칙.
- 브라우저: JS 지연·실패, UI 그림 지연·실패·재시도·기본 화면, 전투 그림 지연·실패·재시도, 모듈 실패·새로고침, 무인 중복 생성 방지, 키보드 설명 열기·닫기.
- 회귀: 필수 3개 해상도 및 좁은 화면, 5개 언어, 가방·창고·폐기, 저장·복원.
- 직접 검토: 실제 로컬·공개 브라우저의 로비와 독립 브라우저의 로딩·복구·무공 설명 캡처를 확인했다. 설정 조작과 언어 전환은 자동 검사 결과다. 실제 사용자 저장에는 검증 데이터를 쓰지 않았다.
- 공개 배포를 별도로 검증했다. 자동 검사와 시각 검토는 실제 새 사용자 플레이테스트·접근성 인증을 뜻하지 않는다.
