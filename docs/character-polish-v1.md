# 캐릭터 표현과 사건별 효과음 — 2026-10-03

## 적용 범위

- 성장 특성 8개를 무공 그림 재사용에서 전용 그림으로 교체했다. 카드와 무인 정보 모두 특성 ID로 매핑한다. `src/ui/CharacterArtwork.tsx`, `AugmentChoices.tsx`, `CharacterProfile.tsx`.
- 모집 후보 초상 3개는 기존 주인공의 흑발·붉은 끈·흰 도포를 유지하고 자세와 표정으로 구분한다. 별개의 전투 모델 3종을 만든 것은 아니다. 선택한 초상 번호를 후보와 무인 저장 데이터에 유지하고 로비 명부와 전투 HUD에 사용한다. 이전 저장은 기존 초상으로 표시한다. `src/platform/character-art.ts`, `src/domain/recruitment.ts`, `src/domain/model.ts`, `src/platform/save-validation.ts`.
- 공통 리그 동작 전환을 55ms smoothstep으로 연결한다. 전투 위치·조준·피해 타이밍은 보간하지 않는다. 타격·피격·사망과 reduced-motion은 즉시 반영한다. `src/game/pose-transition.ts`, `src/game/CombatScene.ts`.
- 기존 효과음에 사건별 합성음 17종을 추가했다. 검·봉·권·부채·암기·활, 기탄, 독·빙결·화염·혈기, 함정·술, 모래벽 붕괴, 봉인, 체력 교환, 수리 드론을 구분한다. 밝고 짧은 게임 효과음을 목표로 만들었으며 녹음 파일을 사용하지 않는다. `src/platform/combat-sounds.ts`, `src/platform/audio.ts`, `src/game/feedback.ts`, `src/domain/boss-mechanics.ts`.
- 투사체 소리는 생성 객체당 한 번만 재생한다. 같은 사건의 중복 소리와 동시 재생 수를 제한한다. 폭발·접촉 피해·궁극기는 실제 전투 이벤트에서 전달한다.

## 에셋 관리

원본 PNG는 `docs/source/character-polish-v1/`, 배포 WebP는 `public/art/character-polish-v1/`에 보관한다. 성장 그림은 4×2 atlas의 순서를 고정하고 ID로 연결한다. 초상은 0/1/2 번호를 저장하므로 이후 다른 인물로 임의 교체하지 않는다. 모두 기존 캐릭터와 같은 의상·색·화풍을 기준으로 생성했다. 런타임은 배포 WebP만 로드한다.

생성 프롬프트는 화면 구조, 대상, 동일성, 투명 배경 조건 중심으로 짧게 작성했다. 전용 성장 그림은 심장/주먹/천신과 바람/내공 구슬/방패/검과 잔상/약사 도구/수비하는 팔을 지정했고, 초상은 기존 주인공 원화를 참조했다. 원본은 보존하고 배포본만 크롭·리사이즈·WebP 변환했다.

## 검증과 한계

`tests/presentation-polish.test.ts`는 초상 저장 검증, 폭발 이벤트, 효과음 샘플의 유한값·크기·고유성, 전환 시간과 즉시 피격을 검사한다. `tests/e2e/presentation-polish.spec.ts`는 모집 선택→전투 HUD→새로고침 유지, 실제 AudioContext 재생, 특성 그림과 reduced-motion을 검사한다. 모집·성장 기존 E2E는 1440×900, 1366×768, 1093×614에서 실행한다. 테스트는 독립 브라우저 저장만 사용한다.

캡처와 효과음 미리듣기는 `docs/verification/character-polish-v1/`에 저장한다. 샘플 생성·브라우저 재생 검사는 청취 품질 검수와 구분한다. 모집과 성장 화면 및 생성 그림은 육안 확인했다.

최종 결과: TypeScript/배포 빌드 통과, 단위 검사 36파일 889개 통과(`npx vitest run --maxWorkers=2`). 브라우저 모집/성장/표현 검사 8개는 작은 화면 간격 수정 후 해당 1개 재검증까지 모두 통과했다. 1093×614에서는 5개 언어의 무인 정보와 하단 보관 영역 겹침을 검사했다. 별도 기존 동작 검사에서 10개 지역의 캐릭터 동일성/크기와 60/120/144Hz 적 이동 상태 검사를 통과했다. 동시에 빌드·브라우저·단위 검사를 실행한 첫 검사에서 긴 단위 검사 3개가 시간 초과되어 동시 작업 수를 제한한 재실행으로 확인했다. 개발 서버 갱신 중 동적 import를 사용하는 브라우저 테스트는 다른 store 인스턴스를 참조할 수 있어 소스 수정 종료 후 새 5181 서버로 검증했다.

모든 캐릭터의 모든 방향을 새 연속 원화로 다시 그린 것은 아니다. 기존 승인 원화 프레임과 공통 리그가 함께 사용되며 이번 작업은 그 전환을 개선했다. 온라인 모드, 최종 밸런스, 구형 출전 명령 정리는 이번 범위에 포함하지 않았다. Daytona 배포본 반영은 별도다.
