# 다음 단계 화면·콘텐츠 제작·개발 완료 기준

2026-09-30. [상위 설계](../next-stage-design.md), [보스·레이드](bosses-raids-v2.md), [PVP](pvp-v2.md), [온라인](online-progression-v2.md)을 실제 작업 단위로 나눈 추천 계획이다. 새 패키지·코드·서버의 구현은 이번 문서 작업에 포함하지 않는다.

## 출전 화면

상단은 현재 로비 메뉴를 유지하고, 등록된 무인을 선택했을 때 출전 영역에 **레이드 / 비무 / 생사결**을 제공한다. 명부가 비어 있으면 새 무인 생성이 주 행동이고 아직 사용할 수 없는 세 모드를 크게 나열하지 않는다. 강호 진행 중이면 강호 이어하기가 우선이다.

모드를 선택해도 전체 설명 문서를 펼치지 않는다. 이름·목적·보상·위험 한 줄, 선택 무인의 HP·수명·빌드 요약, 준비/매칭 행동을 한 화면에서 확인한다.

| 화면 | 꼭 보여줄 것 | 주 행동 |
| --- | --- | --- |
| 레이드 준비 | 5층, 1~4인, 개인 전리품, 전투 사망 위험, 내 HP·수명, 파티 구성 | 혼자 출전 / 파티 만들기 / 초대 코드로 참가 |
| 비무 준비 | 경기 성장 보상 없음, 시즌 순위, 내 빌드·예상 매칭 범위 | 비무 찾기 |
| 생사결 준비 | 실제 손실, 현재 HP·수명, 각자 판돈·총액, 상대 조건, 명확한 동의 | 판돈 선택 / 조건에 동의하고 출전 |
| 출전 불가 | 사유 하나와 해결 행동 | 가방에서 정비 / 수련 마치기 / 다른 무인 선택 |
| 대기 | 경과 시간·모드·내 무인, 취소 | 매칭 취소 |
| 연결/자료 오류 | 실패 원인과 현재 자산 잠금 상태 | 다시 연결 / 결과 확인 / 안전한 전투 전 취소 |

생사결의 손실 동의는 장식 안내를 닫는 버튼과 섞지 않는다. 실제 무인을 잃을 수 있다는 결과를 행동 직전에 설명한다. 숫자·가격·HP·수명·상대 정보는 이미지에 굽지 않고 다섯 언어의 실시간 텍스트로 표시한다.

## 전투 HUD와 가방

현재 무협 HUD의 배치와 카툰 전장 축척을 유지한다. 온라인 모드마다 별도 스킬바와 화면을 새로 만들지 않는다.

- 왼쪽 위: 내 이름·HP·짧은 수명 주의. 레이드는 그 아래 최대 아군 3명의 작은 HP·접속 표식을 둔다. 내 캐릭터와 아군 그림 표식은 구분한다.
- 상단 중앙: 보스 HP·짧은 페이즈 이름, 또는 PVP 상대 HP·경기 점수·남은 시간. 보스 전조·캐릭터를 가리지 않게 한다.
- 오른쪽 위: 레이드 층·파티 인원 또는 비무 라운드, 가방·설정. 현재 로비 메뉴는 전장에 넣지 않는다.
- 왼쪽 아래: 부채 무공·Q/E, hover/Shift/초점 설명. 중앙 아래 궁극, 오른쪽 아래 현재 무공 방어 재사용을 유지한다.
- 연결 상태: 실제 지연·재접속·입력 중립 여부를 짧게 알리고 서버가 멈춘 상태와 내 접속만 끊긴 상태를 구별한다.
- 온라인 전투 가방: 현재 통합 무인 요약·두 가방·물품 정보를 재사용하고 `전투는 계속됩니다`를 표시한다. 사용·이동·회전·연결·폐기를 허용하지 않는다.

가방을 닫은 뒤 전투 조작으로 초점을 돌리고 눌린 공격 입력을 비운다. 재접속·성장·결착·로딩 화면 뒤의 입력이 전투나 이전 가방으로 새지 않는다.

## 레이드 정비 화면

가방의 같은 작업 공간을 사용하고 상단에 짧은 층/파티 띠를 넣는다. 무인 요약·격자·물품·개인 전리품/유품·정리판을 함께 표시한다. 성장 후보는 정비 중 처리하고, 그동안 내 준비만 불가하다.

```text
층 클리어 · 2 / 5                   아군 3명 · 각자 HP / 준비 상태
────────────────────────────────────────────────────────────
무인 요약  │ 무장 4×7 │ 일반 10×8 │ 선택 물품 / 유품 원 소유자
상태·무공  │         │           │ 수납·회전·사용·착용·내려놓기
착용 장비  │         │           │
────────────────────────────────────────────────────────────
개인 전리품 / 회수 가능한 유품                  임시 정리판
────────────────────────────────────────────────────────────
귀환하기     성장 / 공간 / 수명 문제 안내        다음 층 준비
```

전리품과 유품은 한 보관 영역 안에서 작은 소유자 표식으로 구분한다. 본문 전체를 별도 탭으로 바꿔 가방과 전리품을 숨기지 않는다. 다량 아이템은 해당 영역의 페이지로 이동한다. 유품을 고르면 일반 사용 대신 원 소유자·반환 규칙·현장 내려놓기를 보여준다.

누군가 귀환하면 `3명 → 2명`과 새 구성, `함께 귀환하기` / `2명으로 준비하기`를 같은 화면에서 확인한다. 기존 준비 상태는 해제한다. 정비 시간을 줄이려고 임의 자동 출발을 넣지 않는다.

추천 문구 예:

- `전투가 끝났습니다. 물품을 정리하고 귀환하거나 다음 층을 준비하세요.`
- `파티가 2명으로 바뀌었습니다. 다음 층 진행을 다시 선택하세요.`
- `수련 선택을 마쳐야 준비할 수 있습니다.`
- `이 유품은 {세가}의 소유입니다. 생환하면 자동 반환됩니다.`

레이드 층 사이에 강호 상인·의원을 자동 배치하지 않는다. 현재 가지고 있는 약 사용·연결 변경·착용과 보상 정리만 먼저 구현한다.

## 결과·기록 화면

| 결과 | 우선 정보 | 이어지는 행동 |
| --- | --- | --- |
| 레이드 생환 | 귀환 층·남은 HP·획득품·성장·반환한 유품 | 가방 / 로비 |
| 레이드 사망 | 실제 사망·잃은 물품·아군의 회수/반환 상태 | 관전 / 명부 |
| 비무 | 승/패/무승부·순위 변화·시즌 종료 | 다시 찾기 / 로비 |
| 생사결 자비 | 상대 생존·판돈 정산·남은 HP | 로비 |
| 생사결 사망 | 실제 사망 또는 승자 직접 수납·판돈·XP | 전리품 정리 / 로비 |
| 서버 정산 대기 | 미확정/확정 여부·마지막 결과 ID | 결과 다시 확인 |

기록은 무인의 이름·탄생/사망 원인·생환 층·대표 무공과 세가 이력을 남긴다. 유품이 돌아왔다는 사실과 무인이 살아났다는 사실을 혼동하지 않는다. 결과 대기 중에는 동일 무인 재출전·판매 버튼을 켜지 않는다. 시즌 보상은 기록/로비의 짧은 수령 표시로 제공하고 매 경기 보상 화면을 만들지 않는다.

## 텍스트·그림·소리의 제작 목록

### 첫 에셋 범위

| 제작 묶음 | 분량 | 검수할 것 |
| --- | --- | --- |
| 강호 보스 | 네 실루엣, 기본/준비/공격/회복/피격/사망 동작 | 원거리/검/창 구별, 손과 무기 연결, 작은 화면의 자세 |
| 레이드 새 보스 | 철갑 호위장·흑풍채주 두 명 | 기존 적보다 뚜렷한 실루엣, 과한 갑옷·이펙트 제거 |
| 레이드 환경 | 산채 테마 1세트·5층 변형, 배경/전경/장애물 분리 | 넓은 공간, 위험 범위와 겹치지 않는 바닥, 이동 가능 영역 |
| HUD 소품 | 파티/소유권/유품/생환/결착의 작은 그림 | 기존 종이·먹·금속 스타일, 글자 없이 제작 |
| 전투 효과 | 방향 예고·돌진 궤적·검기·방어 접촉 | 서버 정의의 모양과 같은 경계, 화면을 덮지 않는 짧은 효과 |
| 오디오 | 보스 준비·돌진·검기·강한 접촉·페이즈·생환·자비·결착 | 밝고 짧은 과장 효과, 경고 우선, 음악과 음량 균형 |

초기에는 현재 적/효과를 이용해 판정을 검증하고, 최종 그림은 별도로 제작한다. 서비스용 결과를 선으로 된 임시 도형만으로 완료 처리하지 않는다. 반대로 에셋 제작이 끝나기 전 판정·자산 정산을 미룰 필요는 없다.

사용자가 지적한 과한 동작 프롬프트를 반복하지 않는다. 승인한 같은 기준 그림을 첨부하고 대상·행동·배경 조건만 요청한다. 예:

> 같은 카툰 무협 화풍. 긴 창을 든 보스 한 명, 전신 3/4 시점, 기본 대기 자세. 투명 배경, 글자 없음.

동작 요청:

> 같은 캐릭터가 창으로 한 번 찌르고 대기 자세로 돌아오는 짧은 동작. 고정 카메라.

생성 영상의 시간·투명 배경·프레임/일관성이 맞는지는 실제 결과를 확인한다. 생성 프롬프트만으로 runtime-ready라고 판단하지 않는다. 무기별 타격 접촉점을 애니메이션에서 기록하고 서버의 공격 준비/접촉/회복 틱에 매핑한다.

### 현지화와 사운드

콘텐츠 ID와 표시 키를 분리한다. 보스명·패턴명·경고·소유권·귀환·판돈·승패·자비·수명·연결/정산 오류를 한국어·영어·일본어·중국어 간체/번체로 처리한다. 변수와 날짜·수량·단복수는 전체 문장으로 구성하고 서버는 번역 문장 대신 코드와 매개변수를 보낸다.

배경음은 기존 로비·전투 방향을 유지하고 보스에는 전투 곡의 층을 얹는다. 무거운 징·긴 금속 잔향으로 통일하지 않는다. 빠른 팝·짧은 휙·압축된 강한 접촉으로 타격 크기를 구별한다. 적 경고는 일반 공격 효과음보다 우선하며 아군 4명의 효과가 겹쳐 경고가 사라지지 않게 동시 발음과 우선순위를 제한한다. 내 행동 예측음과 서버 확정 적중음은 다른 cue ID로 관리하고 재전달이 소리를 중복 재생하지 않게 한다.

## 단계별 구현 백로그

완료 기준은 작업을 했다는 체크가 아니라 실행 결과다. 다음 단계는 앞 단계의 필요한 검증이 끝난 뒤 연결한다.

| 단계 | 실제 작업 | 의존성 | 완료 기준 |
| --- | --- | --- | --- |
| M0 공통 규칙 | mode policy·actor/team·공통 공격 정의·명시적 시계/난수·기존 로컬 어댑터 | 현재 설계 검토 | 기존 강호/가방/저장 회귀, 단일/다중 actor 공격 재현 일치 |
| M1 보스 | 5/10 패턴 정리→15/20 구별·페이즈·예고·그림·소리 | M0 | 네 무공과 이동 공략, 예고/실제 범위·프레임·캡처·사람 플레이 |
| M2 솔로 레이드 1층 | 명부 선택→출전→보스→정비 성장→수납→귀환/사망·기록 | M0, M1의 보스 하나 | 귀환 HP·XP·빌드·물품 보존, 사망/수명/공간/중복 귀환 검사 |
| M3 온라인 기반 | 인증·DB·원장·출전 잠금·온라인 강호 1인 방·입력/스냅샷·복구 | M0, M2 규칙 | 로컬 보존, 서버에서 생성한 무인만 사용, 재접속/죽음/중복 정산/DB 실패 검사 |
| M4 협동 5층 | 파티·초대·1~4인·개인 보상·유품·재선택·준비·난이도·5층 콘텐츠 | M2, M3 | 여러 실제 브라우저의 출전→인원 변화→유품 재드랍→귀환·반환 |
| M5 비무 | 1대1·빌드 사본·매칭·라운드·결과·MMR·서버 무효 | M3, D1/D2 확정 | 실제 HP/물품 보존, 지연·동시 타격·반격·단절·중복 점수 검사 |
| M6 생사결 | 판돈·실제 HP·자비·사망·직접 루팅·XP·이탈 | M3, M5, 위험 정책 확정 | 양쪽 자산 불변식, 자비/사망/동시 사망/정산 재시도·장애 회복 |
| M7 시즌·시장 | 시즌 마감/보상·장비 개별 매물·호가·수수료·수령 대기 | M3, M5, 기본 경제 측정 | 계정별 보상 한 번, 매물/출전 경합·부분 체결·중복 구매·취소/만료 |
| M8 공개 검증 | 성능·실기기·새 사용자·번역·장시간·배포/롤백·복원 리허설 | 공개할 단계 전체 | 완료 기준의 증거를 기록하고 미지원/미완료 범위를 표시 |

M3의 온라인 강호는 첫 단계에서 한 구간으로 네트워크 연결을 시험한 뒤 전체 20웨이브를 적용한다. 로컬 자산을 온라인으로 올려서 시험을 통과시키지 않는다. M4는 먼저 한 층의 2인 왕복, 그 다음 4인·5층으로 확장한다. M6는 공개 경제를 켜기 전에 비공개 테스트 세가로 검증한다.

## 첫 구현 작업 카드

설계 확정 뒤 처음 수행할 구체적인 작업은 다음 네 개다.

1. `ModePolicy`와 전투 actor 모델을 추가하고 기존 강호 명령/저장을 어댑터로 유지한다. 로컬 저장 v1의 읽기·원본 보존·다른 모드 격리를 먼저 확인한다.
2. `AttackDefinition/Instance`와 원·부채·직선·투사체 판정을 공유한다. 현재 chief/captain의 피해와 전조를 이 정의에 연결한다.
3. 5웨이브 보스 하나에 패턴·목표 고정·회복·페이즈를 적용해 현재 타격감·방어 cue를 유지한다. 무공별 실제 방어 성공과 전조 경계를 비교한다.
4. 같은 보스를 명부의 무인이 솔로 레이드 1층에서 만나는 흐름을 구성한다. 출전 전 잠금→실제 HP 유지→성장/전리품→귀환/사망의 단위를 검증한다.

온라인 서버 도입은 위 왕복의 결과 계약과 동시에 준비할 수 있으나 인증·정산 검증 없이 실제 위험 출전을 공개하지 않는다. 새 무공·팀전·길드·10지역·40보스·복잡한 강화 제작은 이 왕복을 완성한 뒤 평가한다.

## 초기 밸런스 실험표

아래 수치는 구현을 시작하기 위한 제안이다. 보장된 보상표나 확정된 경제는 아니다.

| 항목 | 실험 시작 기준 | 먼저 측정할 것 |
| --- | --- | --- |
| 레이드 XP | 층별 30/40/50/60/80, 비급은 별도 제한된 드랍 | Lv.13~16 무인이 완주 후 약 2~3번 성장 선택을 얻는지 |
| 레이드 장비 | 현재 품질 80~120 범위를 유지, 깊은 층에서 상위 값 확률 개선 | 장비가 성장을 돕되 큰 격차로 비무 매칭이 막히지 않는지 |
| 회복 | 현재 금창약 35HP와 실제 드랍/보급 비용을 기준 | 천마 외 빌드도 반복 출전 가능하고 자동 회복이 필요 없는지 |
| 파티 HP | `1+0.65(N−1)`, 피해는 인원에 따라 증가시키지 않음 | 1~4인 평균 처치 시간·사망률·가독성 |
| 생사결 XP | 확정 결착만·동일 계정 쌍 지급 예산 | 자비 보상 규칙 유지·합의 처치 파밍·세가 성장 속도 |
| 시즌 보상 | 계정 외형/칭호 추천 | 순위 이외 경기 보상 없이 참가 목적이 명확한지 |
| 반로환 | 최초 연장 24h, 반복 효율 절반 후보 | 강한 무인 유지 비용·7일 교체 루프·공급량 |

레이드 전투 XP·보스 비급·아이템 품질의 합산을 함께 측정한다. 무공 최대 단계 이후에는 무공 투자 완료를 안내하고 상한을 늘리거나 레벨 자체에 자동 공격 보너스를 주지 않는다.

## 착수 전 결정 기록

큰 질문 D1/D2/D3를 반영한 뒤 비무 HP·라운드/시간, 자비 마감 기본 결과, 동시 사망, 레이드 XP 정비 처리, 연결 유예, 수명 만료 경합, 유품 내려놓기/재드랍, 시즌 보상, 반로환·시장 수수료를 정책 표에 최종 기록한다. 나머지 패턴 전조·피해·드랍 확률은 플레이 조정값으로 관리한다.

이번 설계의 현재 상태는 **문서·의존성·규칙 정합성 검토 완료 / 질문과 새 위험 정책 미확정 / 새 콘텐츠 구현·플레이 검증 전**이다.
