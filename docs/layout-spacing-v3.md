# 블록 배치·간격 점검 · 2026-09-29

텍스트·로딩 개선만으로 UI·UX 전체가 끝났다고 표현하지 않는다. 이번에는 실제 구현된 로비·생성·설정·기록·안내·가방·창고·성장 선택·전투 HUD·일시 정지의 배치와 간격을 점검했다. 게임 규칙과 사용자 요구가 공개 디자인 참고 문서보다 우선한다.

| ------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------- |

## 간격 기준

`src/layout.css`에서 4·8·12·16·24·32·48px 토큰을 정의한다. 같은 정보 안에서는 작은 간격을, 다른 그룹 사이에서는 더 큰 간격을 사용한다. 화면 여백은 기본 32px, 낮은 화면 24px, 좁은 화면 16px다. 패널 본문과 제목의 시작선을 맞추고 버튼 간격은 12px, 좁은 화면은 8px를 쓴다.

모든 간격을 하나의 값으로 만들지 않는다. 장식 그림·격자 좌표·HUD 초상처럼 특수한 형태는 별도로 처리한다. 전체 화면 배율 축소, 글자 축소, 필수 조작을 숨기는 방식으로 맞추지 않는다. 4×7·10×8 가방, 150% UI, 전투 카메라와 밸런스는 유지한다.

## 검증과 증거

새 배치 검사는 세 기준 해상도마다 13개 화면을 캡처한다. 실제 버튼·입력 영역의 겹침과 잘림, 로비 시작선, 가방 핵심 행동, 성장 카드 선택 줄 정렬을 검사한다. 입문 안내도 5개 언어와 세 기준 해상도에서 확인한다. 단순히 특정 CSS 값이 있는지만 검사하지 않는다.

기존 수납·드래그·회전·키보드·착용·사용·창고·폐기·저장·로딩 회귀는 별도로 실행한다. 모든 테스트 상태는 독립 Playwright 컨텍스트에만 쓰며 실제 사용자 저장은 바꾸지 않는다. 최종 수치·배포 상태는 [검증 기록](verification/layout-v3/result.json)에 둔다.

빌드·단위 검사 32개·로컬 전체 회귀 38개가 통과했다. 이후 안내·고정 제목 조정은 관련 11개, 마지막 명부 패널 경계 조정은 세 해상도에서 다시 통과했다. 최종 공개 Daytona 빌드도 8개 시나리오가 통과했다. 실제 로컬·공개 브라우저에서 키보드로 설정 열기·Esc 닫기·원래 버튼 초점 복귀를 확인했다. 개별 캡처의 시각 검토 범위는 JSON에 별도로 기록했다.

자동 검사는 실제 사용자가 목적을 쉽게 이해하거나 조작을 빠르게 배웠다는 증거가 아니다. 직접 시각 검토와 신규 사용자 검토를 구분한다.
